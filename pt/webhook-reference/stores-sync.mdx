---
title: "stores.sync"
description: "Disparado quando o Fire precisa propagar um lote grande de configurações de loja de uma vez."
---

`stores.sync` é a contraparte em lote de [`store.updated`](/pt/webhook-reference/store-updated). O Fire o emite quando várias lojas precisam ser propagadas em massa — por exemplo, durante o onboarding inicial ou uma mudança massiva de configuração.

O Fire divide automaticamente os lotes grandes e emite vários eventos `stores.sync` com até 50 lojas cada. Seu sistema deve tratar cada evento de forma independente.

## Campos

### `data`

| Campo | Tipo | Descrição |
|---|---|---|
| `account` | string | Identificador da conta — exigido por sistemas downstream |
| `country` | string | Identificador do país — exigido por sistemas downstream |
| `batchIndex` | integer | Posição deste lote (1-based) |
| `batchTotal` | integer | Número total de lotes nesta sincronização |
| `stores` | object[] | Configurações de loja — mesma estrutura de [`store.updated`](/pt/webhook-reference/store-updated) |
| `channels` | object[] | Configurações de canal — mesma estrutura de [`store.updated`](/pt/webhook-reference/store-updated) |

## Processamento

Processe cada evento `stores.sync` de forma independente. Use `batchIndex` e `batchTotal` para acompanhar o progresso se seu sistema precisar saber quando uma sincronização completa termina.

<Note>
  Cada evento de lote é entregue e reenviado de forma independente. Se um lote falhar, somente esse lote é reenviado — não toda a sincronização.
</Note>

## Quando o Fire emite este evento?

- Durante o onboarding inicial de um cliente
- Após uma mudança massiva de configuração que afeta muitas lojas
- Em solicitações explícitas de sincronização disparadas pelo dashboard do Fire

Para mudanças individuais de loja em operação normal, o Fire emite [`store.updated`](/pt/webhook-reference/store-updated) em vez disso.
