---
title: "Receitas"
description: "Gerencie receitas de venda, produção e subreceitas — as definições que impulsionam o consumo de inventário no BOH."
---

Uma **receita** define como uma venda, um lote de produção ou uma subreceita consome itens de inventário. O BOH usa receitas para calcular o consumo quando pedidos chegam ou produção é registrada.

**Escopos necessários:** `recipes:read` (leituras), `recipes:write` (escritas).

## Tipos de receita

| Tipo | O que representa |
|---|---|
| `SALES_RECIPE` | Vinculada a um produto/variante do POS. Consumida quando uma linha de pedido é registrada. |
| `PRODUCTION_RECIPE` | Vinculada a um item produzido. Consumida ao registrar um lote de produção; o item de saída é adicionado ao estoque. |
| `SUBRECIPE` | Conjunto de ingredientes reutilizável referenciado por outras receitas via `consume_by: SUBRECIPE`. Não está vinculada diretamente a um produto. |

## Ciclo de vida da receita

Receitas começam como **DRAFT**, requerem ao menos uma linha e devem ser **publicadas** antes que o BOH as use para consumo. Rascunhos podem ser editados livremente. A publicação é imutável — crie um novo rascunho para revisar uma receita publicada.

```
DRAFT → PUBLISHED → ARCHIVED
```

## Linhas com escopo de canal

Linhas em uma `SALES_RECIPE` podem conter um array opcional `service_codes`. Quando não vazio, aquela linha só é consumida se o service code do pedido (ex.: `DELIVERY`, `DINE_IN`) corresponder a um dos códigos no array. Linhas sem `service_codes` (ou com array vazio) se aplicam a todos os canais.

## Listar receitas

<api>GET https://boh.api.fire.rest/api/v1/public/vendors/{vendorId}/recipes</api>

<ParamField header="x-api-key" type="string" required>API key do BOH com escopo `recipes:read`.</ParamField>
<ParamField path="vendorId" type="string" required>UUID do vendor.</ParamField>
<ParamField query="recipe_type" type="string">Filtro: `SALES_RECIPE`, `PRODUCTION_RECIPE` ou `SUBRECIPE`.</ParamField>
<ParamField query="status" type="string">Status: `DRAFT`, `PUBLISHED` ou `ARCHIVED`.</ParamField>
<ParamField query="external_product_id" type="string">Seu ID de produto — retorna receitas vinculadas a esse produto.</ParamField>
<ParamField query="service_code" type="string">Retorna receitas que têm ao menos uma linha correspondente a este service code.</ParamField>
<ParamField query="limit" type="integer" default="50">Tamanho da página (1–200).</ParamField>
<ParamField query="offset" type="integer" default="0">Paginação por offset.</ParamField>
<ParamField query="cursor" type="string">Paginação por cursor.</ParamField>

## Criar receita (rascunho)

<api>POST https://boh.api.fire.rest/api/v1/public/vendors/{vendorId}/recipes</api>

Cria uma nova receita em status DRAFT.

<ParamField header="x-api-key" type="string" required>API key do BOH com escopo `recipes:write`.</ParamField>
<ParamField path="vendorId" type="string" required>UUID do vendor.</ParamField>
<ParamField body="recipe_type" type="string" required>`SALES_RECIPE`, `PRODUCTION_RECIPE` ou `SUBRECIPE`.</ParamField>
<ParamField body="recipe_name" type="string" required>Nome para exibição da receita.</ParamField>
<ParamField body="store_id" type="string">UUID de loja BOH. Null para uma receita que se aplica a todas as lojas.</ParamField>
<ParamField body="external_product_id" type="string">Seu ID de produto do POS. Necessário para `SALES_RECIPE` com vinculação automática.</ParamField>
<ParamField body="output_item_id" type="string">UUID do item produzido. Necessário para `PRODUCTION_RECIPE` e `SUBRECIPE`.</ParamField>
<ParamField body="recipe_code" type="string">Código curto para referenciar esta receita como subreceita.</ParamField>
<ParamField body="recipe" type="object" required>
  Conteúdo da receita:
  <Expandable title="campos de recipe">
    <ParamField body="output" type="object">Para `PRODUCTION_RECIPE`: quantidade de saída planejada (`qty_base` + `base_unit_id`).</ParamField>
    <ParamField body="lines" type="object[]" required>
      Linhas de ingredientes. Cada linha tem `consume_by` (`ITEM`, `ITEM_TAG` ou `SUBRECIPE`), `qty_base`, `base_unit_id` e opcionalmente `service_codes`.
    </ParamField>
  </Expandable>
</ParamField>
<ParamField body="external_user_id" type="string">Ator para auditoria.</ParamField>

<RequestExample>
```json Receita de venda com linhas por canal
{
  "recipe_type": "SALES_RECIPE",
  "recipe_name": "Hambúrguer clássico",
  "external_product_id": "prod-burger-001",
  "recipe": {
    "lines": [
      {
        "consume_by": "ITEM",
        "item_id": "itm_carne_01...",
        "qty_base": 180,
        "base_unit_id": "unit_g_01..."
      },
      {
        "consume_by": "ITEM",
        "item_id": "itm_caixa_delivery_01...",
        "qty_base": 1,
        "base_unit_id": "unit_ea_01...",
        "service_codes": ["DELIVERY"]
      }
    ]
  },
  "external_user_id": "user_chef_99"
}
```
</RequestExample>

## Obter receita

<api>GET https://boh.api.fire.rest/api/v1/public/vendors/{vendorId}/recipes/{recipeId}</api>

Retorna um único snapshot de receita por ID.

---

## Atualizar receita (somente rascunhos)

<api>PATCH https://boh.api.fire.rest/api/v1/public/vendors/{vendorId}/recipes/{recipeId}</api>

Atualiza parcialmente uma receita em status DRAFT. Não é possível atualizar uma receita PUBLISHED ou ARCHIVED.

---

## Publicar receita

<api>POST https://boh.api.fire.rest/api/v1/public/vendors/{vendorId}/recipes/{recipeId}/publish</api>

Publica uma receita DRAFT. Uma vez publicada, não pode ser editada — crie um novo rascunho para revisá-la.

<ParamField body="external_user_id" type="string">Ator para auditoria.</ParamField>

---

## Arquivar receita

<api>POST https://boh.api.fire.rest/api/v1/public/vendors/{vendorId}/recipes/{recipeId}/archive</api>

Arquiva uma receita. O BOH para de usá-la para consumo após o arquivamento.

Retorna `{ "ok": true }`.

---

## Duplicar receita como rascunho

<api>POST https://boh.api.fire.rest/api/v1/public/vendors/{vendorId}/recipes/{recipeId}/duplicate-as-draft</api>

Cria uma nova receita DRAFT como cópia da receita fonte, pronta para edição.

---

## Expandir receita (resolução de ingredientes)

<api>GET https://boh.api.fire.rest/api/v1/public/vendors/{vendorId}/recipes/{recipeId}/expansion</api>

Resolve recursivamente todas as referências a subreceitas em uma receita publicada, retornando uma lista plana de linhas de itens com a quantidade efetiva a consumir.

<ParamField query="service_code" type="string">
  Quando fornecido, apenas linhas que correspondem a este service code (ou sem `service_codes`) são incluídas.
</ParamField>

<ResponseField name="recipe_id" type="string">UUID da receita resolvida.</ResponseField>
<ResponseField name="lines" type="object[]">Lista plana de linhas de ingredientes resolvidas com `consume_by`, `item_id` ou `item_tag_id`, `qty_base`, `base_unit_id` e `source_trace`.</ResponseField>
<ResponseField name="trace" type="object">Árvore mostrando como as subreceitas foram expandidas, com ratios e contagens de linhas por nó.</ResponseField>

---

## Buscar receita publicada por produto

<api>GET https://boh.api.fire.rest/api/v1/public/vendors/{vendorId}/recipes/published</api>

Encontra a receita atualmente publicada para uma combinação de produto/variante/serviço.

<ParamField query="external_product_id" type="string">Seu ID de produto do POS.</ParamField>
<ParamField query="external_variant_id" type="string">Seu ID de variante do POS.</ParamField>
<ParamField query="store_id" type="string">UUID de loja BOH.</ParamField>
<ParamField query="service_code" type="string">Código de serviço/canal.</ParamField>

Retorna o `RecipeSnapshotResponse` da receita encontrada ou `404` se nenhuma for encontrada.
