---
title: "Webhooks"
description: "Assine eventos do BOH: conclusão e falha de transações de inventário, e mudanças de status em pedidos de compra."
---

Os webhooks do BOH entregam notificações de eventos ao seu endpoint HTTPS. Cada evento dispara uma requisição `POST` com um payload JSON e uma assinatura que você pode verificar.

**Escopo necessário:** `admin:webhooks`.

**Limite:** até **10 endpoints de webhook** por conta.

## Eventos suportados

| Tipo de evento | Quando é disparado |
|---|---|
| `inventory_transaction.completed` | Uma transação de inventário assíncrona (recebimento, perda, contagem, transferência, lote de produção, ajuste manual) foi processada com sucesso e os saldos de estoque foram atualizados. |
| `inventory_transaction.failed` | Uma transação assíncrona falhou no processamento e não será repetida. A transação fica marcada como `FAILED`. |
| `purchase_order.status_changed` | Um pedido de compra mudou para um novo status do ciclo de vida (`DRAFT`, `SENT`, `PARTIAL`, `RECEIVED`, `CANCELLED`). |
| `api_key.expiring` | Uma API key expirará em 7 dias. Enviado diariamente até expirar ou ser renovada. |
| `ping` | Evento de teste enviado quando você dispara um teste de webhook. |

## Envelope do payload

Todos os eventos compartilham o mesmo envelope:

```json
{
  "event_id": "evt_01j5k...",
  "event_type": "inventory_transaction.completed",
  "created_at": "2026-08-07T14:30:00.000Z",
  "api_version": "v1",
  "data": { ... }
}
```

## Entrega e retentativas

O BOH tenta a entrega imediatamente. Se seu endpoint retornar uma resposta que não seja 2xx ou atingir o timeout, o BOH tenta novamente com backoff exponencial. Após **20 falhas consecutivas**, o endpoint é automaticamente desabilitado (`is_active: false`). Reative-o chamando o endpoint [Atualizar webhook](#atualizar-webhook).

## Listar webhooks

<api>GET https://boh.api.fire.rest/api/v1/public/admin/webhooks</api>

Retorna todos os endpoints de webhook da conta.

<ParamField header="x-api-key" type="string" required>API key do BOH com escopo `admin:webhooks`.</ParamField>

<RequestExample>
```http
GET /api/v1/public/admin/webhooks
x-api-key: boh_live_xxxxxxxx
```
</RequestExample>

<ResponseExample>
```json 200
{
  "endpoints": [
    {
      "id": "wep_01j5k...",
      "url": "https://seuapp.com/webhooks/boh",
      "events": ["inventory_transaction.completed", "purchase_order.status_changed"],
      "is_active": true,
      "disabled_reason": null,
      "consecutive_failures": 0,
      "created_at": "2026-07-01T09:00:00.000Z",
      "updated_at": "2026-07-01T09:00:00.000Z"
    }
  ]
}
```
</ResponseExample>

## Criar webhook

<api>POST https://boh.api.fire.rest/api/v1/public/admin/webhooks</api>

Registra um novo endpoint de webhook. A resposta inclui o **segredo de assinatura** — guarde-o com segurança; ele é exibido apenas uma vez.

<ParamField header="x-api-key" type="string" required>API key do BOH com escopo `admin:webhooks`.</ParamField>

<ParamField body="url" type="string" required>
  URL HTTPS que receberá as requisições POST. Deve começar com `https://`.
</ParamField>

<ParamField body="events" type="string[]" required>
  Um ou mais tipos de eventos para assinar. Ver [Eventos suportados](#eventos-suportados).
</ParamField>

<ResponseField name="endpoint" type="object">O endpoint criado.</ResponseField>
<ResponseField name="secret" type="string">
  Segredo de assinatura (`whsec_...`). **Exibido apenas uma vez.** Guarde-o no seu gerenciador de segredos imediatamente.
</ResponseField>

<RequestExample>
```json
{
  "url": "https://seuapp.com/webhooks/boh",
  "events": [
    "inventory_transaction.completed",
    "inventory_transaction.failed",
    "purchase_order.status_changed"
  ]
}
```
</RequestExample>

<ResponseExample>
```json 201
{
  "endpoint": {
    "id": "wep_01j5k...",
    "url": "https://seuapp.com/webhooks/boh",
    "events": ["inventory_transaction.completed", "inventory_transaction.failed", "purchase_order.status_changed"],
    "is_active": true,
    "disabled_reason": null,
    "consecutive_failures": 0,
    "created_at": "2026-08-07T14:30:00.000Z",
    "updated_at": "2026-08-07T14:30:00.000Z"
  },
  "secret": "whsec_xxxxxxxxxxxxxxxxxxxxxxxx"
}
```
</ResponseExample>

## Obter webhook

<api>GET https://boh.api.fire.rest/api/v1/public/admin/webhooks/{webhookId}</api>

Retorna um único endpoint por ID. O segredo não é retornado após a criação.

---

## Atualizar webhook

<api>PATCH https://boh.api.fire.rest/api/v1/public/admin/webhooks/{webhookId}</api>

Atualiza parcialmente um endpoint. Use para alterar a URL, atualizar a lista de eventos ou reativar um endpoint desabilitado automaticamente.

<ParamField body="url" type="string">Nova URL HTTPS.</ParamField>
<ParamField body="events" type="string[]">Nova lista de assinaturas de eventos (substitui a lista existente).</ParamField>
<ParamField body="is_active" type="boolean">
  Defina `true` para reativar um endpoint desabilitado automaticamente. Defina `false` para desabilitá-lo manualmente.
</ParamField>

---

## Excluir webhook

<api>DELETE https://boh.api.fire.rest/api/v1/public/admin/webhooks/{webhookId}</api>

Remove permanentemente o endpoint. Nenhum evento adicional será entregue a essa URL.

---

## Listar entregas

<api>GET https://boh.api.fire.rest/api/v1/public/admin/webhooks/{webhookId}/deliveries</api>

Retorna tentativas de entrega recentes de um endpoint, mais recentes primeiro.

<ParamField query="limit" type="integer" default="50">Número de entregas a retornar (1–100).</ParamField>

<ResponseField name="deliveries" type="object[]">
  Cada entrega inclui: `id`, `event_id`, `event_type`, `status` (`PENDING`, `PROCESSING`, `DELIVERED`, `FAILED`, `DEAD`), `attempts`, `next_retry_at`, `last_response_status` e `last_error`.
</ResponseField>

---

## Testar webhook

<api>POST https://boh.api.fire.rest/api/v1/public/admin/webhooks/{webhookId}/test</api>

Envia um evento `ping` ao endpoint imediatamente. Útil para verificar conectividade e sua lógica de verificação de assinatura.

<ResponseField name="delivery_id" type="string">UUID da entrega de teste criada.</ResponseField>

---

## Verificação de assinaturas

Cada entrega inclui um header `X-BOH-Signature` que você deve verificar para confirmar que a requisição veio do BOH. Use o segredo de assinatura retornado ao criar o endpoint.

```
X-BOH-Signature: sha256=<hex_digest>
```

Calcule `HMAC-SHA256(secret, raw_request_body)` e compare com o valor `sha256=`. Rejeite requisições onde não correspondam.

<Warning>
  Sempre verifique assinaturas em produção. Pular a verificação permite que qualquer parte falsifique payloads de webhook.
</Warning>
