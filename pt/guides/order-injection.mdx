Seu sistema pode injetar pedidos no Fire usando a API de Orders. O Fire então gerencia o ciclo de vida do pedido e envia as atualizações de status de volta via webhooks.

## Fluxo

```
Seu sistema recebe um pedido → Seu sistema injeta no Fire → Fire confirma
```

## Injetar um pedido

```http
POST /v1/orders
Authorization: Bearer <your_api_key>
Content-Type: application/json
```

```json
{
  "channel_id": "channel_abc123",
  "external_order_id": "uber_order_9876",
  "customer": {
    "name": "Jane Doe",
    "phone": "+1555000111"
  },
  "items": [
    {
      "product_id": "prod_001",
      "quantity": 2,
      "unit_price": 1200,
      "modifiers": []
    }
  ],
  "delivery": {
    "type": "delivery",
    "address": "123 Main St"
  },
  "total": 2400
}
```

### Campos obrigatórios

| Campo | Descrição |
|---|---|
| `channel_id` | O ID do canal de venda do Fire (de webhooks de publicação como [`channel.updated`](/pt/webhook-reference/channel-updated) ou [Integrações de agregadores](/pt/configuration/backoffice-integrations)) |
| `external_order_id` | Seu próprio ID de pedido — usado para correlacionar as atualizações de status |
| `items` | Array de produtos pedidos com quantidades e preços |

### Resposta

```json
{
  "id": "fire_order_abc",
  "external_order_id": "uber_order_9876",
  "status": "received",
  "created_at": "2025-01-15T14:30:00Z"
}
```

Armazene o `id` devolvido pelo Fire para correlacionar eventos `order.status_changed` futuros.

## Criar pedido: v1 e v2

Criar um pedido tem **duas versões vigentes**, conforme o formato que o seu sistema envia. As duas
terminam no mesmo lugar: mesmas validações, mesma resposta.

| Versão | Endpoint | Use-a se o seu sistema envia |
|---|---|---|
| [v1](/pt/api-reference/create-order) | `POST /api/v1/fire/external/orders` | Pedidos no formato Fire (o corpo deste guia) |
| [v2](/pt/api-reference/create-order-v2) | `POST /api/v2/external/orders` | Pedidos com a estrutura de PDV e quiosque ou com a de agregadores |

Com a v2:

- Você envia o mesmo corpo que já monta; o Fire reconhece o tipo de pedido pelo `channel.uid`.
- Você se autentica com a sua API key do Fire, associada ao seu vendor.
- A resposta traz o `id` do pedido no Fire, que você usa para consultá-lo, atualizá-lo ou cancelá-lo.

## Tratamento de erros

| Status | Significado |
|---|---|
| `400` | Payload inválido — verifique os campos obrigatórios |
| `404` | `channel_id` desconhecido — re-obtenha os canais |
| `409` | `external_order_id` duplicado — o pedido já existe |
| `5xx` | Erro do lado do Fire — refaça a chamada com backoff exponencial |

<Warning>
  Não envie o mesmo pedido duas vezes com o mesmo `external_order_id`. O Fire rejeitará duplicatas com um `409`.
</Warning>
