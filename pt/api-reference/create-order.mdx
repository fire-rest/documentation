---
title: "Criar pedido"
api: "POST https://api.fire.rest/api/v1/fire/external/orders"
description: "Cria um pedido no Fire a partir do PDV, do quiosque ou de um integrador de agregadores, com a mesma estrutura de pedido que já enviam hoje."
authMethod: "bearer"
---

Cria um pedido no Fire. O **PDV**, o **quiosque** e os **integradores de agregadores** o usam para
enviar suas vendas diretamente ao Fire, **sem mudar o corpo** que já montam hoje: mudam apenas a URL,
a credencial e a forma de ler a resposta.

O Fire reconhece o tipo de pedido pelo `channel.uid` do corpo:

- Se o canal é de um agregador (iFood, 99Food, Keeta, Rappi), o corpo é o de
  [Injetar pedido](/pt/api-reference/orders) (camelCase, com preços e totais).
- Qualquer outro canal (PDV, quiosque) usa a estrutura de PDV e quiosque descrita abaixo
  (snake_case, só com o preço unitário: o Fire calcula os totais).

Depois de criado, o pedido segue o mesmo ciclo de qualquer pedido do Fire: impostos, dia de negócio,
documento fiscal e [eventos](/pt/events/overview).

## Autenticação

<ParamField header="x-api-key" type="string" required>
  Sua API key do Fire com escopo `orders:write`. Também é aceito `Authorization: Bearer <api_key>`.
  A key **deve estar associada a um vendor**: a conta do pedido vem desse vendor. Uma key sem vendor
  é rejeitada com `403`. Não é preciso enviar o header `account`; se chegar, é ignorado.
</ParamField>

## Identidade do cliente (PDV e quiosque)

Envie **exatamente um** destes dois headers. Se não enviar nenhum, ou enviar os dois, o pedido é
rejeitado com `422` `INVALID_ORDER`. Pedidos de agregadores não os usam.

<ParamField header="anonymous_customer_uid" type="string">
  Identificador da sessão anônima do equipamento (PDV ou quiosque). É o caso habitual.
</ParamField>

<ParamField header="customer_uid" type="string">
  Identificador de um cliente registrado.
</ParamField>

## Corpo — PDV e quiosque

<ParamField body="order_code" type="string" required>
  Código único do pedido no seu sistema. Se já existir um pedido com esse código para o seu vendor,
  a resposta é `409`.
</ParamField>

<ParamField body="vendor_uid" type="string" required>Vendor do pedido (ex.: `11.6.1350`).</ParamField>

<ParamField body="catalog_uid" type="string" required>Catálogo do canal de venda.</ParamField>

<ParamField body="status" type="string">
  `COMPLETED` se a venda já está fechada; `OPEN` se ainda aguarda cobrança. Um pedido que não chega
  `COMPLETED` + `SUCCEEDED` fica pendente de pagamento.
</ParamField>

<ParamField body="payment_status" type="string">`SUCCEEDED` se já foi cobrado.</ParamField>

<ParamField body="channel" type="object" required>
  Canal de venda. O seu `uid` decide como o corpo é interpretado.
  <Expandable title="channel">
    <ParamField body="uid" type="string" required>UID do canal no Fire.</ParamField>
    <ParamField body="code" type="string" required>Código do canal (ex.: `POS`, `KIOSK`).</ParamField>
  </Expandable>
</ParamField>

<ParamField body="service" type="object" required>
  Serviço da venda.
  <Expandable title="service">
    <ParamField body="uid" type="string" required>UID do serviço no Fire.</ParamField>
    <ParamField body="code" type="string" required>Código do serviço (ex.: `Dine-In`, `Takeaway`).</ParamField>
  </Expandable>
</ParamField>

<ParamField body="store" type="object" required>
  Loja da venda.
  <Expandable title="store">
    <ParamField body="uid" type="string" required>UID da loja.</ParamField>
    <ParamField body="code" type="string" required>Código da loja.</ParamField>
    <ParamField body="name" type="string" required>Nome da loja.</ParamField>
    <ParamField body="vendor_uid" type="string" required>Vendor da loja.</ParamField>
    <ParamField body="vendor_name" type="string" required>Nome do vendor.</ParamField>
  </Expandable>
</ParamField>

<ParamField body="fulfillment" type="object" required>
  Forma de entrega e catálogo.
  <Expandable title="fulfillment">
    <ParamField body="method" type="string" required>`POS` ou `KIOSK`.</ParamField>
    <ParamField body="catalog_uid" type="string" required>Catálogo. Deve estar habilitado para a sua conta.</ParamField>
    <ParamField body="details" type="object">Dados da entrega, ex.: `buzzer_name` (nome para chamar o cliente).</ParamField>
  </Expandable>
</ParamField>

<ParamField body="device" type="object">
  Equipamento que registrou a venda: `uid`, `name`, `metadata`.
</ParamField>

<ParamField body="operator" type="object">
  Caixa ou operador: `uid`, `name`, `session` (`uid`, `start_timestamp`, `end_timestamp`).
  `null` no quiosque.
</ParamField>

<ParamField body="customer" type="object">
  Dados do cliente: `uid`, `name`, `last_name`, `phone` (obrigatórios se você enviar o objeto),
  `email`, `gov_id_type`, `gov_id_number`.
</ParamField>

<ParamField body="billing" type="object">Dados de faturamento: `gov_id_type`, `gov_id_number`, `business_name`.</ParamField>

<ParamField body="metadata" type="object">
  Dados adicionais da venda, ex.: `display_code` (número para chamar o pedido) e os dados do
  quiosque ou do PDV.
</ParamField>

<ParamField body="order_lines" type="object[]" required>
  Produtos do pedido.
  <Expandable title="order_lines[]">
    <ParamField body="hash" type="string" required>Identificador da linha dentro do pedido.</ParamField>
    <ParamField body="item_id" type="string" required>UID do produto no catálogo.</ParamField>
    <ParamField body="item_description" type="string" required>Nome do produto.</ParamField>
    <ParamField body="item_type" type="string" required>Tipo de item (ex.: `PRODUCT`).</ParamField>
    <ParamField body="quantity" type="string" required>Quantidade, como texto (`"1"`).</ParamField>
    <ParamField body="selected_currency" type="string" required>Moeda (ex.: `BRL`).</ParamField>
    <ParamField body="vendor_uid" type="string" required>Vendor.</ParamField>
    <ParamField body="store_uid" type="string" required>Loja.</ParamField>
    <ParamField body="fulfillment" type="object" required>`method` e `catalog_uid`, como no pedido.</ParamField>
    <ParamField body="price" type="object" required>
      Só o preço unitário: `unit_price[]` com `currency_code`, `gross_price`, `net_price`, `taxes`,
      `taxes_value`, `discount_value`, `subtotal_before_taxes` e `discounts`. Os valores vão como
      texto (`"14.9"`). O Fire calcula o total da linha e do pedido.
    </ParamField>
    <ParamField body="modifier_groups" type="object[]" required>
      Grupos de modificadores (`uid`, `description`, `selected_modifiers[]`). Cada modificador tem a
      mesma forma de uma linha. `[]` se não houver.
    </ParamField>
    <ParamField body="additional_info" type="object">Códigos do produto, ex.: `code`, `external_code`, `ncm`.</ParamField>
  </Expandable>
</ParamField>

<ParamField body="payment_methods" type="object[]" required>
  Pagamentos do pedido.
  <Expandable title="payment_methods[]">
    <ParamField body="uid" type="string" required>UID do meio de pagamento.</ParamField>
    <ParamField body="method" type="string" required>Meio de pagamento (ex.: `CASH`, `CREDIT`, `DEBIT`).</ParamField>
    <ParamField body="currency_code" type="string" required>Moeda.</ParamField>
    <ParamField body="total" type="string" required>Valor pago, como texto.</ParamField>
    <ParamField body="details" type="object">
      Detalhe da transação: `processor`, `transaction_status` (`APPROVED`, `PENDING`),
      `transaction_type`, `transaction_id`, `tid`, `authorization_code`, `total_bill`,
      `customer_cash_amount`, `change_amount`, `card`, `acquirer`, `transaction_date`. Um pagamento
      `PENDING` deixa o pedido aberto, aguardando cobrança.
    </ParamField>
    <ParamField body="metadata" type="object">Dados do autorizador do pagamento.</ParamField>
  </Expandable>
</ParamField>

## Corpo — agregadores

O mesmo corpo de [Injetar pedido](/pt/api-reference/orders), sem mudanças. O Fire o identifica como
pedido de agregador pelo `channel.uid` e o registra fechado e pago.

## Resposta

<ResponseField name="success" type="boolean">`true` quando o pedido foi criado.</ResponseField>

<ResponseField name="data" type="object">
  <Expandable title="data">
    <ResponseField name="id" type="string">ID do pedido no Fire. Use-o para consultar, atualizar ou cancelar o pedido.</ResponseField>
    <ResponseField name="external_order_id" type="string">O `order_code` que você enviou.</ResponseField>
    <ResponseField name="status" type="string">`COMPLETED` ou `OPEN`.</ResponseField>
    <ResponseField name="payment_status" type="string">`SUCCEEDED` ou `PENDING`.</ResponseField>
    <ResponseField name="business_day_date" type="string">Dia de negócio da loja, `YYYY-MM-DD`.</ResponseField>
    <ResponseField name="created_at" type="string">Data de criação no Fire (ISO 8601).</ResponseField>
  </Expandable>
</ResponseField>

## Erros

| HTTP | `error` / `code` | Quando |
|---|---|---|
| `400` | `VALIDATION_ERROR` | Falta o código do pedido ou o payload resultante não é válido |
| `400` / `404` | `BUSINESS_ERROR` / `NOT_FOUND` | Loja inexistente ou inativa, dia de negócio fechado |
| `401` | `UNAUTHORIZED` | API key inválida, vencida ou revogada |
| `403` | `FORBIDDEN` | API key sem escopo `orders:write` ou não associada a um vendor |
| `409` | `CONFLICT` / `DUPLICATE_ORDER` | O pedido já existia para o seu vendor. `data` traz `id`, `externalOrderId` e `status` do existente |
| `422` | `INVALID_ORDER` | O corpo de PDV ou quiosque não é válido, ou os headers de cliente faltam ou vieram os dois. `data.issues[]` detalha cada problema |
| `422` | `INVALID_AGGREGATOR_ORDER` | O corpo de agregador não pode ser interpretado |
| `422` | `ORDER_CONFIG_NOT_FOUND` | O catálogo não está habilitado para a sua conta |
| `422` | `CHANNEL_PROFILE_NOT_FOUND` | O canal não está habilitado para a sua conta |
| `422` | `ORDER_TRANSFORMATION_FAILED` | O Fire não conseguiu processar o pedido. Fale com o suporte informando o `order_code` |

<Info>
  Toda requisição fica registrada no Fire com o corpo e o motivo da rejeição, inclusive as
  rejeitadas. Se você reenviar um pedido que já foi criado, a resposta é `409` e ele não é duplicado.
</Info>
