---
title: "Obter pedido"
api: "GET https://api.fire.rest/api/v1/fire/external/orders/{orderId}"
description: "Leia um pedido por qualquer uma de suas referências, com projeção de campos. O pedido deve pertencer ao account e vendor da sua API key."
authMethod: "bearer"
---

Retorna um pedido projetado conforme `fields`. Se o pedido não existe — ou pertence a outro tenant —
a resposta é `404` (a existência nunca é vazada entre tenants).

Sem `fields`, retorna o pedido completo: linhas, totais, meios de pagamento, progresso da cobrança,
dados de faturamento e o documento fiscal com o seu percurso. É o endpoint para conciliar um pedido
específico.

## Autenticação

<ParamField header="x-api-key" type="string" required>
  Sua API key do Fire com scope `orders:read`. A key **deve ser vendor-scoped** — keys sem `vendorId`
  são rejeitadas com `403`.
</ParamField>

## Path params

<ParamField path="orderId" type="string" required>
  Qualquer uma das referências públicas do pedido:

  | referência | o que é |
  | --- | --- |
  | `orders.id` | o UUID interno do Fire |
  | `order_external` | o id que você atribuiu ao criar o pedido |
  | `metadata.order_id` | cópia do id externo dentro do pedido |
  | `order_code` | o código do pedido que o caixa vê |

  Não precisa traduzir: use o id que você já conhece. `order_code` pode se repetir dentro do seu
  vendor; se corresponder a mais de um pedido, a resposta é `409` — nesse caso, use o UUID ou o id externo.
</ParamField>

<Note>
  É o mesmo conjunto de referências aceito por [Cancelar pedido](/pt/api-reference/cancel-order), então
  o id com que você criou o pedido também serve para lê-lo.
</Note>

## Query params

<ParamField query="fields" type="string">
  Projeção — veja [Projeção de campos](/pt/api-reference/list-orders#projeção-de-campos). Omita para
  retornar todos os campos.
</ParamField>

## Requisição

<RequestExample>
```http
GET https://api.fire.rest/api/v1/fire/external/orders/7e2b8c10-1a2b-4c3d-8e9f-0a1b2c3d4e5f?fields=id,orderCode,status,orderLines,totals
x-api-key: <sua_api_key>
```
</RequestExample>

## Resposta

A resposta chega no envelope padrão `{ "success": true, "data": { … } }`. `data` é um objeto
pedido, projetado conforme `fields`. Veja a lista completa de campos em
[Projeção de campos](/pt/api-reference/list-orders#projeção-de-campos).

Para conciliar um pedido, leia em [Listar pedidos](/pt/api-reference/list-orders):

- [Escalas dos valores](/pt/api-reference/list-orders#escalas-dos-valores): nem todos os valores
  vêm na mesma escala.
- [Progresso da cobrança](/pt/api-reference/list-orders#progresso-da-cobrança-settlement-e-payments):
  `settlement` (quanto já entrou) e `payments` (com o quê).
- [O bloco `fiscal` por país](/pt/api-reference/list-orders#o-bloco-fiscal-por-país): o
  documento fiscal e o seu percurso.

Cada entrada de `paymentMethods` traz `details.acquirer_configured`: quem credencia esse pagamento conforme a configuração da sua conta na Fire, ou `null` — veja
[Credenciadora configurada](/pt/events/order-completed#credenciadora-configurada).

<Note>
  Cada linha de `orderLines` e cada modificador podem trazer `descriptions` (`{ marketing, ops }`) do catálogo da Fire e `item_type` com o tipo do menu, como nos [eventos de pedido](/pt/events/order-completed#data-orderlines). `reported_item_type` é informativo: o tipo enviado pelo canal quando não coincide com o menu, ou `null` se não enviou nenhum. Não vem se o canal enviou o tipo do menu.
</Note>
