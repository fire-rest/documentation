---
title: "Listar lojas"
api: "GET https://app.fire.rest/api/v1/fire/external/stores"
description: "Lista as lojas do account e vendor vinculados à sua API key, com paginação e filtros."
authMethod: "bearer"
---

Retorna as lojas do account + vendor vinculados à sua API key, com a **configuração completa** —
incluindo o bloco `fiscal` necessário para integrações de nota fiscal eletrônica. Campos internos do
back-office (drafts, overrides, colunas de auditoria) são excluídos.

Use `fields` para reduzir o payload ao que você precisa.

## Autenticação

<ParamField header="x-api-key" type="string" required>
  Sua API key do Fire com scope `store:read`. A key **deve ser vendor-scoped** (binding account +
  vendor) — keys sem `vendorId` são rejeitadas com `403`.
</ParamField>

## Query params

<ParamField query="accountId" type="string" required>
  Identificador do account. **Deve coincidir** com o account da sua API key, ou a requisição é rejeitada com `403`.
</ParamField>

<ParamField query="vendorId" type="string" required>
  Identificador do vendor. **Deve coincidir** com o vendor da sua API key, ou a requisição é rejeitada com `403`.
</ParamField>

<ParamField query="fields" type="string">
  Lista de campos a retornar separados por vírgula (projeção). Veja [Projeção de campos](#projecao-de-campos).
  Omita para retornar todos. Um campo desconhecido resulta em `400`.
</ParamField>

<ParamField query="status" type="string">
  Filtra por status de publicação: `DRAFT`, `PUBLISHED`, `PARTIALLY_PUBLISHED`, `ARCHIVED`.
</ParamField>

<ParamField query="active" type="string">
  Filtra por estado operacional: `ACTIVE`, `INACTIVE`, `SUSPENDED`.
</ParamField>

<ParamField query="syncStatus" type="string">
  Filtra por estado de sync: `SYNCED`, `PENDING`, `FAILED`.
</ParamField>

<ParamField query="countryId" type="string">Filtra por id de país.</ParamField>
<ParamField query="cityId" type="string">Filtra por id de cidade.</ParamField>
<ParamField query="channel" type="string">Filtra por um código de canal publicado (ex. `APP`).</ParamField>
<ParamField query="query" type="string">Busca de texto sobre nome, store code e external id.</ParamField>

<ParamField query="page" type="integer" default="1">Número da página (base 1).</ParamField>
<ParamField query="size" type="integer" default="20">Tamanho da página (1–500).</ParamField>

## Requisição

<RequestExample>
```http
GET https://app.fire.rest/api/v1/fire/external/stores?accountId=100&vendorId=100.1.10&page=1&size=20
x-api-key: <sua_api_key>
```
</RequestExample>

## Bloco fiscal

`fiscal` traz a configuração de nota fiscal eletrônica da loja. É o **mesmo objeto** que você já
recebe como `store.storeFiscalConfig` nos eventos de pedido, por exemplo
[`order.completed`](/pt/events/order-completed) — ambos são gerados pela mesma projeção, então as
duas fontes nunca divergem.

| Campo | Tipo | Descrição |
|---|---|---|
| `enabled` | boolean | `true` se a emissão está habilitada para a loja |
| `company` | object \| null | Snapshot do emissor: `{ govIdType, govIdNumber, legalName, tradeName }` |
| `govIdType` | string \| null | Tipo de documento fiscal da loja (ver tabela) |
| `govIdNumber` | string \| null | Número do documento fiscal |
| `secondaryGovIdType` | string \| null | Documento secundário — hoje apenas Brasil |
| `secondaryGovIdNumber` | string \| null | Número do documento secundário |
| `metadata` | object \| null | **Específico por país** — ver abaixo |

### O que `metadata` retorna por país

Só `metadata` muda entre países. Discrimine usando `location.countryCode` — não há campo `country`
dentro de `fiscal`.

| País | `govIdType` | `secondaryGovIdType` | `metadata` |
|---|---|---|---|
| 🇧🇷 BR | `CNPJ` | `INSCRICAO_ESTADUAL` | `{ storeCode3S, serialNumber, neverstop: { enabled, url } }` |
| 🇪🇨 EC | `RUC` | — | `null` |
| 🇨🇴 CO | `NIT` | — | `null` |
| 🇨🇱 CL | `RUT` | — | `null` |
| 🇦🇷 AR | `CUIT` | — | `null` |
| 🇻🇪 VE | `RIF` | — | `null` |

Hoje o Brasil é o único país que popula `metadata`. Novos países adicionam chaves sem quebrar o
contrato. `fiscal` é `null` em lojas sem configuração fiscal.

## Projeção de campos

Escolha quais campos cada loja retorna, como a projeção do MongoDB ou o parâmetro `_source` do
Elasticsearch.

- Sem `fields` → todos os campos são retornados.
- `fields=id,name,fiscal` → apenas esses campos.
- Um campo fora do catálogo → `400` com a lista de campos permitidos.

**Campos disponíveis**: `id`, `storeNumber`, `storeCode`, `accountId`, `vendorId`, `name`,
`externalId`, `status`, `active`, `timezone`, `location`, `services`, `channels`,
`publishedChannels`, `operationSchedule`, `salesSchedule`, `schedulesByChannel`, `taxesInfo`,
`contactInfo`, `deliveryInfo`, `salesGoals`, `fiscal`, `operational`, `syncStatus`, `lastSyncedAt`,
`createdAt`, `updatedAt`.

```http
GET https://app.fire.rest/api/v1/fire/external/stores?accountId=100&vendorId=100.1.10&fields=id,storeCode,fiscal
x-api-key: <sua_api_key>
```
