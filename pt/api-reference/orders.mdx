---
title: "Injetar pedido"
api: "POST https://api.fire.rest/v1/orders"
description: "Injeta um pedido no Fire. O Fire valida o payload, persiste a requisição bruta, normaliza canal + cumprimento e emite webhooks de ciclo de vida. Idempotente em `orderId`."
authMethod: "bearer"
---

O endpoint aceita o envelope de pedido do XMART Gateway. A validação é estrutural e **passthrough** — campos desconhecidos são persistidos sem alteração. Os campos obrigatórios listados abaixo são os que o Fire realmente exige hoje; o resto é opcional.

A autenticação usa uma API Key com escopo `orders:write`. Veja [API keys](/pt/configuration/api-keys).

**Idempotência.** Um `orderId` repetido para a mesma loja retorna `200 OK` com `_idempotent: true` em vez de criar um duplicado.

### Fallback legacy (quando `channel` / `service` / `device` não vêm)

Por retrocompatibilidade com payloads XMART antigos, o Fire **deriva** os objetos canônicos a partir dos campos legacy quando você não os envia. Esta tabela é só de referência para chamadores legacy — integrações novas devem enviar `channel`, `service`, `device` e `operator` diretamente.

| Campo persistido | Ordem de fontes |
|---|---|
| `metadata.channel.uid` | `channel.uid` |
| `metadata.channel.code` | `channel.code` → canal resolvido a partir de `channelId` → `channelName.toUpperCase()` |
| `metadata.service.uid` | `service.uid` |
| `metadata.service.code` | `service.code` → cumprimento resolvido a partir de `channelId` → `selectedShippingMethod.toUpperCase()` |
| `metadata.device.uid` | `device.uid` → `stationId` |
| `metadata.device.name` | `device.name` → `channelName.toUpperCase()` |
| `metadata.device.metadata.ip` | `device.metadata.ip` → `additionalInfo.kiosk.ip` |
| `metadata.operator` | `operator` (não é derivado — `null` se ausente) |
| `metadata.kds.buzzerName` | `additionalInfo.kiosk.buzzer_name` |
| `metadata.kds.invoiceEmail` | `additionalInfo.kiosk.invoice_email` |
| `metadata.kds.invoicePrint` | `additionalInfo.kiosk.invoice_print` |
| `metadata.kds.orderCode` | `additionalInfo.orderCode` |

## Referência de objetos

### DetailedPrice

Cada `unitPrice` / `totalPrice` é um `DetailedPrice`. Apenas `currencyCode` e `total` são validados estritamente; o restante é opcional e passa de largo.

| Campo | Tipo | Notas |
|---|---|---|
| `currencyCode` | string | ISO 4217 (`USD`, `COP`, `BRL`, …). Obrigatório. |
| `total` | number | Total final. Obrigatório. |
| `subtotalWithoutTaxes` | number | Subtotal sem impostos. |
| `subtotalIncludeDiscounts` | number | Subtotal após descontos, antes dos impostos. |
| `discountPercentage` | number \| null | Percentual de desconto aplicado. |
| `discountsValue` | number \| null | Valor de desconto. |
| `taxesPercentage` | number | Percentual de imposto. |
| `taxValue` | number | Valor de imposto. |
| `totalBeforeSale` | number | Preço antes da promoção. |
| `suggestedPrice` | number | Preço sugerido original. |
| `taxes` | `PriceTax[]` | **Apenas Brasil.** Detalhamento por imposto — veja abaixo. Quando presente sobrescreve `taxesPercentage` / `taxValue`. |

**`PriceTax`** (dentro de `taxes[]` para países multi-imposto como o Brasil):

| Campo | Tipo | Notas |
|---|---|---|
| `name` | string | `icms`, `pis`, `cofins`, `ibs`, `cbs`, … |
| `rate` | string | Decimal em string (ex.: `"0.18"`). |
| `amount` | string | Decimal em string (ex.: `"7.06"`). |
| `base` | number | Base reduzida (reforma IBS/CBS). |
| `metadata` | object | Livre (ex.: `{ cst: "00" }`). |

### PaymentMethod

Apenas `processor`, `currencyCode`, `transactionStatus` e `totalBill` são validados estritamente. O restante passa de largo. Os payloads reais do XMART costumam incluir:

| Campo | Tipo | Notas |
|---|---|---|
| `processor` | string | Obrigatório. Exemplos: `CREDIT_CARD`, `Kushki`, `Efectivo`. |
| `currencyCode` | string | Obrigatório. |
| `transactionStatus` | string | Obrigatório. Exemplos: `APPROVED`, `PENDING`, `DECLINED`. |
| `totalBill` | number | Obrigatório. Valor cobrado por este método. |
| `paymentMethodCode` | string | Código interno do método. |
| `transactionType` | string | Ex.: `credit`, `debit`. |
| `transactionId` | string | ID de transação do adquirente. |
| `tid`, `mid` | string \| null | Identificadores de terminal / lojista. |
| `authorizationCode` | string | Código de autorização. |
| `voucher` | string \| null | Número do voucher. |
| `referenceNumber` | string \| null | Referência do adquirente. |
| `exactPayment` | boolean | Se foi entregue valor exato. |
| `customerCashAmount` | string \| number | Valor em dinheiro entregue. |
| `acquirer` | object | `{ code, name }`. |
| `card` | object \| null | Dados do cartão (mask, BIN, últimos quatro, bandeira, portador). |
| `transactionDate` | object | `{ date, timeZoneName, timeZoneType }`. |
| `additionalInfo` | object | Metadata específica do processador. |

  `true` apenas em `200` (replay de um `orderId` existente).
</ResponseField>

<ResponseField name="_adapter" type="string">
  Sempre `"xmart"` enquanto o adaptador XMART for o envelope ativo.
</ResponseField>

### Códigos de status

| Status | Significado |
|---|---|
| `201 Created` | Novo pedido aceito. |
| `200 OK` | Replay idempotente — já existe um pedido com esse `orderId`. A resposta inclui `_idempotent: true`. |
| `400 Bad Request` | Falha de validação de schema (campo obrigatório ausente, tipo incorreto). |
| `401 Unauthorized` | API key ausente ou inválida. |
| `403 Forbidden` | A API key não tem o escopo `orders:write` ou o tenant não bate. |
| `404 Not Found` | `store.code` não resolve para uma loja conhecida. |
| `422 Unprocessable Entity` | Dia operacional fechado ou loja inativa. |
