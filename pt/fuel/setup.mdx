## Autenticação

O FUEL utiliza seu próprio sistema de contas, separado da plataforma FIRE. Acesse a página de login do FUEL e entre com as credenciais fornecidas pelo administrador da sua equipe.

<Note>
  As contas do FUEL são gerenciadas por um superadmin. Se você não tiver credenciais, solicite ao seu administrador que crie uma conta para você pelo painel **Admin**.
</Note>

## O contexto operacional

Antes de usar qualquer aba do FUEL, você precisa estabelecer um **contexto operacional** pela barra lateral. O contexto informa ao FUEL qual ambiente FIRE e qual loja devem ser utilizados em todas as operações.

A barra lateral contém quatro menus suspensos sequenciais e um seletor de loja:

<Steps>
  <Step title="Selecione um ambiente">
    Escolha o ambiente FIRE que você deseja utilizar (por exemplo, staging, produção ou um sandbox específico de um cliente). Os ambientes são configurados por um superadmin e cada um aponta para uma URL base do FIRE com suas próprias credenciais de API.
  </Step>
  <Step title="Selecione uma conta">
    Escolha a conta dentro desse ambiente. As contas agrupam vendors sob uma única entidade operadora.
  </Step>
  <Step title="Selecione um país">
    Escolha o país de operação. A seleção do país afeta os formatos de documentos fiscais, o tratamento de moeda e a disponibilidade de canais.
  </Step>
  <Step title="Selecione um vendor">
    Escolha o vendor (marca ou conceito) que você está testando. Cada vendor possui sua própria chave de API com escopo no ambiente selecionado.
  </Step>
  <Step title="Selecione uma loja">
    Use o seletor de loja para escolher o estabelecimento específico. O seletor exibe apenas as lojas pertencentes ao vendor selecionado acima.
  </Step>
</Steps>

Após realizar todas as cinco seleções, o contexto operacional estará ativo e cada aba utilizará essa combinação de ambiente + loja.

<Warning>
  Abas como **Pedido individual**, **Lote** e **Cancelar pedido** ficam desabilitadas até que um contexto operacional completo seja definido. Certifique-se de que todos os cinco menus suspensos exibam um valor antes de continuar.
</Warning>

## Ambientes

Os ambientes são a ponte entre o FUEL e uma instalação do FIRE. Cada registro de ambiente armazena:

- Uma **URL base do FIRE** (por exemplo, `https://api.staging.firepos.io`)
- Uma **chave de API por vendor**, com escopo naquele ambiente

Somente um superadmin pode criar ou editar ambientes. Se você precisar de um novo ambiente (por exemplo, um novo sandbox de cliente ou um ambiente de UAT), entre em contato com seu superadmin.

## Painel Admin (somente superadmin)

O painel **Admin** é acessível pela barra lateral por usuários com privilégios de superadmin. Ele contém quatro seções:

<CardGroup cols={2}>
  <Card title="Ambientes" icon="server">
    Adicione, edite ou desative ambientes. Para cada ambiente, você pode configurar a URL base do FIRE e definir chaves de API por vendor.
  </Card>
  <Card title="Gestão de usuários" icon="users">
    Crie contas no FUEL, atribua funções (usuário / superadmin) e desative contas quando membros da equipe saírem.
  </Card>
  <Card title="Menus de teste" icon="utensils">
    Crie e gerencie menus de teste — catálogos de produtos utilizados por **Pedido individual** e **Lote** para construir os payloads de pedidos.
  </Card>
  <Card title="Lojas" icon="store">
    Visualize e sincronize a lista de lojas para cada combinação de vendor/ambiente.
  </Card>
</CardGroup>

## Menus de teste

Um menu de teste é um catálogo de produtos gerenciado pelo admin que define quais produtos, canais e processadores de pagamento estão disponíveis ao construir um pedido no FUEL.

Cada menu de teste tem escopo para um ambiente e vendor específicos, e contém:

- **Produtos** — itens com nome, preço (na unidade mínima da moeda: centavos para BRL, dólares para USD) e grupos de modificadores opcionais (molhos, tamanhos, adicionais)
- **Canais** — os canais de pedido disponíveis para aquele vendor: `POS`, `KIOSK`, `APP`, `AGGREGATOR`
- **Processadores** — os métodos de pagamento aceitos pelo vendor

<Warning>
  **Pedido individual** e **Lote** exigem pelo menos um menu de teste atribuído ao vendor e ambiente ativos. Sem um menu de teste, o FUEL não consegue construir os payloads de pedidos e os controles de injeção ficarão indisponíveis. Solicite ao seu superadmin que crie um menu de teste caso nenhum apareça no seletor.
</Warning>

<Tip>
  Os menus de teste podem modelar múltiplas linhas de produtos e faixas de preço. Crie menus separados para diferentes cenários de teste (por exemplo, um menu de "caminho feliz" com itens simples e um menu de "modificadores" para testar grupos de modificadores com mais intensidade).
</Tip>

Assim que o contexto operacional estiver definido e um menu de teste estiver disponível, você estará pronto para começar a injetar pedidos. Consulte [Pedido individual](/pt/fuel/single-order) para um guia passo a passo.
