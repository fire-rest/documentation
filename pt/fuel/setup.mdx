## Autenticação

Faça login com suas credenciais de conta do FUEL na URL do FUEL fornecida pela sua equipe. O FUEL usa seu próprio banco de dados de usuários gerenciado por um superadmin — entre em contato com seu admin se precisar de uma conta.

## Selecionando um contexto de operação

Antes de usar qualquer aba, você precisa selecionar um contexto de operação completo na barra lateral esquerda:

<Steps>
  <Step title="Selecione um ambiente">
    Um ambiente mapeia para uma implantação específica do FIRE (ex.: homologação Brasil, produção Equador). Cada ambiente tem sua própria URL base e chaves de API.
  </Step>
  <Step title="Selecione uma conta">
    A conta dentro desse ambiente (corresponde a uma rede de restaurantes ou grupo de marcas).
  </Step>
  <Step title="Selecione um país">
    O país de operação. Determina as regras fiscais, moeda, processadores de pagamento e canais disponíveis.
  </Step>
  <Step title="Selecione um vendor">
    O vendor (marca) dentro da conta. Cada vendor tem sua própria chave de API configurada no ambiente.
  </Step>
  <Step title="Selecione uma loja">
    A localização específica da loja. Carrega os canais disponíveis para essa loja.
  </Step>
</Steps>

Quando todos os cinco estiverem selecionados, as abas ficam ativas e todas as requisições são vinculadas a esse contexto.

## Ambientes

Os ambientes são configurados por um superadmin. Cada ambiente armazena:

| Configuração | Descrição |
|---|---|
| **Rótulo** | Nome legível (ex.: "Homologação BR", "Produção EC") |
| **URL base do FIRE** | O endpoint da API do FIRE para esse ambiente — o gateway/adapters usados na injeção |
| **Host de catálogo (`xmart_url`)** | O host XMART que serve o menu real (`productsBy`) usado pelo **Pedido individual**. Distinto da URL base; a autenticação é a mesma `x-api-key` por vendor |
| **Host do motor fiscal (`fiscal_engine_url`)** | Usado para enriquecer o documento fiscal antes de injetar no Brasil (`/enrich-order`). Opcional para testes não fiscais |
| **Chaves de API** | Uma chave de API criptografada por vendor ID — usada para todas as requisições de pedidos e webhooks |

<Note>
  As chaves de API são armazenadas criptografadas. Superadmins as gerenciam pelo painel **Admin → Utils** (o botão de ação flutuante no canto inferior direito, visível apenas para superadmins).
</Note>

## Menu real vs. menus de teste

O **Pedido individual** lê o **menu real** da loja diretamente do XMART (`productsBy`), usando o host de catálogo do ambiente (`xmart_url`). Não há nada para configurar por pedido — escolha o contexto de operação e o catálogo ao vivo é carregado.

Os **menus de teste** ainda são usados pelo **Lote**. Um menu de teste é um catálogo de produtos predefinido, criado por um admin para um ambiente e vendor específicos, e define:

- Produtos disponíveis com preços e grupos de modificadores
- Canais de venda (POS, KIOSK, APP, AGGREGATOR)
- Processadores de pagamento

Se nenhum menu de teste aparecer no dropdown, peça a um superadmin para criar um em **Admin → Menus de Teste**.

<Warning>
  O **Lote** exige pelo menos um menu de teste atribuído ao vendor e ambiente ativos. O **Pedido individual** não — ele precisa de um host de catálogo (`xmart_url`) configurado no ambiente e, para os cupons fiscais brasileiros, de um host do motor fiscal (`fiscal_engine_url`).
</Warning>

## Painel admin (somente superadmin)

Superadmins têm acesso a um painel admin flutuante (o botão no canto inferior direito):

| Seção | O que faz |
|---|---|
| **Ambientes** | Criar/editar ambientes, definir URL base do FIRE, gerenciar chaves de API por vendor |
| **Usuários** | Convidar e gerenciar usuários do FUEL, restringir acesso por ambiente |
| **Menus de Teste** | Criar e publicar catálogos de produtos para qualquer ambiente/vendor |
| **Dados de exemplo** | Sincronizar amostras de pedidos do FIRE |
