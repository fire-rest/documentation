`order.invoiced` dispara quando o **órgão fiscal do país** autoriza o documento fiscal associado a um pedido — SEFAZ no Brasil, SRI no Equador, DIAN na Colômbia, AFIP na Argentina, SII no Chile, SENIAT na Venezuela.

Este evento é **separado de** [`order.completed`](/pt/events/order-completed): o pedido é pago primeiro (`order.completed`), depois o documento é emitido por meio do seu provedor fiscal, e `order.invoiced` dispara apenas quando o órgão devolve a autorização.

## Condição de disparo

O Fire emite `order.invoiced` quando um documento fiscal do pedido chega a `authorized`, seja pela integração nativa com o provedor ou pelo [callback fiscal](/pt/api-reference/fiscal-callback) com `eventType: "authorized"`.

| | |
|---|---|
| Cobertura | **Todos os países** — o país viaja em `fiscal.countryCode`, não no nome do evento |
| Chave de idempotência | `event.id` |
| Dispara mais de uma vez | Uma vez por Integration Flow ativo inscrito no evento; com retentativa em falha de entrega |
| Latência em relação a `order.completed` | Normalmente segundos; minutos se o órgão estiver degradado |

## O que tem em `trigger.data`

O mesmo snapshot V4 do pedido que [`order.completed`](/pt/events/order-completed), mais o bloco **`fiscal`** descrito abaixo. O `status` do pedido permanece `"COMPLETED"`: uma autorização fiscal não muda o status do pedido.

## Onde vivem os totais fiscais

`authority.amounts` são os valores **do documento** conforme o órgão os reportou. Os agregados do próprio pedido (vBC, vNF, vICMS…) continuam em `data.payments.metadata.fiscal`, e a classificação por linha (NCM, CFOP) em `data.orderLines[n].metadata.fiscal` — igual a `order.completed`.

## Handler de exemplo

```js
async function onOrderInvoiced(data) {
  const { orderId, fiscal } = data;
  const doc = fiscal.authority;

  await db.fiscalDocs.upsert({
    where: { providerDocId: doc.providerDocId },
    create: {
      fireOrderId: orderId,
      country: fiscal.countryCode,
      documentType: doc.documentType,
      documentNumber: doc.documentNumber,
      issuedAt: doc.issuedAt,
      // Itere countryData: as chaves dependem do país.
      identifiers: doc.countryData,
      total: doc.amounts.total ?? null,
    },
    update: {},
  });

  // Arquive o XML legal — o link pode expirar.
  const xml = await fetch(doc.xmlUrl).then((r) => r.text());
  await archive.put(`xml/${doc.providerDocId}.xml`, xml);
}
```

## Erros comuns

- **Leia `fiscal.authority.*`, não `fiscal.*`.** Os campos planos da v1.2 não existem mais. A tabela em [Mudanças de caminho](#mudanças-de-caminho-em-relação-à-versão-anterior) mapeia cada um.
- **Não alinhe por hora usando `authorizedAt` no Brasil.** Ele carrega uma meia-noite convencional; use `issuedAt` para a hora.
- **`history` inclui o documento atual.** Não conte suas entradas como "documentos anteriores".
- **Não há evento para `rejected` / `denied` / `error`.** Esses resultados são armazenados, mas não disparam `order.invoiced`.

## `data.fiscalRepresentation`

Sem mudanças na v2. É a **numeração fiscal** que o ponto de venda obteve *antes* de injetar o pedido — o que foi impresso no caixa — e é um bloco diferente de `fiscal`: `fiscalRepresentation` é o que foi numerado, `fiscal.authority` é o que o órgão decidiu. A referência de campos está em [`order.completed`](/pt/events/order-completed) e na [página v1.2](/pt/events-v1/order-invoiced#data-fiscalrepresentation).
