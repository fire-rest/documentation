`order.reversed` dispara quando o **órgão fiscal confirma o cancelamento** de um documento que tinha autorizado previamente. É o resultado fiscal de [`order.cancelled`](/pt/events/order-cancelled): o pedido é cancelado primeiro dentro do Fire (`order.cancelled`), o cancelamento é solicitado ao órgão por meio do seu provedor fiscal, e `order.reversed` dispara apenas quando o órgão o aprova.

<Warning>
  **Se você precisa saber que o documento está anulado no órgão, escute este evento — não `order.cancelled`.** `order.cancelled` é emitido quando o pedido é cancelado, antes de o órgão responder: seu bloco fiscal ainda descreve a fatura autorizada. Em um caso real brasileiro, `order.cancelled` saiu às `05:06:45`, a SEFAZ aprovou às `05:06:51` e `order.reversed` saiu às `05:08:12`.
</Warning>

## Condição de disparo

O Fire emite `order.reversed` quando um documento fiscal do pedido chega a `cancelled` — pela integração nativa com o provedor ou pelo [callback fiscal](/pt/api-reference/fiscal-callback) com `eventType: "cancelled"` — **e** o pedido tem um registro operacional de cancelamento no Fire. Sem esse registro o evento não é emitido: o bloco `cancellation` é o que diz aos consumidores que se trata de uma anulação e não de uma venda.

| | |
|---|---|
| Cobertura | **Todos os países** — o país viaja em `cancellation.fiscal.countryCode` |
| Chave de idempotência | `event.id` |
| Dispara mais de uma vez | Uma vez por Integration Flow ativo inscrito no evento; com retentativa em falha de entrega |
| Latência em relação a `order.cancelled` | Normalmente segundos; minutos se o órgão estiver degradado |
| Pré-condição | Um documento autorizado anterior para o mesmo `orderId` |

## O que tem em `trigger.data`

O mesmo snapshot V4 do pedido que [`order.completed`](/pt/events/order-completed), com `status: "CANCELLED"`, mais o bloco **`cancellation`**: os mesmos campos de auditoria de `order.cancelled` e, dentro dele, o **bloco fiscal** com o documento cancelado.

## Referência de `data.cancellation`

Os campos de auditoria são os mesmos de [`order.cancelled`](/pt/events/order-cancelled#referência-de-data-cancellation) — incluindo `cancellationId`, que ambos os eventos compartilham para o mesmo cancelamento e que você pode usar como chave de junção. O bloco fiscal está documentado abaixo.

## Lifecycle

```mermaid
flowchart LR
    A([pedido pago]) --> B([order.completed])
    B --> C([order.invoiced])
    C --> D([pedido cancelado no Fire])
    D --> E([order.cancelled])
    E --> F([órgão aprova o cancelamento])
    F --> G([order.reversed])
```

Um pedido cancelado **antes** de seu documento ser autorizado só dispara `order.cancelled`: não há nada a estornar no órgão.

## Handler de exemplo

```js
async function onOrderReversed(data) {
  const { orderId, cancellation } = data;
  const fiscal = cancellation.fiscal;
  const doc = fiscal.authority;

  await db.fiscalDocs.update({
    where: { providerDocId: doc.providerDocId },
    data: {
      status: "cancelled",
      documentType: doc.documentType,
      cancelledAt: doc.cancelledAt,
      reason: cancellation.cancellationType,
    },
  });

  // O documento substituído, inteiro, está em history.
  const replaced = fiscal.history.find(
    (e) => e.authority.documentNumber === fiscal.compensates?.documentNumber
      && e.status !== "cancelled",
  );

  await reconciliation.close(orderId, { original: replaced?.authority });
}
```

## Erros comuns

- **Leia `cancellation.fiscal`, não `cancellation.metadata.fiscal`.** O caminho anterior vem vazio na v3.
- **`sefazCancellation` não existe mais.** A data do cancelamento é `authority.cancelledAt`; os identificadores do órgão estão em `authority.countryData`.
- **A entrega fora de ordem é possível.** Se chegar um `order.reversed` de um pedido para o qual você não tem cancelamento, crie-o a partir do bloco `cancellation` deste evento em vez de descartar o evento.
- **Não há evento para um cancelamento que falhou.** Se o órgão rejeitar o cancelamento, nenhum evento dispara.

## `data.fiscalRepresentation`

Sem mudanças na v3. Guarda os números do comprovante impresso no caixa — o que **está sendo anulado** — e é um bloco diferente de `cancellation.fiscal`: `fiscalRepresentation` é o que foi numerado, `authority` é o que o órgão decidiu. A referência de campos está na [página v2](/pt/events-v2/order-reversed#data-fiscalrepresentation).
