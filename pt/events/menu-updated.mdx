<Note>
  **Disponibilidade limitada.** Este evento está em implantação e é habilitado por conta. Consulte seu contato no Fire para saber se já se aplica à sua.
</Note>

<Warning>
  Este é o evento `menu.updated` de **Integration Flows**, documentado nesta página. **Não** é o webhook de integrações de agregadores com o mesmo nome descrito em [Referência de webhooks → `menu.updated`](/pt/webhook-reference/menu-updated): aquele é o formato das integrações existentes, tem outro formato e não muda.
</Warning>

`menu.updated` é disparado toda vez que o cardápio de uma loja é **sincronizado** para um canal e um tipo de serviço. Ele sempre traz o **cardápio completo** dessa combinação — nunca um diff. Trate-o como uma substituição total do cardápio que você tem para ela.

Chamamos essa combinação de **terna**: **loja × canal × tipo de serviço** (por exemplo, Laboratorio · `KIOSK` · `TAKEAWAY`). Cada terna tem um id fixo, `data.menuSyncId`, que também viaja em [`product.updated`](/pt/events/product-updated) e liga os dois eventos.

## Condição de disparo

- **Sincronizar o cardápio** de uma ou várias ternas (por exemplo, em Atribuição de cardápios) emite **um** `menu.updated` **por terna**.
- **Salvar uma mudança de preço** no editor de preços e disponibilidade emite o `menu.updated` da terna editada, além do [`product.updated`](/pt/events/product-updated) de preço. As outras ternas que compartilham esse cardápio recebem a mudança na próxima sincronização.

Todos os eventos de uma mesma ação compartilham `data.groupId`.

**Nada é emitido** ao editar o catálogo sem sincronizar, nem ao desligar ou religar um produto: isso é um [`product.updated`](/pt/events/product-updated). Um flow limitado a certos canais recebe apenas as ternas desses canais.

| | |
|---|---|
| Cobertura | Todos os países, nas contas em que o evento está habilitado |
| Unidade | Uma terna: `data.store` × `data.channel` × `data.fulfillment` |
| Id da terna | `data.menuSyncId` — fixo; também é `data.menu.menus[0].id` |
| Id da ação | `data.groupId` — o mesmo em todos os eventos dessa ação |
| Id da entrega | `event.id`, como em todos os eventos (a execução do flow) |
| Entidade | `_meta.triggerEntityId` é `data.menuSyncId` |

## Regras gerais

1. **Um só modelo de produto.** Cada produto de `data.menu.products[]` usa os mesmos campos que um produto de [`product.updated`](/pt/events/product-updated). Os nomes vão em camelCase (`modifierGroups`, `outOfStockUntil`).
2. **Textos por idioma.** Todo texto visível é `{ "<locale>": "texto" }`, no idioma do país da loja (`es-EC`, `pt-BR`, …).
3. **Preços.** `price` é o que se cobra (oferta incluída). `anchorPrice` é o preço de lista riscado e só aparece quando há oferta.
4. **Horários na hora local da loja** (`store.locationInfo.timezone`). Veja [Horários](#horários).
5. **`metadata` só traz dados de catálogo.** O que não está aqui não viaja no evento.

### O produto como opção

Um mesmo produto pode ser opção em vários grupos e custar diferente em cada um: a bebida vale `0` dentro do combo e `1.00` como adicional. Cada entrada de `pricing.modifiers[]` diz como ele é vendido **nesse grupo**:

| Campo | O que é |
|---|---|
| `modifierGroupId` | O grupo (`modifierGroups[].id`). |
| `price` | O que se cobra ao escolhê-lo nesse grupo, oferta incluída. |
| `anchorPrice` / `anchorPricePercentage` | Preço de lista e desconto; só se a opção tiver oferta. |
| `isTaxInclusive`, `taxRate` | Igual ao produto. |
| `minimumQuantity` / `maximumQuantity` | Quantas unidades **desta opção** podem ser escolhidas. |
| `defaultQuantity` | Quantidade pré-selecionada. |
| `displayType` | Como se escolhe: `RADIO` (só uma do grupo), `CHECKBOX` (marcar ou não) ou `QUANTITY` (seletor de quantidade). |

### `menu.categories[]`

| Campo | O que é |
|---|---|
| `id`, `name`, `imageUrl` | Identidade da categoria. `description` é sempre `null`. |
| `items[]` | Produtos da categoria **na ordem de exibição**: `{ "type": "PRODUCT", "id": "…" }`. |
| `availability.status` | `ACTIVE` (exibida) ou `HIDDEN` (existe mas não é exibida). |
| `availability.schedules` | Horário próprio da categoria, ou `null`. `inactiveUntil` é sempre `null`. |
| `metadata` | Sempre `{}`. |

A **ordem das categorias** é a de `menus[0].categoryIds`.

### `menu.modifierGroups[]`

| Campo | O que é |
|---|---|
| `id` | Id do grupo (veja a nota). |
| `title` | Título exibido. `description` é sempre `null`. |
| `displayType` | Sempre `"LIST"`. Como cada opção é escolhida vai em `pricing.modifiers[].displayType`. |
| `modifierIds[]` | Produtos que são opção neste grupo, na ordem de exibição. Apontam para `products[].id`. |
| `minimumQuantity` | Mínimo a escolher (`1` ou mais = obrigatório). |
| `maximumQuantity` | Máximo a escolher. **`9999` = sem limite.** |
| `chargeAboveQuantity` | Sempre `null`. `metadata` é sempre `{}`. |

<Note>
  **Um grupo do catálogo pode chegar como várias cópias.** `{id}` é o grupo como está; `{id}-{hash}` é uma cópia para quando produtos pai diferentes põem **preços diferentes** nas mesmas opções, e `{id}-x{hash}` corta um **ciclo** (um produto que, pelas suas opções, chegaria a si mesmo). Para você são grupos normais: siga `pricing.modifierGroupIds` do pai. Os ids são estáveis enquanto os preços que os geram não mudarem, e o cardápio seguinte sempre traz os vigentes.
</Note>

### `menu.recommendations[]`

| Campo | O que é |
|---|---|
| `id` | `rec-{hash}`. |
| `title` | Nome exibido (o do produto sugerido). `description` é sempre `null`. |
| `type` | `UPSELL` (trocar por algo maior) ou `CROSS_SELL` (adicionar algo mais). |
| `targetProductId` | O produto sugerido (`products[].id`). |
| `metadata` | Sempre `{}`. |

### `menu.menus[0]` — o cabeçalho

| Campo | O que é |
|---|---|
| `id` | Igual a `menuSyncId`. |
| `name` | Nome do cardápio no catálogo. `description` é sempre `null`. |
| `schedules` | Horário de venda **efetivo** da terna, já resolvido (loja → canal → tipo de serviço). `null` = 24/7. |
| `categoryIds[]` | As categorias, na ordem de exibição. |
| `status` | `ACTIVE` ou `INACTIVE`; hoje sempre `ACTIVE`. |
| `metadata.catalogMenuId` | Id do cardápio do catálogo atribuído à terna. Várias ternas podem compartilhar cardápio. |
| `metadata.store` | Cópia de `store.metadata`, para quem lê o cardápio salvo sem o evento em mãos. `{}` se a loja não tiver dados. |

## Horários

O formato é o mesmo no cardápio, na categoria e no produto:

```json
[
  { "dayOfWeek": "monday", "periods": [{ "startTime": "09:00:00", "endTime": "22:30:00" }] },
  { "dayOfWeek": "sunday", "periods": [] }
]
```

- Sempre vêm **os 7 dias**, de `monday` a `sunday`, em minúsculas.
- Hora local da loja, formato `HH:MM:SS`. `periods: []` = fechado nesse dia.
- Um horário que cruza a meia-noite vem **dividido** em dois dias (sexta `22:00:00–23:59:59` e sábado `00:00:00–02:00:00`). Um fechamento às `00:00` vem como `23:59:59`.
- `null` no lugar da lista = sem restrição.

## Entrega e ordem

- **O cardápio manda.** Cada `menu.updated` traz o estado completo da terna: o último substitui tudo o que veio antes. Entre um cardápio e o seguinte, [`product.updated`](/pt/events/product-updated) aplica as mudanças rápidas.
- **Em ordem por terna.** Dentro de um flow, os `menu.updated` de **uma mesma terna** são entregues um de cada vez, na ordem em que foram emitidos; ternas diferentes avançam em paralelo. Um `menu.updated` e um `product.updated` não têm ordem garantida entre si: ordene por `event.emittedAt`.
- **Deduplique por `data.groupId` + `data.menuSyncId`.** `event.id` identifica a entrega, não o fato (veja [Idempotência do seu lado](/pt/events/delivery#idempotência-do-seu-lado)).
- **Responda rápido.** Devolva `2xx` assim que receber e processe depois: um cardápio completo é grande, e um timeout provoca novas tentativas.
- **Se o seu sistema processa de forma assíncrona**, você pode informar o resultado final com o [callback de resultado de cardápio](/pt/api-reference/catalog-menu-result).

## Handler de exemplo

```js
async function onMenuUpdated(event, data) {
  const key = `${data.groupId}:${data.menuSyncId}`;
  if (await db.appliedMenus.exists(key)) return; // já aplicado

  // Substituição total — o evento traz o cardápio completo da terna
  await db.menus.replace(data.menuSyncId, {
    store: data.store.uid,
    channel: data.channel.code,
    fulfillment: data.fulfillment.service.code,
    emittedAt: event.emittedAt,
    menu: data.menu,
  });
  await db.appliedMenus.add(key);
}
```

## Erros comuns

- **Não é um diff.** Um produto que falta no evento não está mais no cardápio dessa terna. Substitua, não combine.
- **Não mostre os produtos `optionOnly`.** Eles existem só como opção de um grupo.
- **O esgotado viaja no produto.** `availability.status: "OUT_OF_STOCK"` com seu `outOfStockUntil`: não há uma lista à parte.
- **Os ids de cópia de grupo podem mudar** se mudarem os preços que os geram. Use sempre os do último cardápio.
- **Não há evento de "cardápio excluído".** Um cardápio deixa de ser atualizado; se você precisa detectar remoções, compare com o seu próprio registro.
