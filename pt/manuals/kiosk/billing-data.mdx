Um cliente que pede nota fiscal precisa digitar o documento, o nome, o telefone, o endereço e o e-mail em uma tela touch, em pé e com gente atrás. Se ele se cansa, sai como consumidor final ou desiste da fila. Por isso, se o cliente aceitou os termos em uma compra anterior, o quiosque preenche os dados dele assim que ele digita o documento.

<Note>
  **O mínimo que você precisa saber**

  - Os tipos de documento são os mesmos do POS, com os mesmos nomes, em cada país.
  - O quiosque preenche só os campos **vazios**: o que o cliente já digitou não é alterado.
  - Os dados só são salvos se o cliente **aceitar os termos**. Sem isso, na próxima vez ele digita tudo de novo.
</Note>

## O caminho simples

1. No pagamento, em **Quer adicionar dados à sua nota fiscal?**, o cliente toca em **Sim, quero dados**.
2. Ele escolhe o tipo de documento e digita o número.
3. Se já comprou antes e aceitou os termos, o quiosque preenche os dados dele e avisa com **Preenchemos seus dados de uma compra anterior**.
4. Ele revisa os dados, aceita os termos e toca em **Salvar dados de faturamento**.

## Tipos de documento por país

O quiosque abre no tipo mais comum do país. Os nomes são os mesmos que o POS mostra.

| País | Tipos de documento | Abre em |
|------|--------------------|---------|
| Colômbia | NIT, CEDULA, CEDULA DE EXTRANJERIA, PASAPORTE | CEDULA |
| Equador | RUC, CEDULA, PASAPORTE | CEDULA |
| Brasil | CPF, CNPJ, PASSAPORTE | CPF |
| Argentina | NIT, CEDULA, DNI, CUIL, CUIT, PASAPORTE | DNI |
| Chile | RUT, CEDULA, PASAPORTE | RUT |
| Venezuela | V, E, F, A, CEDULA, RIF, PASAPORTE | CEDULA |

O quiosque confere o tamanho do número conforme o tipo; no Brasil, também os dígitos verificadores do CPF e do CNPJ. O passaporte aceita letras.

## Como o quiosque preenche os dados

- Busca o cliente quando o número tem 6 caracteres ou mais e o cliente para de digitar.
- Preenche o nome, o telefone, o endereço e o e-mail que estiverem vazios, e marca o checkbox de termos: o cliente já os tinha aceitado.
- Se o cliente muda o tipo ou o número, o quiosque apaga o que tinha preenchido. O mesmo número em outro tipo de documento é outra pessoa.
- O nome e o endereço são preenchidos como o formulário do quiosque aceita: sem acentos nem símbolos como **#** ("Pérez" fica "Perez").
- Se o cliente muda um dado preenchido, ao pagar o dado novo é salvo.
- Se não encontra o cliente, ou o sistema não responde, o formulário fica vazio como sempre e o pedido segue.

Não busca quando o cliente não quer nota fiscal, nem com CPF ou CNPJ no Brasil, que não pedem esses dados.

## O que o cliente precisa aceitar

| País | Para salvar os dados |
|------|----------------------|
| Equador | As quatro políticas: termos e promoções, experiência personalizada e compartilhar dados dentro e fora do país. O checkbox principal marca todas juntas. |
| Demais países | Os termos e condições e receber promoções. |

Se no Equador o cliente desmarca alguma política em **Configurar preferências**, os dados dele não são salvos.

## Onde os clientes aparecem

Os clientes salvos são consultados e excluídos no backoffice: consulte [Clientes do Fire](/pt/manuals/backoffice/customers). O mesmo cliente é encontrado pelo quiosque e pelo POS.

## Erros que custam caro

<Warning>
  **Faturar com os dados preenchidos sem olhar.** Se o cliente se mudou ou trocou de e-mail, a nota fiscal sai com o dado antigo. Ele precisa revisar os dados antes de pagar: o que corrigir fica salvo.
</Warning>

<Warning>
  **Trocar o tipo de documento para "testar".** O mesmo número em outro tipo é outro cliente: o quiosque não o encontra e, se ele aceitar os termos, salva um novo.
</Warning>

  </Accordion>

  </Accordion>

  <Accordion title="O quiosque preencheu um dado errado">

  </Accordion>
</AccordionGroup>
