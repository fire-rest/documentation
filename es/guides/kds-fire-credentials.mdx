Esta página es para quien configura print y cancel contra Fire. Los operadores de cocina usan el formulario de [Credenciales Fire](/es/manuals/kds/fire-credentials) en el backoffice; no eligen variables de entorno.

## Cascada de resolución

En runtime fire-kds siempre recorre la misma lista:

1. **Fila activa de vendor** para el vendor de la orden (**Vendor ID** del backoffice).
2. **Default de cuenta** (vendor vacío).
3. **Variables de entorno** en el servidor fire-kds.

Print y cancel **no** comparten el mismo fallback de env:

| Consumidor | Env después de las filas en DB |
|---|---|
| Impresión fiscal | Solo `FISCAL_PRINT_API_BASE_URL` + `FISCAL_PRINT_API_KEY`. **Nunca** `FIRE_API_*`. |
| Cancelación | `FIRE_API_BASE_URL` + `FIRE_API_KEY`, y luego el par fiscal si esos están vacíos. |

La API key guardada es la misma fila para ambos trabajos, y los dos la envían como `x-api-key`. Para imprimir, la key necesita el scope **`printing:read`** (**Impresión Lectura** en Gestión de API).

<Note>
  `base_url` es **solo el host** de Fire (`https://br.app.fire.rest`). fire-kds agrega el path. Una URL con `/v1/print` se rechaza en el backoffice.
</Note>

## Llamada de impresión

La factura fiscal y la comanda llegan ya armadas desde la [API de impresión de Fire](/es/api-reference/print-order-document). Cuando las credenciales se resuelven, fire-kds pide:

```
POST {base_url}/api/v1/external/printing/orders/{external_id}/documents/{invoice|kitchen}
x-api-key: {api_key}

{ "printer": { "width": 48 }, "copies": 1 }
```

Fire devuelve las líneas listas para imprimir; fire-kds solo las convierte a ESC/POS y las envía al Agente Fire con las copias de la tienda. La misma llamada sirve para todos los países, así que un país o una plantilla nuevos no necesitan un cambio en el KDS. La comanda es el pedido completo y sus etiquetas siguen el país de la tienda.

- El timeout por defecto es 4 segundos.
- `400` / `401` / `403` / `409` y una orden sin `external_id` son permanentes: no se imprime nada y el trabajo queda fallido.
- `404`, `5xx` y los timeouts van a la cola de reintentos (**Imprimir facturas encoladas** en la pantalla).
- Una key sin `printing:read` recibe `403` en todas las órdenes de la cuenta.

<Note>
  La llamada anterior (`GET .../restaurant-os/injected-orders/{external_id}/fiscal-print` con `Authorization: Bearer`) ya no la usa fire-kds. [Datos de impresión fiscal](/es/api-reference/fiscal-print) sigue documentado para los partners que la leen.
</Note>

## Cancelación cuando Fire dice que no

Cancel usa la misma cascada y luego `POST` al adaptador de cancelación de XMART con `x-api-key`.

Si Fire (o el adaptador) responde 4xx:

- El operador ve **Fire rechazó la cancelación** más el detalle de policy (`reasonDetail` y, si viene, umbral / tiempo transcurrido).
- El **trabajo de cancel queda fallido**. El ticket **no** se marca cancelado.
- El mismo input no se reintenta solo.

Una cancelación posterior exitosa, o un bump, es lo que saca el ticket de la cocina.

Ver [Acciones en pantalla](/es/manuals/kds/screen-actions#cancelar-un-pedido) para el copy del operador.

## Lo que esto no es

- No es el Agente Fire (WebSocket de impresora local). Eso es [Periféricos, impresión y validación](/es/manuals/kds/peripherals-printing).
- No es el catálogo de motivos de cancelación. Cuáles ofrece el KDS se define en [Configuración de cuenta](/es/manuals/kds/account-settings#motivos-de-cancelación-en-el-kds).
