Fire entrega los eventos a tu sistema vía webhooks. Debes registrar tu endpoint en el dashboard de Fire antes de poder recibir cualquier evento.

## Registrar un endpoint

<Steps>
  <Step title="Abre el dashboard de Fire">
    Ve a **Settings → Endpoints**.
  </Step>
  <Step title="Agrega un nuevo endpoint">
    Pulsa **Add endpoint** y rellena los siguientes campos:

    | Campo | Descripción |
    |---|---|
    | URL | La URL HTTPS donde quieres recibir los eventos |
    | Secret | Una cadena aleatoria usada para firmar payloads — guárdala de forma segura |
    | Events | Selecciona los eventos que quieres recibir (o deja "All events") |
  </Step>
  <Step title="Guarda y prueba">
    Guarda el endpoint. Usa el botón **Send test event** para verificar que tu endpoint es accesible y responde con `2xx`.
  </Step>
</Steps>

<Warning>
  Tu endpoint debe responder con un estado `2xx` en menos de 10 segundos o Fire marcará la entrega como fallida.
</Warning>

## Comportamiento de reintentos

Si tu endpoint devuelve una respuesta no-`2xx` o se agota el tiempo, Fire reintenta la entrega con backoff exponencial:

| Intento | Retraso |
|---|---|
| 1er reintento | 5 minutos |
| 2do reintento | 30 minutos |
| 3er reintento | 2 horas |
| 4to reintento | 8 horas |

## Recibir eventos

Cada evento que Fire envía es una petición HTTP `POST` con:

- `Content-Type: application/json`
- `X-Fire-Signature`: firma HMAC-SHA256 del body (consulta [Autenticación](/es/authentication))
- `X-Fire-Event`: identificador del tipo de evento (p. ej. `menu.updated`)

Verifica siempre la firma antes de procesar el evento.

## Responder a los eventos

Devuelve un `200 OK` (o cualquier `2xx`) en cuanto recibas la petición — antes de procesar el payload. Esto evita timeouts si tu procesamiento toma tiempo.

```js
app.post("/fire-webhook", (req, res) => {
  res.sendStatus(200); // Confirma primero

  // Procesa de forma asíncrona
  processFireEvent(req.body).catch(console.error);
});
```
