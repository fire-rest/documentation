---
title: "Callback fiscal"
description: "Cómo reportar el resultado de tu integración fiscal local (DIAN, SRI, SII, AFIP, SENIAT) a Fire."
---

Para todos los países excepto Brasil, **tu sistema es responsable de la integración fiscal local**: emitir el documento legal con la autoridad tributaria del país y obtener la autorización. Una vez tienes ese resultado, lo reportas a Fire mediante un único callback multipaís para que Fire persista el documento fiscal, registre el evento y cierre el ciclo de la orden.

<Note>
  Brasil es distinto: Fire integra con PlugNotas para emitir NFC-e / NF-e directamente, así que Fire emite `fiscal.authorized.br` / `fiscal.cancelled.br` hacia tu sistema. **No** llames a este endpoint para BR. Ver [Cómo funcionan los eventos](/es/concepts/events).
</Note>

## Cuándo llamarlo

Llamas al callback fiscal en estos momentos:

| Momento | `eventType` |
|---|---|
| La autoridad local autorizó el documento | `authorized` |
| La autoridad local canceló el documento | `cancelled` |
| La autoridad local rechazó o denegó el documento | `rejected` o `denied` |
| Tu integración fiscal falló y quieres registrarlo | `error` |

## Endpoint

```http
POST https://api.fire.rest/v1/webhooks/fiscal/callback
x-api-key: <key con scope webhooks:fiscal>
Content-Type: application/json
```

La API key debe llevar el scope `webhooks:fiscal` y estar atada a un vendor. Ver [API keys y scopes](/es/configuration/api-keys#webhooks-fiscal) para crearla.

## Body — envelope común

```json
{
  "countryCode":     "CO" | "EC" | "CL" | "AR" | "VE",
  "eventType":       "authorized" | "cancelled" | "rejected" | "denied" | "error",
  "providerEventId": "evt-xyz-1001",
  "occurredAt":      "2025-01-15T14:30:05.000Z",
  "orderId":         "<UUID de la orden en Fire>",
  "eventId":         "<event.id del envelope que Fire te envió>",
  "document":        { /* específico del país — ver más abajo */ },
  "error":           { "code": "string", "message": "string" }
}
```

| Campo | Requerido | Descripción |
|---|---|---|
| `countryCode` | Siempre | Código ISO de país. Determina la validación de `document`. |
| `eventType` | Siempre | Qué pasó en la autoridad local. |
| `providerEventId` | Siempre | Llave de idempotencia. Fire indexa `(provider_code, providerEventId)` UNIQUE — reenviar el mismo id es seguro. |
| `occurredAt` | Siempre | Cuándo ocurrió en **tu** sistema, ISO 8601 UTC. No cuándo lo recibió Fire. |
| `orderId` | Siempre | UUID de la orden en Fire (`data.orderId` del envelope original `order.completed`). |
| `eventId` | Siempre | El `event.id` que Fire te envió. Correlaciona el callback con la ejecución específica que disparó tu emisión local. |
| `document` | Cuando `eventType` ∈ {authorized, cancelled} | Datos fiscales del país. Cambia según `countryCode`. |
| `error` | Cuando `eventType` ∈ {rejected, denied, error} | Motivo del fallo. |

## Respuesta

```json
{
  "received":     true,
  "receiptId":    "rcpt_abc123",
  "outcome":      "updated",
  "documentId":   "doc_xyz789",
  "processingMs": 42
}
```

| Campo | Significado |
|---|---|
| `received` | Siempre `true` con `2xx`. Confirma que Fire aceptó el payload. |
| `receiptId` | Identificador en Fire de esta entrega. Útil para auditoría. |
| `outcome` | `created`, `updated`, `idempotent`, `regression` o `duplicate`. Ver [Idempotencia y concurrencia](#idempotencia-y-concurrencia). |
| `documentId` | ID interno en Fire del `fiscal_document` persistido. |
| `processingMs` | Tiempo de procesamiento server-side, en milisegundos. |

### Códigos HTTP

| Status | Significado |
|---|---|
| `200 OK` | Callback aceptado y procesado (incluye reentregas idempotentes). |
| `400 Bad Request` | El body no pasó la validación. La respuesta indica los campos en falta. |
| `401 Unauthorized` | API key falta o es inválida. |
| `403 Forbidden` | A la API key le falta el scope `webhooks:fiscal`, o el `orderId` no pertenece al mismo vendor. |
| `5xx` | Error transitorio de Fire. Reintenta con backoff. |

## Idempotencia y concurrencia

Hay dos redes de seguridad incorporadas:

1. **Deduplicación por `providerEventId`.** Fire fuerza un índice UNIQUE sobre `(provider_code, providerEventId)`. Si reenvías el mismo callback (un blip de red, retry desde tu cola) Fire devuelve `outcome="duplicate"` en vez de aplicarlo dos veces.
2. **Transiciones de estado optimistas.** Si dos callbacks de la misma orden compiten (ej. authorized vs cancelled), Fire aplica el segundo solo si el estado destino es alcanzable desde el actual. En caso contrario devuelve `outcome="regression"` y deja el documento como estaba.

Para semánticas limpias, trata `providerEventId` como un **hash estable** del identificador del evento de la autoridad local — nunca lo aleatorices en reintentos.

## Autocreación del documento fiscal

Tu sistema es la fuente de verdad de los datos fiscales fuera de Brasil. La primera vez que Fire recibe un callback para un `orderId` sin documento fiscal previo, Fire **autocrea** la fila desde tu payload. Los callbacks siguientes la actualizan.

Esto significa que no necesitas llamar a ningún endpoint de "crear documento" antes del primer callback de autorización — el callback mismo es el create.

## Ejemplo completo — Colombia

```bash
curl -X POST https://api.fire.rest/v1/webhooks/fiscal/callback \
  -H "x-api-key: pk_live_a1b2c3…" \
  -H "Content-Type: application/json" \
  -d '{
    "countryCode":     "CO",
    "eventType":       "authorized",
    "providerEventId": "evt-co-1001",
    "occurredAt":      "2025-01-15T14:30:05.000Z",
    "orderId":         "df8cdf6a-62c5-4daf-b35f-b6e7bb1b98b3",
    "eventId":         "2167a211-e757-4185-abb4-59474e275019",
    "document": {
      "docType":      "invoice",
      "docSubtype":   "factura",
      "totalAmount":  100.00,
      "taxAmount":    19.00,
      "currencyCode": "COP",
      "pdfUrl":       "https://files.tu-sistema.com/factura.pdf",
      "xmlUrl":       "https://files.tu-sistema.com/factura.xml",
      "emittedAt":    "2025-01-15T14:30:05.000Z",
      "cufe":         "5fa31abc1234567890def1234567890abcdef1234567890",
      "prefijo":      "FE-CO",
      "numeroDian":   "FE-CO-1001",
      "qrCode":       "https://catalogo-vpfe.dian.gov.co/document/searchqr?documentkey=5fa31abc…"
    }
  }'
```

Respuesta exitosa:

```json
{
  "received":     true,
  "receiptId":    "rcpt_2024_01_15_co_1001",
  "outcome":      "created",
  "documentId":   "doc_co_1001",

```
