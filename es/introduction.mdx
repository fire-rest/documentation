Fire es un OS de gestión de restaurantes que administra tiendas, menús, productos y canales de venta — incluyendo web, app, kioscos y agregadores de delivery (iFood, Keeta, 99, Rappi y otros).

## Modelo de integración

Fire es el **sistema maestro**. Emite eventos cada vez que algo relevante cambia y recibe órdenes inyectadas desde sistemas externos. Cualquier sistema que necesite reaccionar a esos eventos — o enviar órdenes hacia Fire — se integra a través de la misma interfaz:

- **Fire emite eventos** cada vez que cambian tiendas, menús o productos, y cuando se actualiza el estado de una orden. Los eventos se entregan a tu sistema mediante llamadas webhook por HTTPS.
- **Fire recibe órdenes** inyectadas por tu sistema vía la API REST.

Tu sistema se suscribe a los eventos que le interesan y actúa sobre ellos como necesite.

<Note>
  Un caso de uso común es un orquestador de agregadores — un sistema que conecta Fire con varios agregadores de delivery (iFood, Keeta, 99, Rappi, etc.) y maneja la publicación y el flujo de órdenes entre ellos. La integración funciona igual para cualquier otro tipo de cliente.
</Note>

## Qué construyes

Tu integración necesita:

| Responsabilidad | Dirección |
|---|---|
| Exponer un endpoint HTTPS para recibir eventos | Fire → Tu sistema |
| Validar las firmas de los eventos entrantes | Fire → Tu sistema |
| Procesar eventos de publicación (tienda, menú, producto) | Fire → Tu sistema |
| Inyectar órdenes en Fire usando tu API key | Tu sistema → Fire |
| Manejar las actualizaciones de estado de órdenes desde Fire | Fire → Tu sistema |

Tanto la recepción de eventos como las llamadas a la API requieren autenticación. Consulta [Autenticación](/es/authentication) para saber cómo se emiten las credenciales y cómo usarlas en cada lado.
