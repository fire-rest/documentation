## Autenticación

FUEL utiliza su propio sistema de cuentas, independiente de la plataforma FIRE. Navega a la página de inicio de sesión de FUEL e ingresa con las credenciales que te proporcionó el administrador de tu equipo.

<Note>
  Las cuentas de FUEL son gestionadas por un superadmin. Si no tienes credenciales, pídele a tu administrador que cree una cuenta para ti desde el panel de **Administración**.
</Note>

## El contexto operativo

Antes de usar cualquier pestaña de FUEL, debes establecer un **contexto operativo** mediante la barra lateral. El contexto le indica a FUEL qué entorno de FIRE y qué tienda debe utilizar como destino en todas las operaciones.

La barra lateral contiene cuatro selectores secuenciales y un selector de tienda:

<Steps>
  <Step title="Selecciona un entorno">
    Elige el entorno de FIRE al que deseas apuntar (por ejemplo, staging, producción o un sandbox específico para un cliente). Los entornos son configurados por un superadmin y cada uno apunta a una URL base de FIRE con sus propias credenciales de API.
  </Step>
  <Step title="Selecciona una cuenta">
    Elige la cuenta dentro de ese entorno. Las cuentas agrupan a los vendors bajo una misma entidad operadora.
  </Step>
  <Step title="Selecciona un país">
    Elige el país de operación. La selección del país afecta los formatos de documentos fiscales, el manejo de moneda y la disponibilidad de canales.
  </Step>
  <Step title="Selecciona un vendor">
    Elige el vendor (marca o concepto) que estás probando. Cada vendor tiene su propia API key vinculada al entorno seleccionado.
  </Step>
  <Step title="Selecciona una tienda">
    Usa el selector de tienda para elegir la ubicación específica. El selector muestra únicamente las tiendas que pertenecen al vendor seleccionado en el paso anterior.
  </Step>
</Steps>

Una vez realizadas las cinco selecciones, el contexto operativo estará activo y cada pestaña apuntará a esa combinación de entorno + tienda.

<Warning>
  Pestañas como **Orden individual**, **Batch** y **Cancelar orden** permanecen deshabilitadas hasta que se establezca un contexto operativo completo. Asegúrate de que los cinco selectores muestren un valor antes de continuar.
</Warning>

## Entornos

Los entornos son el puente entre FUEL y un despliegue de FIRE. Cada registro de entorno almacena:

- Una **URL base de FIRE** (por ejemplo, `https://api.staging.firepos.io`) — el gateway/adapters que se usan para la inyección.
- Un **host de catálogo** (`xmart_url`) — el host de XMART que sirve el menú real (`productsBy`) que usa **Orden individual**. Distinto de la URL base; la autenticación es la misma `x-api-key` por vendor.
- Un **host del motor fiscal** (`fiscal_engine_url`) — se usa para enriquecer el documento fiscal antes de inyectar en Brasil (`/enrich-order`). Opcional para pruebas no fiscales.
- Una **API key por vendor**, vinculada a ese entorno.

Solo un superadmin puede crear o editar entornos. Si necesitas un nuevo entorno (por ejemplo, un sandbox para un nuevo cliente o un entorno de UAT), contacta a tu superadmin.

## Panel de administración (solo superadmin)

El panel de **Administración** es accesible desde la barra lateral para los usuarios con privilegios de superadmin. Contiene cuatro secciones:

<CardGroup cols={2}>
  <Card title="Entornos" icon="server">
    Agrega, edita o desactiva entornos. Por cada entorno puedes configurar la URL base de FIRE y establecer las API keys por vendor.
  </Card>
  <Card title="Gestión de usuarios" icon="users">
    Crea cuentas de FUEL, asigna roles (usuario / superadmin) y desactiva cuentas cuando los miembros del equipo se van.
  </Card>
  <Card title="Menús de prueba" icon="utensils">
    Crea y gestiona menús de prueba — catálogos de productos utilizados por **Batch** para construir los payloads de órdenes. (**Orden individual** usa el menú real de la tienda en su lugar.)
  </Card>
  <Card title="Tiendas" icon="store">
    Visualiza y sincroniza la lista de tiendas para cada combinación de vendor y entorno.
  </Card>
</CardGroup>

## Menú real vs. menús de prueba

**Orden individual** lee el **menú real** de la tienda directamente desde XMART (`productsBy`), usando el host de catálogo del entorno (`xmart_url`). No hay nada que configurar por orden — elige el contexto operativo y el catálogo en vivo se carga.

Los **menús de prueba** todavía los usa **Batch**. Un menú de prueba es un catálogo de productos administrado por el superadmin que define qué productos, canales y procesadores de pago están disponibles al generar los payloads de órdenes. Cada menú de prueba está vinculado a un entorno y vendor específicos, y contiene:

- **Productos** — ítems con nombre, precio (en la unidad mínima de la moneda: centavos para BRL, dólares para USD) y grupos de modificadores opcionales (salsas, tamaños, extras)
- **Canales** — los canales de orden disponibles para ese vendor: `POS`, `KIOSK`, `APP`, `AGGREGATOR`
- **Procesadores** — los métodos de pago que acepta el vendor

<Warning>
  **Batch** requiere al menos un menú de prueba asignado al vendor y entorno activos. **Orden individual** no — necesita un host de catálogo (`xmart_url`) configurado en el entorno y, para los cupones fiscales de Brasil, un host del motor fiscal (`fiscal_engine_url`).
</Warning>

Una vez que tu contexto operativo esté establecido, estarás listo para comenzar a inyectar órdenes. Consulta [Orden individual](/es/fuel/single-order) para un recorrido paso a paso.
