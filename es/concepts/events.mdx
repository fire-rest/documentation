Fire avisa a tu sistema en tiempo real con **eventos**. Cuando se completa una orden, cuando un documento fiscal queda autorizado, cuando se actualiza un menú — Fire dispara un evento. Lo recibes como un `POST` HTTP en el endpoint que registraste, actúas, y respondes `2xx`.

Todo evento que Fire entrega comparte el mismo envelope. La forma dentro de `data` cambia según el tipo, pero el envoltorio nunca lo hace.

Dos ideas clave:

1. **Fire es la fuente de verdad.** Las órdenes entran por una sola API; el ciclo se gestiona dentro de Fire.

## El envelope

Todo evento que Fire entrega — sin importar tipo o país — usa la misma forma exterior:

```json
{
  "event": {
    "id":        "evt_2167a211e7574185abb459474e275019",
    "type":      "order.completed",
    "createdAt": "2025-01-15T14:30:00.000Z"
  },
  "data": {
    /* payload específico del evento — ver la página reference de cada tipo */
  }
}
```

| Campo | Tipo | Descripción |
|---|---|---|
| `event.id` | string | Identificador único de **este intento de entrega**. Estable entre reintentos. Úsalo como llave de idempotencia. |
| `event.type` | string | Discriminador del tipo. Un endpoint puede manejar varios tipos haciendo switch sobre este campo. |
| `event.createdAt` | string | Cuándo se materializó el evento en Fire (UTC, ISO 8601). |
| `data` | object | Payload específico. Los campos dependen de `event.type`. Ver la página reference de cada tipo abajo. |

<Tip>
  Para semántica "procesa esta orden exactamente una vez", almacena `event.id` en tu base con un UNIQUE constraint. Si recibes el mismo `event.id` dos veces, devuelve `2xx` y omite el procesamiento.
</Tip>

## Entrega

<Steps>
  <Step icon="signature" title="Fire firma cada solicitud">
    Fire calcula `HMAC-SHA256(body, secret)` y lo adjunta como `X-Fire-Signature`. Tu endpoint recalcula la misma firma sobre el body crudo y compara.
  </Step>
  <Step icon="paper-plane" title="Fire entrega a tu endpoint">
    `POST` con `Content-Type: application/json`, `X-Fire-Event` (el tipo) y `X-Fire-Delivery` (ID único de entrega).
  </Step>
  <Step icon="reply" title="Tú confirmas rápido">
    Devuelve cualquier `2xx` en menos de 10 segundos. Procesa el payload de forma asíncrona después del acknowledge.
  </Step>
  <Step icon="rotate" title="Fire reintenta ante fallos">
    No-`2xx` o timeout dispara reintentos exponenciales. Tras agotarlos, la entrega se marca como fallida y la puedes reenviar desde el dashboard.
  </Step>
</Steps>

### Headers

| Header | Descripción |
|---|---|
| `Content-Type` | Siempre `application/json` |
| `X-Fire-Event` | Tipo de evento (ej. `order.completed`) — mismo valor que `event.type` en el body |
| `X-Fire-Signature` | `HMAC-SHA256` del body crudo usando el secreto del endpoint |
| `X-Fire-Delivery` | ID único de intento de entrega (cambia en cada retry) |

Ver [Autenticación](/es/authentication) para la receta completa de verificación de firma.

### Calendario de reintentos

| Intento | Cuándo |
|---|---|
| 1er retry | 5 minutos tras la entrega fallida |
| 2do retry | 30 minutos |
| 3er retry | 2 horas |
| 4to retry | 8 horas |

Tras el 4º retry la entrega queda marcada como fallida. Puedes reenviarla manualmente desde el dashboard de Fire.

### Confirmación

<CodeGroup>

```js Node.js (Express)
app.post("/fire-webhook", express.raw({ type: "application/json" }), (req, res) => {
  // 1. Verificar firma sobre el body crudo — antes de parsear
  const signature = req.headers["x-fire-signature"];
  if (!verifySignature(req.body, signature, process.env.FIRE_WEBHOOK_SECRET)) {
    return res.status(400).send("invalid signature");
  }

  // 2. Acknowledge rápido
  res.sendStatus(200);

  // 3. Procesar async
  const event = JSON.parse(req.body.toString());
  processEvent(event).catch(console.error);
});
```

```python Python (FastAPI)
@app.post("/fire-webhook")
async def fire_webhook(request: Request):
    raw = await request.body()
    signature = request.headers.get("x-fire-signature")

    if not verify_signature(raw, signature, settings.FIRE_WEBHOOK_SECRET):
        raise HTTPException(400, "invalid signature")

    event = json.loads(raw)
    asyncio.create_task(process_event(event))
    return Response(status_code=200)
```

```php PHP
<?php
$raw = file_get_contents('php://input');
$signature = $_SERVER['HTTP_X_FIRE_SIGNATURE'] ?? '';

if (!verifySignature($raw, $signature, getenv('FIRE_WEBHOOK_SECRET'))) {
    http_response_code(400);
    exit('invalid signature');
}

http_response_code(200);
header('Content-Type: application/json');
echo '{"received": true}';

// Procesa diferido (ej. encolar)
$event = json_decode($raw, true);
enqueueProcessing($event);
```

</CodeGroup>

## Comportamiento por país

El envelope es idéntico en todos los países. Lo que cambia es **qué eventos disparan** y **qué hay dentro de los bloques específicos del país**.

<Tabs>
  <Tab title="🇧🇷 Brasil (BR)">
    Fire es dueño de la integración SEFAZ vía PlugNotas, así que Fire emite ambos eventos fiscales nativamente.

    | Evento | Quién lo emite |
    |---|---|
    | `order.completed` | Fire |
    | `order.cancelled` | Fire |
    | `fiscal.authorized.br` | **Fire** (después de la autorización SEFAZ) |
    | `fiscal.cancelled.br` | **Fire** (después de la confirmación SEFAZ de cancelación) |

    Tu sistema **no llama** a `/v1/webhooks/fiscal/callback` para Brasil. Solo recibe eventos desde Fire.

    Los payloads brasileños llevan bloques fiscales extra: `payments.metadata.fiscal` (vBC, vNF, vICMS, vTotTrib…), metadata fiscal por línea (CST, cBenef, cClassTrib…) y el bloque `fiscal` top-level en `fiscal.authorized.br`.
  </Tab>

  <Tab title="🇨🇴 Colombia (CO)">
    Tu sistema gestiona la integración con DIAN y reporta de regreso vía el [callback fiscal](/es/configuration/fiscal-callback).

    | Evento | Quién lo emite |
    |---|---|
    | `order.completed` | Fire |
    | `order.cancelled` | Fire |
    | Fiscal autorizado | **Tú** llamas `POST /v1/webhooks/fiscal/callback` con `eventType="authorized"` |
    | Fiscal cancelado | **Tú** llamas `POST /v1/webhooks/fiscal/callback` con `eventType="cancelled"` |

    Campos del documento: `cufe`, `prefijo`, `numeroDian`, `qrCode`. Moneda: `COP`.
  </Tab>

  <Tab title="🇪🇨 Ecuador (EC)">
    Tu sistema gestiona la integración con SRI y reporta de regreso vía el [callback fiscal](/es/configuration/fiscal-callback).

    | Evento | Quién lo emite |

    | `order.cancelled` | Fire |
    | Fiscal autorizado | **Tú** llamas `POST /v1/webhooks/fiscal/callback` |
    | Fiscal cancelado | **Tú** llamas `POST /v1/webhooks/fiscal/callback` |

    Campos del documento: `claveAcceso`, `numeroAutorizacion`, `ambiente`. Moneda: `USD`.
  </Tab>

  <Tab title="🇨🇱 Chile (CL)">
    Tu sistema gestiona la integración con SII y reporta de regreso vía el [callback fiscal](/es/configuration/fiscal-callback).

    | Evento | Quién lo emite |
    |---|---|
    | `order.completed` | Fire |
    | `order.cancelled` | Fire |
    | Fiscal autorizado | **Tú** llamas `POST /v1/webhooks/fiscal/callback` |
    | Fiscal cancelado | **Tú** llamas `POST /v1/webhooks/fiscal/callback` |

    Campos del documento: `folio`, `ted`, `tipoDte`, `trackId`. Moneda: `CLP`.
  </Tab>

  <Tab title="🇦🇷 Argentina (AR)">
    Tu sistema gestiona la integración con AFIP y reporta de regreso vía el [callback fiscal](/es/configuration/fiscal-callback).

    | Evento | Quién lo emite |
    |---|---|

    | `order.cancelled` | Fire |
    | Fiscal autorizado | **Tú** llamas `POST /v1/webhooks/fiscal/callback` |

</Note>
