---
title: "Webhooks"
description: "Suscríbete a eventos de BOH: completación y falla de transacciones de inventario, y cambios de estado en órdenes de compra."
---

Los webhooks de BOH entregan notificaciones de eventos a tu endpoint HTTPS. Cada evento dispara una solicitud `POST` con un payload JSON y una firma que puedes verificar.

**Scope requerido:** `admin:webhooks`.

**Límite:** hasta **10 endpoints de webhook** por cuenta.

## Eventos soportados

| Tipo de evento | Cuándo se dispara |
|---|---|
| `inventory_transaction.completed` | Una transacción de inventario asíncrona (recepción, merma, conteo, transferencia, lote de producción, ajuste manual) fue procesada exitosamente y los balances de stock se actualizaron. |
| `inventory_transaction.failed` | Una transacción asíncrona falló en el procesamiento y no se reintentará. La transacción queda marcada como `FAILED`. |
| `purchase_order.status_changed` | Una orden de compra pasó a un nuevo estado del ciclo de vida (`DRAFT`, `SENT`, `PARTIAL`, `RECEIVED`, `CANCELLED`). |
| `api_key.expiring` | Una API key expirará en 7 días. Se envía diariamente hasta su expiración o renovación. |
| `ping` | Evento de prueba enviado cuando disparas un test de webhook. |

## Envelope del payload

Todos los eventos comparten el mismo envelope:

```json
{
  "event_id": "evt_01j5k...",
  "event_type": "inventory_transaction.completed",
  "created_at": "2026-08-07T14:30:00.000Z",
  "api_version": "v1",
  "data": { ... }
}
```

## Entrega y reintentos

BOH intenta la entrega de inmediato. Si tu endpoint devuelve una respuesta que no es 2xx o agota el tiempo de espera, BOH reintenta con backoff exponencial. Después de **20 fallas consecutivas**, el endpoint se deshabilita automáticamente (`is_active: false`). Vuelve a habilitarlo llamando al endpoint [Actualizar webhook](#actualizar-webhook).

## Listar webhooks

<api>GET https://boh.api.fire.rest/api/v1/public/admin/webhooks</api>

Devuelve todos los endpoints de webhook de la cuenta.

<ParamField header="x-api-key" type="string" required>API key de BOH con scope `admin:webhooks`.</ParamField>

<RequestExample>
```http
GET /api/v1/public/admin/webhooks
x-api-key: boh_live_xxxxxxxx
```
</RequestExample>

<ResponseExample>
```json 200
{
  "endpoints": [
    {
      "id": "wep_01j5k...",
      "url": "https://tuapp.com/webhooks/boh",
      "events": ["inventory_transaction.completed", "purchase_order.status_changed"],
      "is_active": true,
      "disabled_reason": null,
      "consecutive_failures": 0,
      "created_at": "2026-07-01T09:00:00.000Z",
      "updated_at": "2026-07-01T09:00:00.000Z"
    }
  ]
}
```
</ResponseExample>

## Crear webhook

<api>POST https://boh.api.fire.rest/api/v1/public/admin/webhooks</api>

Registra un nuevo endpoint de webhook. La respuesta incluye el **secreto de firma** — guárdalo de forma segura; solo se muestra una vez.

<ParamField header="x-api-key" type="string" required>API key de BOH con scope `admin:webhooks`.</ParamField>

<ParamField body="url" type="string" required>
  URL HTTPS que recibirá las solicitudes POST. Debe comenzar con `https://`.
</ParamField>

<ParamField body="events" type="string[]" required>
  Uno o más tipos de evento para suscribirse. Ver [Eventos soportados](#eventos-soportados).
</ParamField>

<ResponseField name="endpoint" type="object">El endpoint creado.</ResponseField>
<ResponseField name="secret" type="string">
  Secreto de firma (`whsec_...`). **Se muestra solo una vez.** Guárdalo en tu gestor de secretos de inmediato.
</ResponseField>

<RequestExample>
```json
{
  "url": "https://tuapp.com/webhooks/boh",
  "events": [
    "inventory_transaction.completed",
    "inventory_transaction.failed",
    "purchase_order.status_changed"
  ]
}
```
</RequestExample>

<ResponseExample>
```json 201
{
  "endpoint": {
    "id": "wep_01j5k...",
    "url": "https://tuapp.com/webhooks/boh",
    "events": ["inventory_transaction.completed", "inventory_transaction.failed", "purchase_order.status_changed"],
    "is_active": true,
    "disabled_reason": null,
    "consecutive_failures": 0,
    "created_at": "2026-08-07T14:30:00.000Z",
    "updated_at": "2026-08-07T14:30:00.000Z"
  },
  "secret": "whsec_xxxxxxxxxxxxxxxxxxxxxxxx"
}
```
</ResponseExample>

## Obtener webhook

<api>GET https://boh.api.fire.rest/api/v1/public/admin/webhooks/{webhookId}</api>

Devuelve un único endpoint por ID. El secreto no se devuelve después de la creación.

---

## Actualizar webhook

<api>PATCH https://boh.api.fire.rest/api/v1/public/admin/webhooks/{webhookId}</api>

Actualiza parcialmente un endpoint. Úsalo para cambiar la URL, actualizar la lista de eventos o volver a habilitar un endpoint deshabilitado automáticamente.

<ParamField body="url" type="string">Nueva URL HTTPS.</ParamField>
<ParamField body="events" type="string[]">Nueva lista de suscripciones de eventos (reemplaza la lista existente).</ParamField>
<ParamField body="is_active" type="boolean">
  Coloca `true` para volver a habilitar un endpoint deshabilitado automáticamente. Coloca `false` para deshabilitarlo manualmente.
</ParamField>

---

## Eliminar webhook

<api>DELETE https://boh.api.fire.rest/api/v1/public/admin/webhooks/{webhookId}</api>

Elimina permanentemente el endpoint. No se entregarán más eventos a esa URL.

---

## Listar entregas

<api>GET https://boh.api.fire.rest/api/v1/public/admin/webhooks/{webhookId}/deliveries</api>

Devuelve los intentos de entrega recientes de un endpoint, más recientes primero.

<ParamField query="limit" type="integer" default="50">Número de entregas a devolver (1–100).</ParamField>

<ResponseField name="deliveries" type="object[]">
  Cada entrega incluye: `id`, `event_id`, `event_type`, `status` (`PENDING`, `PROCESSING`, `DELIVERED`, `FAILED`, `DEAD`), `attempts`, `next_retry_at`, `last_response_status` y `last_error`.
</ResponseField>

---

## Probar webhook

<api>POST https://boh.api.fire.rest/api/v1/public/admin/webhooks/{webhookId}/test</api>

Envía un evento `ping` al endpoint de inmediato. Útil para verificar la conectividad y tu lógica de verificación de firma.

<ResponseField name="delivery_id" type="string">UUID de la entrega de prueba creada.</ResponseField>

---

## Verificación de firmas

Cada entrega incluye un header `X-BOH-Signature` que debes verificar para confirmar que la solicitud provino de BOH. Usa el secreto de firma devuelto al crear el endpoint.

```
X-BOH-Signature: sha256=<hex_digest>
```

Calcula `HMAC-SHA256(secret, raw_request_body)` y compáralo con el valor `sha256=`. Rechaza las solicitudes donde no coincidan.

<Warning>
  Siempre verifica las firmas en producción. Omitir la verificación permite que cualquier parte falsifique payloads de webhook.
</Warning>
