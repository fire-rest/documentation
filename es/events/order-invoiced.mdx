`order.invoiced` dispara cuando la **autoridad fiscal del país** autoriza el documento fiscal asociado a una orden — SEFAZ en Brasil, SRI en Ecuador, DIAN en Colombia, AFIP en Argentina, SII en Chile, SENIAT en Venezuela.

Este evento es **separado de** [`order.completed`](/es/events/order-completed): la orden se paga primero (`order.completed`), después el documento se emite vía tu proveedor fiscal, y `order.invoiced` dispara solo cuando la autoridad devuelve la autorización.

## Condición de disparo

Fire emite `order.invoiced` cuando un documento fiscal de la orden llega a `authorized`, ya sea que Fire se entere por su integración nativa con el proveedor o por el [callback fiscal](/es/api-reference/fiscal-callback) con `eventType: "authorized"`.

| | |
|---|---|
| Cobertura | **Todos los países** — el país viaja en `fiscal.countryCode`, no en el nombre del evento |
| Llave de idempotencia | `event.id` |
| Dispara más de una vez | Una vez por cada Integration Flow activo suscrito al evento; se reintenta ante fallas de entrega |
| Latencia respecto de `order.completed` | Normalmente segundos; minutos si la autoridad está degradada |

## Qué hay en `trigger.data`

El mismo snapshot V4 de orden que [`order.completed`](/es/events/order-completed), más el bloque **`fiscal`** descrito abajo. El `status` de la orden queda en `"COMPLETED"`: una autorización fiscal no cambia el status de la orden.

## Dónde viven los totales fiscales

`authority.amounts` son los montos **del documento** tal como los reportó el ente. Los agregados propios de la orden (vBC, vNF, vICMS…) siguen en `data.payments.metadata.fiscal`, y la clasificación por línea (NCM, CFOP) en `data.orderLines[n].metadata.fiscal` — igual que en `order.completed`.

## Handler de ejemplo

```js
async function onOrderInvoiced(data) {
  const { orderId, fiscal } = data;
  const doc = fiscal.authority;

  await db.fiscalDocs.upsert({
    where: { providerDocId: doc.providerDocId },
    create: {
      fireOrderId: orderId,
      country: fiscal.countryCode,
      documentType: doc.documentType,
      documentNumber: doc.documentNumber,
      issuedAt: doc.issuedAt,
      // Recorre countryData: las claves dependen del país.
      identifiers: doc.countryData,
      total: doc.amounts.total ?? null,
    },
    update: {},
  });

  // Archiva el XML legal — el link puede expirar.
  const xml = await fetch(doc.xmlUrl).then((r) => r.text());
  await archive.put(`xml/${doc.providerDocId}.xml`, xml);
}
```

## Errores comunes

- **Lee `fiscal.authority.*`, no `fiscal.*`.** Los campos planos de v1.2 ya no están. La tabla de [Rutas que cambian](#rutas-que-cambian-respecto-del-contrato-anterior) mapea cada uno.
- **No alinees por hora con `authorizedAt` en Brasil.** Lleva una medianoche convencional; usa `issuedAt` para la hora.
- **`history` incluye el documento vigente.** No cuentes sus entradas como "documentos anteriores".
- **No hay evento para `rejected` / `denied` / `error`.** Esos resultados se guardan pero no disparan `order.invoiced`.

## `data.fiscalRepresentation`

Sin cambios en v2. Es la **numeración fiscal** que el punto de venta obtuvo *antes* de inyectar la orden — lo que se imprimió en la caja — y es un bloque distinto de `fiscal`: `fiscalRepresentation` es lo que se numeró, `fiscal.authority` es lo que decidió el ente. La referencia de campos está en [`order.completed`](/es/events/order-completed) y en la [página v1.2](/es/events-v1/order-invoiced#data-fiscalrepresentation).
