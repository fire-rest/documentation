---
title: "Inyectar orden"
api: "POST https://api.fire.rest/v1/orders"
description: "Inyecta una orden en Fire. Fire valida el payload, persiste la solicitud cruda, normaliza canal + cumplimiento y emite webhooks de ciclo de vida. Es idempotente sobre `orderId`."
authMethod: "bearer"
---

El endpoint acepta el sobre de orden del XMART Gateway. La validación es estructural y **passthrough** — los campos desconocidos se persisten sin tocar. Los campos requeridos listados abajo son los que Fire realmente exige hoy; el resto es opcional.

La autenticación usa una API Key con el scope `orders:write`. Consulta [API keys](/es/configuration/api-keys).

**Idempotencia.** Un `orderId` repetido para la misma tienda devuelve `200 OK` con `_idempotent: true` en lugar de crear un duplicado.

### Fallback legacy (cuando `channel` / `service` / `device` no vienen)

Por retrocompatibilidad con payloads XMART antiguos, Fire **deriva** los objetos canónicos de los campos legacy cuando no los envías. Esta tabla es solo de referencia para callers legacy — las integraciones nuevas deben enviar siempre `channel`, `service`, `device` y `operator` directamente.

| Campo persistido | Orden de fuentes |
|---|---|
| `metadata.channel.uid` | `channel.uid` |
| `metadata.channel.code` | `channel.code` → canal resuelto desde `channelId` → `channelName.toUpperCase()` |
| `metadata.service.uid` | `service.uid` |
| `metadata.service.code` | `service.code` → cumplimiento resuelto desde `channelId` → `selectedShippingMethod.toUpperCase()` |
| `metadata.device.uid` | `device.uid` → `stationId` |
| `metadata.device.name` | `device.name` → `channelName.toUpperCase()` |
| `metadata.device.metadata.ip` | `device.metadata.ip` → `additionalInfo.kiosk.ip` |
| `metadata.operator` | `operator` (no se deriva — `null` si no viene) |
| `metadata.kds.buzzerName` | `additionalInfo.kiosk.buzzer_name` |
| `metadata.kds.invoiceEmail` | `additionalInfo.kiosk.invoice_email` |
| `metadata.kds.invoicePrint` | `additionalInfo.kiosk.invoice_print` |
| `metadata.kds.orderCode` | `additionalInfo.orderCode` |

## Referencia de objetos

### DetailedPrice

Cada `unitPrice` / `totalPrice` es un `DetailedPrice`. Solo `currencyCode` y `total` se validan estrictamente; el resto es opcional y pasa de largo.

| Campo | Tipo | Notas |
|---|---|---|
| `currencyCode` | string | ISO 4217 (`USD`, `COP`, `BRL`, …). Requerido. |
| `total` | number | Total final. Requerido. |
| `subtotalWithoutTaxes` | number | Subtotal sin impuestos. |
| `subtotalIncludeDiscounts` | number | Subtotal después de descuentos, antes de impuestos. |
| `discountPercentage` | number \| null | Porcentaje de descuento aplicado. |
| `discountsValue` | number \| null | Monto de descuento. |
| `taxesPercentage` | number | Porcentaje de impuesto. |
| `taxValue` | number | Monto de impuesto. |
| `totalBeforeSale` | number | Precio antes de oferta. |
| `suggestedPrice` | number | Precio sugerido original. |
| `taxes` | `PriceTax[]` | **Solo Brasil.** Desglose por impuesto — ver más abajo. Cuando viene, sobrescribe `taxesPercentage` / `taxValue`. |

**`PriceTax`** (dentro de `taxes[]` para países multi-impuesto como Brasil):

| Campo | Tipo | Notas |
|---|---|---|
| `name` | string | `icms`, `pis`, `cofins`, `ibs`, `cbs`, … |
| `rate` | string | Decimal en cadena (ej. `"0.18"`). |
| `amount` | string | Decimal en cadena (ej. `"7.06"`). |
| `base` | number | Base reducida (reforma IBS/CBS). |
| `metadata` | object | Libre (ej. `{ cst: "00" }`). |

### PaymentMethod

Solo `processor`, `currencyCode`, `transactionStatus` y `totalBill` se validan estrictamente. El resto pasa de largo. Los payloads reales de XMART suelen incluir:

| Campo | Tipo | Notas |
|---|---|---|
| `processor` | string | Requerido. Ejemplos: `CREDIT_CARD`, `Kushki`, `Efectivo`. |
| `currencyCode` | string | Requerido. |
| `transactionStatus` | string | Requerido. Ejemplos: `APPROVED`, `PENDING`, `DECLINED`. |
| `totalBill` | number | Requerido. Monto cobrado con este método. |
| `paymentMethodCode` | string | Código interno del método. |
| `transactionType` | string | Ej. `credit`, `debit`. |
| `transactionId` | string | ID de transacción del adquirente. |
| `tid`, `mid` | string \| null | Identificadores de terminal / comercio. |
| `authorizationCode` | string | Código de autorización. |
| `voucher` | string \| null | Número de voucher. |
| `referenceNumber` | string \| null | Referencia del adquirente. |
| `exactPayment` | boolean | Si se entregó el monto exacto. |
| `customerCashAmount` | string \| number | Efectivo entregado. |
| `acquirer` | object | `{ code, name }`. |
| `card` | object \| null | Datos de tarjeta (mask, BIN, últimos cuatro, marca, titular). |
| `transactionDate` | object | `{ date, timeZoneName, timeZoneType }`. |
| `additionalInfo` | object | Metadata específica del procesador. |

### Códigos de estado

| Estado | Significado |
|---|---|
| `201 Created` | Nueva orden aceptada. |
| `200 OK` | Replay idempotente — ya existe una orden con ese `orderId`. La respuesta incluye `_idempotent: true`. |
| `400 Bad Request` | Falló la validación de schema (campo requerido faltante, tipo incorrecto). |
| `401 Unauthorized` | API key faltante o inválida. |
| `403 Forbidden` | La API key no tiene el scope `orders:write` o el tenant no coincide. |
| `404 Not Found` | `store.code` no resuelve a una tienda conocida. |
| `422 Unprocessable Entity` | El día operativo está cerrado o la tienda está inactiva. |
