---
title: "Consultar una solicitud fiscal"
api: "GET /api/v1/external/fiscal/numbering/{fiscalRequestId}"
description: "Trae el estado actual de una solicitud de numeración por su identificador — incluido el veredicto del ente cuando ya llegó."
---

Devuelve **el mismo contrato** que [`POST /numbering`](/es/api-reference/fiscal-documents),
con el estado actualizado. Lo que cambia entre una llamada y otra es
`documentStatus`: nace en `PENDING` y pasa a `AUTHORIZED` cuando el ente se
pronuncia.

<Info>
  **En la operación diaria no deberías necesitarlo.** Los identificadores ya te
  llegan en `data.fiscalRepresentation` de los eventos de la orden, y el veredicto
  del ente en `lastKnown.fiscal.status`. Este endpoint existe para cuando el camino
  normal no alcanza: perdiste la respuesta síncrona por un corte de red, o querés
  confirmar el estado sin esperar el evento.
</Info>

## Autenticación

| | |
|---|---|
| Header | `x-api-key: pk_live_…` |
| Scope | `fiscal:write` |

Es el **mismo scope que para emitir**, a propósito: quien puede numerar puede
consultar lo que numeró. No hay un scope de solo lectura que dé menos.

El *tenant* sale de la clave, nunca del request. Una solicitud de otra cuenta
devuelve `404`, igual que una que no existe — no se distingue una cosa de la otra
para no filtrar qué identificadores son reales.

## Parámetros de ruta

<ParamField path="fiscalRequestId" type="string" required>
  El `fiscalRequestId` que devolvió la numeración. Es un UUID.
</ParamField>

## Errores

| Código | Cuándo |
|---|---|
| `401` | La API key falta, no existe o está revocada |
| `403` | La key no tiene el scope `fiscal:write` |
| `404` | El `fiscalRequestId` no existe **o pertenece a otra cuenta** |
