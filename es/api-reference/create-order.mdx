Crea una orden en Fire con el cuerpo en **formato Fire**: el mismo de
[Inyectar orden](/es/api-reference/orders), sin cambios. Fire no lo traduce: lo valida y crea la
orden directamente.

Esta es la **versión 1**. Si tu sistema envía las órdenes con la estructura de caja y kiosco o con
la de agregadores, usa [Crear orden (v2)](/es/api-reference/create-order-v2). Las dos versiones
están vigentes y terminan en el mismo lugar: mismas validaciones, misma respuesta.

Una vez creada, la orden sigue el mismo ciclo que cualquier orden de Fire: impuestos, día de
negocio, documento fiscal y [eventos](/es/events/overview).

## Autenticación

<ParamField header="x-api-key" type="string" required>
  Tu API key de Fire con scope `orders:write`. También se acepta `Authorization: Bearer <api_key>`.
  La key **debe estar asociada a tu cuenta y a un vendor**. No hace falta enviar el header `account`.
</ParamField>

## Cuerpo

El cuerpo es el de [Inyectar orden](/es/api-reference/orders), en formato Fire (camelCase, con
precios y totales). Los campos mínimos son:

<ParamField body="orderId" type="string" required>Identificador de la orden en tu sistema.</ParamField>
<ParamField body="orderCode" type="string" required>
  Código único de la orden. Si ya existe una orden con ese código para tu vendor, la respuesta es `409`.
</ParamField>
<ParamField body="accountId" type="number" required>Cuenta de la orden.</ParamField>
<ParamField body="createdAt" type="string" required>Fecha de la venta.</ParamField>
<ParamField body="selectedShippingMethod" type="string" required>`delivery` o `pickup`.</ParamField>
<ParamField body="client" type="object" required>Cliente: `uid`, `name`, `lastName`.</ParamField>
<ParamField body="store" type="object" required>Tienda: `id`, `code`, `vendorId`.</ParamField>
<ParamField body="order" type="object" required>`products[]` con al menos un producto.</ParamField>
<ParamField body="payments" type="object" required>
  `totals[]` y `paymentMethods[]`, con al menos un elemento cada uno. El `transactionStatus` de los
  pagos decide si la orden queda cerrada (`APPROVED`) o abierta, pendiente de cobro (`PENDING`).
</ParamField>

## Respuesta

<ResponseField name="success" type="boolean">`true` cuando la orden se creó.</ResponseField>

<ResponseField name="data" type="object">
  <Expandable title="data">
    <ResponseField name="id" type="string">ID de la orden en Fire. Úsalo para consultarla, actualizarla o anularla.</ResponseField>
    <ResponseField name="external_order_id" type="string">El `orderId` que enviaste.</ResponseField>
    <ResponseField name="status" type="string">`COMPLETED` u `OPEN`.</ResponseField>
    <ResponseField name="payment_status" type="string">`SUCCEEDED` o `PENDING`.</ResponseField>
    <ResponseField name="business_day_date" type="string">Día de negocio de la tienda, `YYYY-MM-DD`.</ResponseField>
    <ResponseField name="created_at" type="string">Fecha de creación en Fire (ISO 8601).</ResponseField>
  </Expandable>
</ResponseField>

## Errores

| HTTP | `error` / `code` | Cuándo |
|---|---|---|
| `400` | `VALIDATION_ERROR` | Falta `orderCode` o el cuerpo no tiene el formato Fire |
| `400` | `BUSINESS_ERROR` | Tienda inactiva, día de negocio cerrado, o la orden no cumple una regla de validación activada para tu vendor (`ORDER_INVARIANT_VIOLATION`) |
| `404` | `NOT_FOUND` | La tienda no existe |
| `401` | `UNAUTHORIZED` | API key inválida, vencida o revocada |
| `403` | `FORBIDDEN` | API key sin scope `orders:write` o no asociada a tu cuenta |
| `409` | `CONFLICT` / `DUPLICATE_ORDER` | La orden ya existía para tu vendor. `data` trae `id`, `externalOrderId` y `status` de la existente |

<Info>
  Toda petición queda registrada en Fire con su cuerpo y el motivo del rechazo, también las
  rechazadas. Si reintentas una orden que ya se creó, la respuesta es `409` y no se duplica.
</Info>
