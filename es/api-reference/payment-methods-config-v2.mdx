---
title: "Configuración de métodos de pago (v2)"
api: "GET https://api.fire.rest/api/v2/external/payment-methods/config"
description: "Lee la configuración de métodos de pago del vendor de tu API key, resuelta por tienda: qué métodos hay, dónde cobra cada uno y con qué valores."
authMethod: "bearer"
---

Devuelve la configuración de pagos que Fire tiene cargada para el vendor de tu API key: el
catálogo de métodos, y por cada tienda dónde cobra cada método y con qué valores.

Sin filtros trae todas las tiendas del vendor, paginadas. Con `storeId` o `storeCode`, una sola.

<Warning>
  **La respuesta incluye los valores de configuración, también los marcados como secretos**
  (llaves de comercio, credenciales de datáfono). Trata esta respuesta como material sensible:
  no la registres en logs, no la caches en el navegador y no la reenvíes a terceros.
</Warning>

<Info>
  Esta es la v2. La [v1](/es/api-reference/payment-methods-config) devuelve país → vendor →
  métodos con un `enabled` y **sigue disponible, sin fecha de baja**. La v2 cambia la fuente de
  los datos y agrega los niveles de tienda, canal, fulfillment y terminal.
</Info>

## Autenticación

<ParamField header="x-api-key" type="string" required>
  Tu API key de Fire con el scope `payment-methods:read`. La key **debe ser vendor-scoped**
  (binding account + vendor) — las keys sin `vendorId` se rechazan con `403`. El account y el
  vendor se resuelven desde la key: no se aceptan como query params.
</ParamField>

## Parámetros

<ParamField query="storeId" type="string">
  UUID de la tienda en Fire. Excluyente con `storeCode`: mandar los dos devuelve `400`.
</ParamField>

<ParamField query="storeCode" type="string">
  El código externo de la tienda (`EXTERNAL CODE` en el backoffice). Es el identificador que
  probablemente ya tengas en tu propio maestro. No es ambiguo porque la API key fija el vendor.
</ParamField>

<ParamField query="channel" type="string">
  Acota `availability` a un canal (por ejemplo `KIOSK`). Se compara en mayúsculas. Las tiendas
  que se quedan sin combinaciones para ese canal siguen apareciendo, sin métodos.
</ParamField>

<ParamField query="page" type="integer" default="1">
  Página de `stores`.
</ParamField>

<ParamField query="size" type="integer" default="20">
  Tiendas por página. Máximo `100`.
</ParamField>

## Petición

<RequestExample>
```http Todo el vendor
GET https://api.fire.rest/api/v2/external/payment-methods/config
x-api-key: <tu_api_key>
```

```http Una tienda
GET https://api.fire.rest/api/v2/external/payment-methods/config?storeCode=K008
x-api-key: <tu_api_key>
```
</RequestExample>

## Cómo leer la respuesta

**Para saber si mostrar un método en una tienda**, mirá `charging`. Es `true` cuando el método
está activo en la cuenta y cobra en al menos una combinación de esa tienda.

**Para saber en qué canal y fulfillment cobra**, mirá `availability`. Una entrada con
`enabled: false` significa "está configurada acá, pero apagada ahora" —por ejemplo, el proveedor
se cayó—. Es distinto de que no aparezca: lo que no aparece no se ofrece en esa tienda.

**Antes de intentar cobrar**, mirá `missingRequiredKeys`. Si trae algo, faltan datos obligatorios
y el cobro va a fallar del lado del proveedor.

**`devices` casi siempre viene vacío.** Aparece cuando un terminal puntual tiene una excepción
—se rompió el datáfono de un kiosco y se apagó solo ese equipo, sin tocar los demás del local—.
Si tu integración no distingue terminales, podés ignorarlo: el nivel de tienda es la respuesta
correcta para un canal de venta.

## Notas

- Un vendor pertenece a un país, pero sus tiendas se leen por el país que cada una tiene cargado.
  Por eso `methods` puede traer más de un país, y por eso **el `code` de un método no alcanza para
  identificarlo**: dos países pueden definir el mismo código con `id` distinto.
- `fulfillmentCode` se devuelve tal como está guardado, sin normalizar contra el catálogo global.
- Los métodos con `active: false` viajan igual, para que puedas mostrarlos como "no disponible" o
  esconderlos — es tu decisión.
- Pedir una tienda que no pertenece al vendor de tu key devuelve `404`, no `403`.
