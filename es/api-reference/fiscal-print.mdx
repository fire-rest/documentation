<Warning>
  **API de partner.** Este endpoint está pensado para integradores de plataforma. Los clientes estándar de Fire no tienen acceso directo — contactá a tu account manager si necesitás esta integración.
</Warning>

Devuelve el contexto fiscal consolidado de una orden específica — los datos que tu point-of-sale o backoffice renderizaría en un recibo/factura impreso o digital. Expone:

- **Contexto del emisor** — entidad legal, gov ID, info de tienda, inscripción estatal
- **Referencias fiscales por país** — chave de acesso, CUFE, clave de acceso, CAE, folio, etc., según país
- **Contexto del comprador** — destinatario, con flag de anónimo/consumidor final
- **Resumen de la orden** — código, status, día de negocio

Endpoint solo lectura. Sin side effects.

## Autenticación

<ParamField header="x-api-key" type="string" required>
  Tu API key de Fire con scope `orders:read`. Vendor-scoped: la API key debe pertenecer al mismo vendor dueño de la tienda/orden.
</ParamField>

## Path parameters

<ParamField path="orderId" type="string" required>
  UUID interno de la orden en Fire. Coincide con `data.orderId` en el evento [`order.completed`](/es/events/order-completed) de esta orden.
</ParamField>

## Query parameters

<ParamField query="vendorId" type="string" deprecated>
  **Deprecado — ya no es necesario.** El vendor se resuelve desde tu API key (vendor-scoped). Se sigue aceptando por compatibilidad durante una ventana de deprecación: si lo envías, debe coincidir con el vendor de tu API key o Fire responde `403`. Quítalo de tus requests.
</ParamField>

<RequestExample>
```http
GET https://api.fire.rest/v1/orders/21ec1f6c-c301-4528-b999-7836c1d21c6c/fiscal-print
x-api-key: <tu_api_key>
Accept: application/json
```
</RequestExample>

## Respuesta

<ResponseField name="fiscal" type="object">
  Referencias fiscales comunes del documento, sin importar el país.

  <Expandable title="fiscal">
    <ResponseField name="countryCode" type="string">
      Código de país ISO 3166-1 alpha-2: `BR`, `CO`, `EC`, `CL`, `AR`, `VE`.
    </ResponseField>
    <ResponseField name="documentType" type="string">
      Tipo de documento específico por país — p. ej. `nfce`, `nfe`, `factura_electronica`, `dte`, `factura_a`.
    </ResponseField>
    <ResponseField name="documentNumber" type="string | null">
      Número secuencial del documento asignado por la autoridad fiscal/proveedor.
    </ResponseField>
    <ResponseField name="authorizationProtocol" type="string | null">
      Protocolo de autorización de la autoridad tributaria (SEFAZ para BR, DIAN para CO, SRI para EC, SII para CL, AFIP para AR, SENIAT para VE). `null` hasta que el documento sea autorizado.
    </ResponseField>
    <ResponseField name="authorizedAt" type="string | null">
      Timestamp ISO 8601 UTC de cuándo la autoridad estampó la autorización.
    </ResponseField>
    <ResponseField name="pdfUrl" type="string | null">
      URL para obtener el PDF renderizado (DANFE para BR NF-e, DANFCE para BR NFC-e, equivalentes específicos por país en otros). Puede ser efímera en producción — descarga y persiste al recibir.
    </ResponseField>
    <ResponseField name="xmlUrl" type="string | null">
      URL para obtener el XML canónico de la autoridad.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="countryData" type="object">
  Referencias del documento específicas por país. La forma varía según `fiscal.countryCode`. Ejemplos:
  - **BR**: `chaveAcesso` (44 dígitos), `serie`, `serialNumber`
  - **CO**: `cufe`, `prefijo`, `numeroDian`
  - **EC**: `claveAcceso` (49 dígitos), `numeroAutorizacion`, `ambiente`
  - **CL**: `folio`, `ted`, `tipoDte`, `trackId`
  - **AR**: `cae`, `fechaVtoCae`, `puntoVenta`, `numeroComprobante`, `tipoComprobante`
  - **VE**: `numeroControl`, `numeroFactura`, `rifEmisor`
</ResponseField>

    <ResponseField name="govIdNumber" type="string | null">Formato específico por país.</ResponseField>

## Patrones comunes

- **Fetch en tiempo de impresión.** Llama este endpoint al momento de imprimir/renderizar y persiste la respuesta si necesitas artefactos durables — `pdfUrl` y `xmlUrl` pueden ser URLs firmadas que expiran.
- **Flag de consumidor final.** Siempre revisa `buyer.isFinalConsumer` antes de renderizar detalles del comprador. Para consumidores anónimos en BR, `govIdNumber` es `"00000000000"` y otros campos del comprador son `null`.
- **UI específica por país.** Usa `fiscal.countryCode` para despachar al template de renderizado correcto — DANFCE para BR NFC-e, estilo DIAN para CO, SRI para EC, etc.
