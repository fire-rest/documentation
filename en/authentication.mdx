title: "Authentication"

Fire uses two mechanisms for authentication: a login flow to obtain a Bearer token for API calls, and a signature-based mechanism to verify incoming webhook events.

## API authentication

Calling the Fire API requires two credentials on every request:

| Header | Value |
|---|---|
| `x-api-key` | Your Fire API key |
| `Authorization` | `Bearer <access_token>` |

The `x-api-key` identifies your integration. The Bearer token proves your session is authenticated. You obtain the token by calling the login endpoint.

### Step 1 — Get an access token

Call [`POST /auth/login`](/en/api-reference/login) with your API key in the header and your credentials in the body:

```http
POST https://api.fire.rest/v1/auth/login
x-api-key: <your_api_key>
Content-Type: application/json

{
  "username": "<your_username>",
  "password": "<your_password>"
}
```

The response returns an access token and its lifetime:

```json
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "expiresIn": 3600
}
```

### Step 2 — Use the token in every request

Include both headers in all subsequent API calls:

```http
POST https://api.fire.rest/v1/orders
x-api-key: <your_api_key>
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
Content-Type: application/json
```

<Note>
  Tokens expire after `expiresIn` seconds. Re-authenticate before expiry to avoid `401` errors on in-flight requests.
</Note>

### Where to get your credentials

API keys and account credentials are managed from the Fire dashboard under **Settings → API Keys**. Contact your Fire account team if you do not have access.

## Webhook signature verification

When Fire sends an event to your endpoint, it signs the request so you can verify it came from Fire and was not tampered with.

<Warning>
  Always verify the signature before processing an event. Skipping this step exposes your endpoint to spoofed requests.
</Warning>

### Verification steps

<Steps>
  <Step title="Extract the signature header">
    Fire includes a signature in the `X-Fire-Signature` request header.
  </Step>
  <Step title="Compute the expected signature">
    Compute an HMAC-SHA256 of the raw request body using your webhook secret as the key.
  </Step>
  <Step title="Compare signatures">
    Compare the computed signature with the value in the header using a constant-time comparison. If they match, the request is authentic.
  </Step>
</Steps>

```js
const crypto = require("crypto");

function verifySignature(rawBody, signature, secret) {
  const expected = crypto
    .createHmac("sha256", secret)
    .update(rawBody)
    .digest("hex");
  return crypto.timingSafeEqual(
    Buffer.from(expected),
    Buffer.from(signature)
  );
}
```

Your webhook secret is configured when you register your endpoint in the Fire dashboard under **Settings → Endpoints**.
