This guide walks you through the minimum steps to have a working integration with Fire: receiving publication events and injecting orders.

## Prerequisites

- API credentials from the Fire dashboard
- A publicly accessible HTTPS endpoint on your side

## Step 1: Register your webhook endpoint

In the Fire dashboard, go to **Settings → Endpoints** and add your URL.

Fire will send all events (store, menu, product updates and order status changes) to this URL via HTTP POST.

<Tip>
  During development you can use a tool like [ngrok](https://ngrok.com) to expose a local server to the internet.
</Tip>

## Step 2: Fetch your sales channels

If your integration publishes menus to aggregators or injects orders, you need to map Fire channel IDs to your aggregator identifiers.

```http
GET /v1/sales-channels
Authorization: Bearer <your_api_key>
```

Store the channel list and use it to resolve the correct channel when handling events and orders.

See [Sales channels](/en/configuration/sales-channels) for the full mapping guide.

## Step 3: Handle publication events

Your endpoint will receive `POST` requests from Fire when a store, menu, or product needs to be published.

```json
{
  "event": "menu.updated",
  "data": {
    "store_id": "store_abc123",
    "channels": ["channel_uber", "channel_rappi"],
    "menu": { }
  }
}
```

Act on each event however your system needs to — publish to aggregators, sync a billing system or ERP, trigger a workflow, etc. The payload contains everything you need.

See the [Webhook reference](/en/webhook-reference/overview) for the full list of events and payload schemas.

## Step 4: Inject orders

When your system receives an order (from an aggregator or any other source), inject it into Fire using the Orders API.

```http
POST /v1/orders
Authorization: Bearer <your_api_key>
Content-Type: application/json

{
  "channel_id": "channel_uber",
  "external_order_id": "uber_order_xyz",
  ...
}
```

See [Order injection](/en/guides/order-injection) for the complete payload reference.

## Step 5: Handle order status updates

Fire will send `order.status_changed` events to your endpoint as the order progresses. Use them to keep your downstream systems in sync.

See [Order status notifications](/en/guides/order-status) for details.
