</Warning>

`menu.list_ready` is the notify half of [hybrid delivery](/en/hybrid-delivery/overview):
it tells your system a menu is ready for a specific store and channel, without
carrying any catalog data. Call [`GET /v1/menus/{listId}`](/en/hybrid-delivery/get-menu)
with the `listId` from this event to fetch the actual menu.

## Payload

```json
{
  "event": {
    "id": "evt_ghi789",
    "type": "menu.list_ready",
    "executionId": "exec_def456",
    "createdAt": "2025-01-15T14:31:00.000Z"
  },
  "data": {
    "account": "1",
    "country": "EC",
    "groupId": "a3f7c2d1-84be-4e10-9b3a-2c5d6e7f8091",
    "listId": "805-iFood-delivery",
    "storeId": "b3d2a1f0-6e21-4c3a-9f5d-7a8b9c0d1e2f",
    "channelId": "0E049503-85CF-E511-80C6-000D3A3261F3"
  }
}
```

## Fields

### `data`

| Field | Type | Description |
|---|---|---|
| `account` | string | Account identifier |
| `country` | string | ISO 3166-1 alpha-2 country code (e.g. `EC`, `BR`, `CO`) |
| `groupId` | string | UUID that correlates events from the same publication or sync batch |
| `listId` | string | The menu's identifier. Pass it to [`GET /v1/menus/{listId}`](/en/hybrid-delivery/get-menu) to fetch the menu |
| `storeId` | string | Internal store UUID (PK `stores.id`) — same convention as `list.storeId` in [`menu.updated`](/en/webhook-reference/menu-updated) |
| `channelId` | string | Internal sales channel UUID (PK `channels.id`) — same convention as `list.channelId` in [`menu.updated`](/en/webhook-reference/menu-updated) |

## Notes

- This event carries no catalog data. If you need categories, products, or modifier
  groups, call [`GET /v1/menus/{listId}`](/en/hybrid-delivery/get-menu).
- `listId` is the correlation key between this event and the fetch endpoint — same
  identifier used across the menu events (`list.listId` in `menu.updated`).
