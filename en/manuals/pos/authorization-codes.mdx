---
title: "Authorization codes"
description: "Approve from the backoffice the POS operations that move money without a sale, and keep a record of who approved them."
---

Some POS operations move money without a sale: closing a register with a shortage, cancelling an order that was already paid, opening the drawer by hand. If the cashier could do them alone, a shortage could be covered with a cancellation and nobody would notice. That is why the POS asks for a 6-digit code that the manager generates in the backoffice: the operation is approved by someone accountable and recorded under their name.

These codes are different from the linking code, which is used to register a new terminal.

<Note>
  **The minimum you need to know**

  - Each code works for **one thing only**. A **Cash count** code does not open the drawer or close the register.
  - It expires after **3 minutes**, or after **30 minutes** if you choose the long duration.
  - It is used **once**. The **Cancel orders** code opens a panel where the cashier can cancel several orders in a row.
</Note>

## Prerequisites

- Access to the Fire backoffice at **[app.fire.rest](https://app.fire.rest)**, with permissions on the store.
- **Channel - POS** and the cashier's store selected in the header.

## Which code each operation needs

| POS operation | What you choose in the backoffice | What it enables |
|---------------|-----------------------------------|-----------------|
| Start closing the register | **Access → Close register** | Enter the close and count the register |
| Confirm a close with a shortage | **Close with shortage** and the reason | Close that register with the shortage |
| Cash count | **Access → Cash count** | One cash count |
| Cancel orders | **Access → Cancel orders** | The cancellation panel, for one or more orders |
| Open the drawer by hand | **Access → Open drawer** | One drawer opening |

<Info>
  A register close with a shortage needs **two codes**: one to enter the close and another to approve the shortage. The first one is requested before counting, so the cashier does not know whether the register balanced until they finish.
</Info>

## 1. Open Authorization codes

In the side menu, open **Fire POS → Authorization codes**. The **Generate** tab has the form on the left and, on the right, the codes you issued in this session.

<Frame>
  <img src="/images/manuals/pos/authorization-codes/01-generate-tab.png" alt="Generate tab of Authorization codes with the purpose, the duration and the list of issued codes" />
</Frame>

## 2. Choose what the code is for

In **Purpose**, choose one of the two options:

- **Close with shortage**: when the cashier closes the register and the count comes out lower than expected. Also choose the **Discrepancy reason**: it is saved in the register reconciliation and in the audit log.

  <Frame>
    <img src="/images/manuals/pos/authorization-codes/02-shortage-reasons.png" alt="Close with shortage purpose with the list of discrepancy reasons" />
  </Frame>

- **Access**: for everything else. In **What does the cashier need to do?** choose **Cancel orders**, **Close register**, **Cash count** or **Open drawer**.

  <Frame>
    <img src="/images/manuals/pos/authorization-codes/03-access-kinds.png" alt="Access purpose with the list of operations: cancel orders, close register, cash count and open drawer" />
  </Frame>

If the cashier needs two things, generate two codes.

## 3. Choose the duration

In **Duration**, leave **3 minutes** if the cashier is going to enter the code right away. Use **30 minutes** only if it will take them a while to reach that screen.

## 4. Generate the code and read it out to the cashier

Tap **Generate code**. The code appears in **Codes issued in this session**, with the operation, the countdown and a button to copy it.

<Frame>
  <img src="/images/manuals/pos/authorization-codes/04-generated-code.png" alt="6-digit code generated to open the drawer, with the countdown" />
</Frame>

Read the 6 digits out to the cashier. When they enter it in the POS, the operation continues and the code is marked as used.

<Tip>
  If the cashier already completed the operation, you are done.
</Tip>

## Review the history

The **History** tab lists the codes generated in the store. Filter by period and by status.

For each code it shows the date and time, the type, the reason, who generated it, the status and, if it was used, which cashier used it and on which terminal.

<Frame>
  <img src="/images/manuals/pos/authorization-codes/05-history.png" alt="History tab with the generated codes, who issued them, their status and who used them" />
</Frame>

Use it to answer questions such as "who approved this shortage?" or "was the code I generated used?".

## Code rules

- They have 6 digits and are used **only once**.
- They expire after 3 or 30 minutes, depending on the duration you chose.
- They only work for the operation they were generated for, and only in the account where they were generated.
- Every generation and every use is recorded in the audit log, with the manager who generated the code and the cashier who used it.

If the POS rejects a code, the message says why: it does not exist, it was already used, it expired, it is for another operation or it belongs to another account.

## Mistakes that cost money

<Warning>
  **Choosing "Other" as the shortage reason out of habit.** The reason is saved in the register reconciliation. If every shortage says "Other", you cannot tell whether the problem is the change, the count or a payment charged incorrectly.
</Warning>

<Warning>
  **Reading the code out where others can hear it.** Until it expires, anyone who knows it can use it on a terminal of the account. Read it out only to the cashier who asked for it.
</Warning>

<Warning>
  **Generating a 30-minute code when 3 minutes are enough.** A long code that nobody uses stays active for half an hour. Use the long duration only when you need it.
</Warning>

## Frequently asked questions

<AccordionGroup>
  <Accordion title="The POS rejects the code">
    Read the POS message: it says whether the code does not exist, was already used, expired, is for another operation or belongs to another account. In all five cases, generate a new one with the correct operation.
  </Accordion>

  <Accordion title="The code expired before the cashier used it">
    Generate another one. If this happens often, use the 30-minute duration.
  </Accordion>

  <Accordion title="The cashier needs to cancel several orders">
    Generate a single **Access → Cancel orders** code: it opens a panel where the cashier can cancel several orders without asking for another code.
  </Accordion>

  <Accordion title="Who used a code I generated?">
    Open the **History** tab: the **Used by** column shows the cashier and the terminal.
  </Accordion>

  <Accordion title="I generated the code with the wrong purpose">
    It cannot be changed. Generate a new one with the correct purpose; the other one expires on its own.
  </Accordion>
</AccordionGroup>
