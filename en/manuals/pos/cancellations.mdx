---
title: "Cancel an order"
description: "Cancel from the POS an approved order from the last 30 minutes, with the manager's code and the cancellation reason."
---

A charged order the customer no longer wants has to leave sales with its credit note and with the money given back. If it is “fixed” by hand —giving back the cash without canceling the order— the sale still counts and the register comes out short at closing. **Cancel order** cancels the whole order, issues the credit note and records who did it, who authorized it and why.

<Note>
  **The minimum you need to know**

  - Only **Approved** orders created **less than 30 minutes ago** can be canceled.
  - Entering the cancellation requires a manager's code from **Access → Cancel orders**. Each code is good for one cancellation.
  - The cancellation issues a **credit note** and cannot be undone.
  - If the order was paid in cash, the drawer opens so you can give the money back.
</Note>

## Prerequisites

- An open register.
- A manager to generate the code. See [Authorization codes](/en/manuals/pos/authorization-codes).

## 1. Enter the manager's code

Tap your name at the top right to open **Settings** and choose **Cancel order**. Ask the manager for a code from **Access → Cancel orders**, type the 6 digits and tap **Continue**.

<Frame>
  <img src="/images/manuals/pos/cancellations/01-cancel-code.png" alt="Authorization required window with the 6-digit code typed" />
</Frame>

## 2. Choose the order

The list shows the store's orders for the day, with the code, time, customer, total and status. Orders older than 30 minutes appear with **+30 min** and you cannot tap them.

To find an order, type or scan its code in the search box. If an order you just charged does not appear, tap **Refresh**.

<Frame>
  <img src="/images/manuals/pos/cancellations/02-order-list.png" alt="Cancel order list with a recent approved order and others disabled with +30 min" />
</Frame>

## 3. Review the order and choose the reason

Tap the order. The window shows the code, customer, payment method and total. Compare them with what the customer tells you before going on.

<Frame>
  <img src="/images/manuals/pos/cancellations/03-confirm.png" alt="Cancel this order? window with the order details and the cancellation reasons" />
</Frame>

In **Cancellation reason**, choose the category and tap the reason. Some reasons require a note; for the rest it is optional.

<Frame>
  <img src="/images/manuals/pos/cancellations/04-reason-selected.png" alt="Cancellation reason selected and a note typed" />
</Frame>

## 4. Cancel

Tap **Cancel order**. The POS issues the credit note, prints the cancellation receipt and, if the order was paid in cash, opens the drawer so you can give the money back. The window confirms **Order canceled** with the **Refunded** amount.

<Frame>
  <img src="/images/manuals/pos/cancellations/05-canceled.png" alt="Order canceled with the order code and the refunded amount" />
</Frame>

Tap **Done**. To cancel another order, ask for a new code.

<Tip>
  If you see **Order canceled**, you are done: the order no longer counts as a sale.
</Tip>

---

## Cancellation reasons

The reasons and their categories are the ones set up for the country's account, so they change from one country to another. If a reason is missing, ask the Fire team for it. A change to the reasons takes up to 5 minutes to reach the POS.

## Recipes

<AccordionGroup>
  <Accordion title="The customer changes their mind after paying in cash">
    1. Open **Settings → Cancel order** and type the code from **Access → Cancel orders**.
    2. Find the order by its code.
    3. Choose the reason and tap **Cancel order**.
    4. Give back the cash from the drawer, which opens by itself.
  </Accordion>

  <Accordion title="The cashier charged the wrong order">
    1. Cancel the wrongly charged order, with the reason that applies.
    2. Sell the correct order again. See [Sell and charge](/en/manuals/pos/sell-and-charge).
  </Accordion>
</AccordionGroup>

## Mistakes that cost money

<Warning>
  **Giving back the cash without canceling the order.** The sale still counts and the money is no longer in the register: the close comes out with a shortage. Every refund goes through **Cancel order**.
</Warning>

<Warning>
  **Canceling without checking the order.** The cancellation cannot be undone. Check the code, total and payment method before tapping **Cancel order**.
</Warning>

<Warning>
  **Letting the 30 minutes go by.** After that, the order can no longer be canceled from the POS. If the customer asks for the cancellation, do it right away.
</Warning>

## Frequently asked questions

<AccordionGroup>
  <Accordion title="The order appears with “+30 min” and I cannot tap it">
    More than 30 minutes have passed since it was created. It can no longer be canceled from the POS: tell the manager.
  </Accordion>

  <Accordion title="It says “Invalid or expired code”">
    The code was already used, expired, or is for another operation. Ask the manager for a new one from **Access → Cancel orders**.
  </Accordion>

  <Accordion title="It says “The business day is closed”">
    The order belongs to a business day that has already been closed. That cancellation is done from the backoffice.
  </Accordion>

  <Accordion title="It says “The service did not respond”">
    The order is still not canceled. Wait a few seconds and tap **Cancel order** again.
  </Accordion>

  <Accordion title="Can I cancel just one product from the order?">
    No. The cancellation cancels the whole order. If the customer keeps part of it, cancel the order and sell again what they are taking.
  </Accordion>
</AccordionGroup>
