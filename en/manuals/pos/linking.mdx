---
title: "Linking"
description: "Register a device as a store register with a single-use code, or re-pair a register that already existed without losing its history."
---

An unlinked POS doesn't know which store it belongs to: it has no menu, no cashiers and no fiscal numbering. Linking is the step that turns it into one of the store's registers. You do it once per device, with a 6-digit code that the manager generates in the backoffice and that you enter in the POS.

If the device was already a register and the cache was cleared, the device was replaced, or the register was deleted by mistake, you don't need to create a new register: you **re-pair** the same one, and it keeps its name, its history and its fiscal ID.

<Note>
  **The minimum you need to know**

  - You generate the code in **Fire POS → Terminals → Create slot**, and it expires after 30 minutes if nobody uses it.
  - **Pair a new register** creates a new terminal. **Re-pair an existing register** recovers one that already existed.
  - The backoffice and the POS must be on the same environment: a production code doesn't work on staging.
</Note>

## Prerequisites

- Access to the Fire backoffice at **[app.fire.rest](https://app.fire.rest)**, with permissions on the store.
- The device powered on, with internet and a supported browser. See the [terminal requirements](/en/manuals/pos/hardware-requirements).

<Info>
  **FIRE POS is not installed.** It is a web application that opens in the device's browser. Optionally, you can install it as a PWA from the browser itself so it opens full screen.

  This guide uses two applications: the **backoffice**, where you generate the code, and the **POS**, where you enter it.

  | Environment | Backoffice | FIRE POS |
  |---|---|---|
  | **Production** | [app.fire.rest](https://app.fire.rest) | [pos.fire.rest](https://pos.fire.rest) |
  | **Staging** | [stg.app.fire.rest](https://stg.app.fire.rest) | [stg.pos.fire.rest](https://stg.pos.fire.rest) |
</Info>

To print receipts and vouchers, the device also needs the **Fire Agent**. See the [Fire Agent guide](/en/manuals/fire-agent/installation).

## 1. Choose the store

In the backoffice, choose the country and vendor in the selector at the top right, the **Channel - POS** channel and, in the header, the store where the device will work. The register belongs to that store.

<Frame>
  <img src="/images/manuals/pos/linking/01-pick-store.png" alt="Header store selector with Laboratorio Colombia selected" />
</Frame>

## 2. Create the slot

Open **Fire POS → Terminals** and tap **Create slot**.

<Frame>
  <img src="/images/manuals/pos/linking/02-create-slot-button.png" alt="Terminals page with the Create slot button" />
</Frame>

In **What do you want to do**, choose **Pair a new register**. **Validity (minutes)** stays at 30, which is enough time to walk to the device; you can choose between 1 and 60.

<Frame>
  <img src="/images/manuals/pos/linking/03-create-slot-modal.png" alt="Create linking slot dialog with the target store, the mode and the validity" />
</Frame>

Tap **Generate code**. The dialog shows the 6-digit code, a button to copy it and when it expires.

<Frame>
  <img src="/images/manuals/pos/linking/05-slot-code.png" alt="6-digit linking code with the Copy button and the expiration time" />
</Frame>

While nobody uses it, the code appears in the **Pending slots** tab.

## 3. Enter the code in the POS

Open the POS in the device's browser. When it is not linked, it shows **Link terminal** and a numeric keypad.

<Frame>
  <img src="/images/manuals/pos/linking/06-open-pos-app.png" alt="POS Link terminal screen with the numeric keypad" />
</Frame>

Type the 6 digits with the on-screen keypad, with the physical keyboard or with **Paste code**. On the sixth digit, the POS links itself.

<Frame>
  <img src="/images/manuals/pos/linking/07-type-code.png" alt="Linking keypad with five digits entered" />
</Frame>

## 4. Set up the printer

Right after linking, the POS offers to choose the thermal printer. If the Fire Agent is installed, choose the printer, tap **Print test** and **Save**. If you haven't installed it yet, tap **Skip for now**: you can do it later from the menu.

<Frame>
  <img src="/images/manuals/pos/linking/08-printer-setup.png" alt="POS printer setup dialog, without the local agent installed" />
</Frame>

## 5. Check the register

The POS shows the cashier sign-in, with the register name at the top right.

<Frame>
  <img src="/images/manuals/pos/linking/09-cashier-signin.png" alt="Cashier sign-in with the name of the newly linked register" />
</Frame>

In the backoffice, the register appears in **Terminals → Active** with a name like **CO-K000-POS-15**: country, store code, type and number.

<Frame>
  <img src="/images/manuals/pos/linking/10-terminal-active.png" alt="Card of the newly linked register in the active terminals list" />
</Frame>

<Tip>
  If the POS already shows the cashier list, you're done. To sign in with a cashier, see [Start a shift](/en/manuals/pos/start-shift).
</Tip>

## Re-pair an existing register

Use it when the device was already a register and is no longer linked: the browser cache was cleared, the device was replaced, or the register was deleted by mistake. The register keeps its name, its history and its fiscal ID.

1. In **Create slot**, choose **Re-pair an existing register**.
2. In **Register to re-pair**, choose the register.
3. Tap **Generate code** and enter it in the POS, as with a new link.

<Frame>
  <img src="/images/manuals/pos/linking/04-repair-mode.png" alt="Create slot dialog in re-pair mode, with the chosen register and the register-in-operation warning" />
</Frame>

If the register is operating, you can only re-pair it from the same device it is on today. To move it to another device, revoke it first in [Terminal administration](/en/manuals/pos/terminal-admin). Your user is recorded in the audit log as the one who authorized the re-pairing.

## Mistakes that cost money

<Warning>
  **Pairing a new register when you needed to re-pair.** The previous register is left with its shift open, the cashier can't open another one, and the new register starts its own fiscal numbering. If the device was already a register, re-pair it.
</Warning>

<Warning>
  **Mixing environments.** A code generated in the staging backoffice doesn't work on the production POS, or the other way around: the POS rejects it as an invalid code.
</Warning>

## Frequently asked questions

<AccordionGroup>
  <Accordion title="The POS says the code is invalid">
    Check that it hasn't expired (30 minutes by default), that it hasn't been used, and that the backoffice and the POS are on the same environment. If needed, generate another one.
  </Accordion>

  <Accordion title="What is the new register called?">
    The system sets the name: country, store code, type and number, like **CO-K000-POS-15**. You don't choose it.
  </Accordion>

  <Accordion title="I cleared the browser cache and the POS asks me to link it again">
    Re-pair the same register: in **Create slot**, choose **Re-pair an existing register** and the register. That way it keeps its history and its numbering.
  </Accordion>

  <Accordion title="The POS can't find the printer">
    Install and open the Fire Agent on the device, and tap **Retry** in the printer setup.
  </Accordion>
</AccordionGroup>
