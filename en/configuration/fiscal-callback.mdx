---
title: "Fiscal callback"
description: "How to report the result of your local fiscal integration (DIAN, SRI, SII, AFIP, SENIAT) back to Fire."
---

For every country except Brazil, **your system is responsible for the local fiscal integration**: emitting the legal document with the country's tax authority and getting back the authorization. Once you have that result, you report it to Fire through a single multi-country callback so Fire can persist the fiscal document, log the event, and close the loop on the order.

<Note>
  Brazil is different: Fire integrates with PlugNotas to emit NFC-e / NF-e directly, so Fire emits `fiscal.authorized.br` / `fiscal.cancelled.br` to your system. You do **not** call this endpoint for BR. See [How events work](/en/concepts/events).
</Note>

## When to call it

You call the fiscal callback in these moments:

| Moment | `eventType` |
|---|---|
| Local authority authorized the document | `authorized` |
| Local authority cancelled the document | `cancelled` |
| Local authority rejected or denied the document | `rejected` or `denied` |
| Your fiscal integration crashed and you want to record it | `error` |

## Endpoint

```http
POST https://api.fire.rest/v1/webhooks/fiscal/callback
x-api-key: <key with webhooks:fiscal scope>
Content-Type: application/json
```

The API key must carry the `webhooks:fiscal` scope and be vendor-scoped. See [API keys and scopes](/en/configuration/api-keys#webhooks-fiscal) for how to create it.

## Request body — common envelope

```json
{
  "countryCode":     "CO" | "EC" | "CL" | "AR" | "VE",
  "eventType":       "authorized" | "cancelled" | "rejected" | "denied" | "error",
  "providerEventId": "evt-xyz-1001",
  "occurredAt":      "2025-01-15T14:30:05.000Z",
  "orderId":         "<Fire order UUID>",
  "eventId":         "<event.id from the order envelope Fire emitted>",
  "document":        { /* country-specific — see sections below */ },
  "error":           { "code": "string", "message": "string" }
}
```

| Field | Required | Description |
|---|---|---|
| `countryCode` | Always | ISO country code. Drives the validation of the `document` block. |
| `eventType` | Always | What happened in the local authority. |
| `providerEventId` | Always | Idempotency key. Fire indexes `(provider_code, providerEventId)` UNIQUE — sending the same id twice is safe. |
| `occurredAt` | Always | When the event happened in **your** system, ISO 8601 UTC. Not when Fire received it. |
| `orderId` | Always | The Fire order UUID this event belongs to (`data.orderId` from the original `order.completed` envelope). |
| `eventId` | Always | The `event.id` Fire sent you in the order envelope. Used to correlate the callback with the specific run that triggered your local emission. |
| `document` | When `eventType` ∈ {authorized, cancelled} | Country-specific fiscal data. Schema differs per `countryCode`. |
| `error` | When `eventType` ∈ {rejected, denied, error} | Reason for the failure. |

## Response

```json
{
  "received":     true,
  "receiptId":    "rcpt_abc123",
  "outcome":      "updated",
  "documentId":   "doc_xyz789",
  "processingMs": 42
}
```

| Field | Meaning |
|---|---|
| `received` | Always `true` on `2xx`. Confirms Fire accepted the payload. |
| `receiptId` | Fire-side identifier of this callback delivery. Useful for audit trails. |
| `outcome` | `created`, `updated`, `idempotent`, `regression`, or `duplicate`. See [Idempotency and concurrency](#idempotency-and-concurrency) below. |
| `documentId` | Fire's internal id of the persisted `fiscal_document` row. |
| `processingMs` | Server-side processing time in milliseconds. |

### HTTP status codes

| Status | Meaning |
|---|---|
| `200 OK` | Callback accepted and processed (including idempotent re-deliveries). |
| `400 Bad Request` | Body did not pass schema validation. The response includes the offending fields. |
| `401 Unauthorized` | API key missing or invalid. |
| `403 Forbidden` | API key is missing the `webhooks:fiscal` scope or `orderId` does not belong to the same vendor. |
| `5xx` | Transient Fire-side error. Retry with backoff. |

## Idempotency and concurrency

Two safety nets are built in:

1. **`providerEventId` deduplication.** Fire enforces a UNIQUE index on `(provider_code, providerEventId)`. If you replay the same callback (network blip, retry from your queue) Fire returns `outcome="duplicate"` instead of double-applying it.
2. **Optimistic state transitions.** If two callbacks for the same order race each other (e.g. authorized vs cancelled), Fire applies the second one only if its target state is reachable from the current state. Otherwise it returns `outcome="regression"` and leaves the document unchanged.

For the cleanest semantics, treat `providerEventId` as a **stable hash** of the local authority's event identifier — never randomize it on retries.

## Autocreation of the fiscal document

Your system is the source of truth for fiscal data outside Brazil. The first time Fire receives a callback for a given `orderId` with no pre-existing fiscal document, Fire **autocreates** the row from your payload. Subsequent callbacks update it.

This means you do not need to call any "create document" endpoint before sending your first authorization callback — the callback itself is the create.

## Worked example — Colombia

```bash
curl -X POST https://api.fire.rest/v1/webhooks/fiscal/callback \
  -H "x-api-key: pk_live_a1b2c3…" \
  -H "Content-Type: application/json" \
  -d '{
    "countryCode":     "CO",
    "eventType":       "authorized",
    "providerEventId": "evt-co-1001",
    "occurredAt":      "2025-01-15T14:30:05.000Z",
    "orderId":         "df8cdf6a-62c5-4daf-b35f-b6e7bb1b98b3",
    "eventId":         "2167a211-e757-4185-abb4-59474e275019",
    "document": {
      "docType":      "invoice",
      "docSubtype":   "factura",
      "totalAmount":  100.00,
      "taxAmount":    19.00,
      "currencyCode": "COP",
      "pdfUrl":       "https://files.your-system.com/invoice.pdf",
      "xmlUrl":       "https://files.your-system.com/invoice.xml",
      "emittedAt":    "2025-01-15T14:30:05.000Z",
      "cufe":         "5fa31abc1234567890def1234567890abcdef1234567890",
      "prefijo":      "FE-CO",
      "numeroDian":   "FE-CO-1001",
      "qrCode":       "https://catalogo-vpfe.dian.gov.co/document/searchqr?documentkey=5fa31abc…"
    }
  }'
```

Successful response:

```json
{
  "received":     true,
  "receiptId":    "rcpt_2024_01_15_co_1001",
  "outcome":      "created",
  "documentId":   "doc_co_1001",
  "processingMs": 38
}
```
