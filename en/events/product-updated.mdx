---

<Note>
  **Limited availability.** This event is being rolled out and is enabled per account. Ask your Fire contact whether it already applies to yours.
</Note>

<Warning>
  This is the **Integration Flows** `product.updated` event, documented on this page. It is **not** the aggregator-integration webhook with the same name described in [Webhook reference → `product.updated`](/en/webhook-reference/product-updated): that is the format of existing integrations, has a different shape, and does not change. This event also covers what there are [`product.availability_changed`](/en/webhook-reference/product-availability-changed) and [`product.price_updated`](/en/webhook-reference/product-price-updated), with one difference: a change made in the prices and availability editor travels **only for the edited terna**, not for every store where the product appears.
</Warning>

`product.updated` is a **patch**: it carries only the products that changed and, for each one, only the block that changed (`availability` or `pricing`). Whatever is missing did not change. Apply it on top of the menu you already have for each terna, the one you got in [`menu.updated`](/en/events/menu-updated).

It fires **once per action and per store**: turning a product off in a store is one event, with every terna (**channel × fulfillment type**) of that store where it applies. A change in the prices and availability editor carries a single terna: the edited one.

## Trigger condition

| Action | `changes` | What each product carries |
|---|---|---|
| Turning products off in a store (Out-of-stock screen) | `["availability"]` | `availability` with `OUT_OF_STOCK` and its expiry |
| Turning them back on manually, or the turn-off expires | `["availability"]` | `availability` with `AVAILABLE` |
| Enabling or hiding a product in the prices and availability editor | `["availability"]` | `availability` with `AVAILABLE` or `HIDDEN`, **only for the edited terna** |
| Changing prices in the prices and availability editor | `["price"]` | `pricing`, only the parts that change, **only for the edited terna** |

- **From Out-of-stock**, every terna of the store where the product **is sold** travels: a channel that does not have it on its menu does not receive the change. If no terna sells it, nothing is emitted.
- **From the editor**, `targets[0].channels` carries a single terna: the edited one. The other ternas sharing that menu or price list get the change in their next [`menu.updated`](/en/events/menu-updated).
- A price change also emits the [`menu.updated`](/en/events/menu-updated) of that terna, with the same `groupId`.
- A flow limited to some channels receives the event when it touches **at least one** of them — and receives it **whole**, with every terna. Pick yours from `targets[].channels`.

| | |
|---|---|
| Coverage | All countries, on accounts where the event is enabled |
| Unit | One action in one store |
| Action id | `data.groupId` — the same in every event of that action |
| Delivery id | `event.id`, as in every event (the flow execution) |
| Entity | `_meta.triggerEntityId` is the store UUID (`targets[0].store.uid`) |

## `data.*` reference

<ResponseField name="account" type="string">Fire account.</ResponseField>
<ResponseField name="country" type="string">The store's country, 2-letter ISO.</ResponseField>
<ResponseField name="groupId" type="string">UUID of the **action**. A price change shares its `groupId` with the `menu.updated` events it emits.</ResponseField>
<ResponseField name="changes" type="string[]">What changed: `availability` or `price`. New values may appear; ignore the ones you do not know.</ResponseField>

<ResponseField name="targets" type="array">
  Where it applies: one element per store (always one today).

  <Expandable title="targets[]">
    <ResponseField name="store" type="object">The store: the same block as in [`menu.updated`](/en/events/menu-updated#context).</ResponseField>
    <ResponseField name="channels" type="array">
      **Each affected terna**: `{ channel: { uid, code }, fulfillment: { service: { uid, code } }, menuSyncId }`. The change applies to every one in this list; `menuSyncId` is the terna of your copy of the menu.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="products" type="array">
  The products that changed. Each one carries `id` and **only** the block that changed.

  <Expandable title="products[]">
    <ResponseField name="id" type="string">Product id (`products[].id` in the menu).</ResponseField>
    <ResponseField name="availability" type="object">
      With `changes: ["availability"]`. `status`: `AVAILABLE`, `OUT_OF_STOCK` or `HIDDEN`. `outOfStockUntil`: the turn-off's expiry (ISO 8601 UTC), or `null` when it has none or when it is available.
    </ResponseField>
    <ResponseField name="pricing" type="object">
      With `changes: ["price"]`. The same fields as `pricing` in the menu (without `modifierGroupIds` or `recommendationsIds`), but only the ones that change. See [How to apply a price change](#how-to-apply-a-price-change).
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="modifierGroups" type="array">
  **Only on price changes.** The groups cited in `products[].pricing.modifiers`, with the same shape as in the menu, so you know which group is meant.
</ResponseField>

## Availability

| `availability.status` | Meaning | `outOfStockUntil` |
|---|---|---|
| `OUT_OF_STOCK` | Turned off from the Out-of-stock screen | The turn-off's expiry, or `null` if it has none |
| `AVAILABLE` | Turned back on (manually or on expiry) or enabled in the editor | `null` |
| `HIDDEN` | Disabled in the prices and availability editor | `null`, or the expiry of an active turn-off if the product is also turned off |

When turning it back on, **clear the expiry** you had stored: `outOfStockUntil` arrives as `null`.

## How to apply a price change

A price change can touch more products than the edited one, and each carries its own part:

| Who appears | What it carries | Why |
|---|---|---|
| The edited product | `pricing` with `price`, `anchorPrice`, `anchorPricePercentage`, `isTaxInclusive`, `taxRate`, `startingPrice` and `modifiers` | Its price changed. |
| Options of a group where some price changed | Only `pricing.modifiers`, the **complete** list | Its price as an option changed, or that of another option in the same group. |
| Parent products (combos) | Only `pricing.startingPrice` | Their "From" depends on the options. |

- Merge **field by field** over what you already have. Whatever is missing did not change.
- **Lists are replaced whole** (for example, `modifiers`).
- In a price patch, **`anchorPrice: 0` means "no offer"**: remove the struck-through price.
- If a patch cites a group you do not have yet, wait for the `menu.updated` of the same action (same `groupId`): with it everything is consistent again.

## Delivery and order

- **In order per store.** Within a flow, the `product.updated` events of **the same store** are delivered one at a time, in the order they were emitted; different stores move in parallel. There is no guaranteed order between a `product.updated` and a `menu.updated`: order by `event.emittedAt` and, when in doubt, the terna's latest `menu.updated` is the complete truth.
- **Applying it twice leaves the same result**: it carries absolute values (status, price). To deduplicate, use `data.groupId` + `data.changes` + `targets[0].store.uid` (and, for editor events, `targets[0].channels[0].menuSyncId`); `event.id` identifies the delivery, not the fact (see [Idempotency on your side](/en/events/delivery#idempotency-on-your-side)).
- **If your system processes asynchronously**, you can report the result per product with the [product result callback](/en/api-reference/catalog-product-result).

## Example handler

```js
async function onProductUpdated(event, data) {
  for (const target of data.targets) {
    for (const terna of target.channels) {
      const menu = await db.menus.get(terna.menuSyncId);
      if (!menu) continue; // you have not received that terna's menu yet

      for (const patch of data.products) {
        const product = menu.products.find((p) => p.id === patch.id);
        if (!product) continue;
        if (patch.availability) Object.assign(product.availability, patch.availability);
        if (patch.pricing) Object.assign(product.pricing, patch.pricing); // lists are replaced whole
      }
      await db.menus.save(terna.menuSyncId, menu);
    }
  }
}
```

## Common mistakes

- **It is not the whole product.** A product in the event carries only the block that changed; do not delete what is missing.
- **Apply it in every terna in `targets[].channels`.** The same turn-off applies to each listed channel and fulfillment type.
- **`HIDDEN` is not `OUT_OF_STOCK`.** Hidden by menu decision vs temporarily out of stock.
- **When turning it back on, clear `outOfStockUntil`.** Otherwise the old expiry stays stored.
