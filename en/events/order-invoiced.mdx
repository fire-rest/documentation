`order.invoiced` fires once the **country's fiscal authority** authorizes the fiscal document associated with an order — SEFAZ in Brazil, SRI in Ecuador, DIAN in Colombia, AFIP in Argentina, SII in Chile, SENIAT in Venezuela.

This event is **separate from** [`order.completed`](/en/events/order-completed): the order is paid first (`order.completed`), then the document is issued through your fiscal provider, and `order.invoiced` fires only when the authority returns the authorization.

## Trigger condition

Fire emits `order.invoiced` when a fiscal document for the order reaches `authorized`, whether Fire learns it from its native provider integration or from the [fiscal callback](/en/api-reference/fiscal-callback) with `eventType: "authorized"`.

| | |
|---|---|
| Coverage | **All countries** — the country travels in `fiscal.countryCode`, not in the event name |
| Idempotency key | `event.id` |
| Fires more than once | Once per active Integration Flow subscribed to the event; retried on delivery failure |
| Latency relative to `order.completed` | Usually seconds; minutes if the authority is degraded |

## What's in `trigger.data`

The same V4 order snapshot as [`order.completed`](/en/events/order-completed), plus the **`fiscal`** block described below. The order's `status` stays `"COMPLETED"`: a fiscal authorization does not change the order status.

## Where the fiscal totals live

`authority.amounts` are the **document's** amounts as the authority reported them. The order's own aggregates (vBC, vNF, vICMS…) are still in `data.payments.metadata.fiscal`, and per-line classification (NCM, CFOP) in `data.orderLines[n].metadata.fiscal` — same as in `order.completed`.

## Handler example

```js
async function onOrderInvoiced(data) {
  const { orderId, fiscal } = data;
  const doc = fiscal.authority;

  await db.fiscalDocs.upsert({
    where: { providerDocId: doc.providerDocId },
    create: {
      fireOrderId: orderId,
      country: fiscal.countryCode,
      documentType: doc.documentType,
      documentNumber: doc.documentNumber,
      issuedAt: doc.issuedAt,
      // Iterate countryData: the keys depend on the country.
      identifiers: doc.countryData,
      total: doc.amounts.total ?? null,
    },
    update: {},
  });

  // Archive the legal XML — the link may expire.
  const xml = await fetch(doc.xmlUrl).then((r) => r.text());
  await archive.put(`xml/${doc.providerDocId}.xml`, xml);
}
```

## Common pitfalls

- **Read `fiscal.authority.*`, not `fiscal.*`.** The flat fields of v1.2 are gone. The table in [Path changes](#path-changes-from-the-previous-version) maps each one.
- **Do not hour-align on `authorizedAt` in Brazil.** It carries a conventional midnight; use `issuedAt` for time.
- **`history` includes the current document.** Do not count its entries as "previous documents".
- **No event for `rejected` / `denied` / `error`.** Those outcomes are stored but do not fire `order.invoiced`.

## `data.fiscalRepresentation`

Unchanged in v2. It is the **fiscal numbering** the point of sale obtained *before* injecting the order — what was printed at the till — and it is a different block from `fiscal`: `fiscalRepresentation` is what was numbered, `fiscal.authority` is what the authority decided. The field reference is in [`order.completed`](/en/events/order-completed) and in the [v1.2 page](/en/events-v1/order-invoiced#data-fiscalrepresentation).
