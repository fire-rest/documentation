Fire notifies your system of changes in real time via webhooks — HTTP `POST` requests sent to your registered endpoint whenever something relevant happens. You subscribe to the events you care about and act on them however your integration requires.

## Channel events

Channel events notify your system when the sales channel catalog changes. Use them to keep your local channel mapping in sync — channel IDs are required when injecting orders and when processing publication events.

## Event envelope

Every event carries these fields under `event`:

```json
{
  "event": {
    "id": "evt_abc123",
    "type": "event.type",
    "executionId": "exec_abc123",
    "createdAt": "2025-01-15T14:30:00Z"
  },
  "data": {}
}
```

| Field | Type | Description |
|---|---|---|
| `event` | object | Event metadata |
| `event.id` | string | Unique event ID — use for deduplication |
| `event.type` | string | Event type identifier |
| `event.executionId` | string | ID of the publication or sync run that produced this event |
| `event.createdAt` | string | ISO 8601 timestamp when the event was emitted |
| `data` | object | Event-specific payload |

<Note>
  Some events also carry `event.timezone` (the originating account's timezone) in
  addition to the fields above. Check each event's own reference page for its exact
  envelope before relying on a field not listed here.
</Note>

## Delivery

Fire posts each event as `application/json` to the endpoint you configure per
integration from the dashboard (Aggregators → Developer tools → Aggregator
integrations) — you provide the host, and the path is configurable per integration,
for example `https://yourapp.com/webhooks/menu-updated`. Delivery is signed with
HMAC-SHA256 (see [Authentication](/en/authentication)); there's no OAuth handshake on
this path, unlike the API's Bearer token flow.

## Request headers

| Header | Description |
|---|---|
| `Content-Type` | `application/json` |
| `X-Fire-Event` | Event type (e.g. `menu.updated`) |
| `X-Fire-Timestamp` | Unix timestamp (seconds) when Fire signed the request — see [Authentication](/en/authentication) |
| `X-Fire-Signature` | HMAC-SHA256 signature — see [Authentication](/en/authentication) |

## Deduplication

Use the `event.id` field to detect and discard duplicate deliveries. Fire may deliver the same event more than once in case of retries.

## Responding

Return any `2xx` within 10 seconds to acknowledge receipt. Process asynchronously to avoid timeouts.
