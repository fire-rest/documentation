---
title: "order.completed"
description: "Sent when an order is injected into Fire and its payment succeeds. The most common event — most integrations build their main flow around it."
---

Fire fires `order.completed` exactly once per order, the moment Fire records `status="COMPLETED"` and `paymentStatus="SUCCEEDED"`. The payload carries the full V4 Order Snapshot — store, customer, payments, line items, fulfillment — so your handler does not need to call back to Fire to enrich it.

<Note>
  Pending or failed payments **do not** fire this event. If you need to react to those states, subscribe to `order.status_changed` instead.
</Note>

## When it fires

| Trigger | Fires `order.completed`? |
|---|---|
| `POST /v1/orders` succeeds with `status="COMPLETED"` and `paymentStatus="SUCCEEDED"` | ✅ Yes |
| Order is injected with `paymentStatus="PENDING"` | ❌ No |
| Order is later updated to `COMPLETED` after starting as `PENDING` | ✅ Yes (fires on the transition) |
| Order is cancelled before completion | ❌ No (fires `order.cancelled` instead) |

## Envelope

```json
{
  "event": {
    "id":        "evt_2167a211e7574185abb459474e275019",
    "type":      "order.completed",
    "createdAt": "2025-01-15T14:30:00.000Z"
  },
  "data": {
    /* V4 Order Snapshot — see "Data fields" below */
  }
}
```

See [Events](/en/concepts/events) for the envelope contract that wraps every event.

## Data fields

The `data` block is the **V4 Order Snapshot** — a frozen view of the order at the moment of completion.

### Top-level

| Field | Type | Description |
|---|---|---|
| `orderId` | string | Fire's internal UUID for the order. Stable across retries and across all events for this order. |
| `orderCode` | string | Human-readable POS code, e.g. `OC-br-k082-1777566201724`. Empty string when the source did not provide one. |
| `businessDayDate` | string | Business day in `YYYY-MM-DD`. May differ from the calendar date when the store closes after midnight. |
| `externalOrderId` | string | The order ID assigned by your system when you injected the order. |
| `redeemPoints` | boolean | `true` if the order included a loyalty point redemption. |
| `accumulatePoints` | boolean | `true` if the order accumulates loyalty points. |
| `discount` | boolean | `true` if a discount was applied to the order. |
| `createdAt` | string \| null | ISO 8601 UTC — when the order was created at the source POS. |
| `orderComment` | string | Free-form comment from the customer. Empty string when none. |
| `paymentStatus` | string | Always `SUCCEEDED` for this event. |
| `status` | string | Always `COMPLETED` for this event. |
| `metadata` | object | Reserved for future extensions. Always `{}` today. |

### `marketing`

Loyalty and coupon block. `null` when XMART captured no marketing activity.

<Expandable title="marketing properties">

| Field | Type | Description |
|---|---|---|
| `loyalty` | object \| null | Sub-block for points. |
| `loyalty.accumulation` | object | Points the order accumulates: `{ storeCost, marketingCost, totalPoints }` (decimals × 10000). |
| `loyalty.redemption` | object | Points redeemed by the customer. Same shape as `accumulation`. |
| `loyalty.accountBalancePoints` | string | Customer's remaining balance after the order. |
| `coupons` | array | Coupons applied. `[]` when none. Each item: `{ rewardId, name, metadata }`. |

</Expandable>

### `store`

Snapshot of the store at the moment of the order.

<Expandable title="store properties">

| Field | Type | Description |
|---|---|---|
| `uid` | string | Fire's internal `stores.id`. |
| `externalId` | string | External (legacy) ID. |
| `code` | string | Store code, e.g. `BR-SP-001`. |
| `name` | string | Commercial name. |
| `phone` | string | Phone number. |
| `address` | string | Physical address. |
| `locationInfo` | object | Geographic data. See below. |
| `vendor` | object | Brand / operating company. See below. |
| `account` | object | Commercial account. See below. |
| `storeFiscalConfig` | object \| null | Fiscal configuration. See below. |

**`store.locationInfo`**

| Field | Type | Description |
|---|---|---|
| `city` | object | `{ uid, code, name }` |
| `country` | object | `{ uid, code, name }` — `code` is ISO 3166-1 alpha-2. |
| `location` | object | `{ lat, lon }` — both decimal strings. |
| `timezone` | string | IANA timezone, e.g. `America/Sao_Paulo`. |
| `currencyCode` | string | ISO 4217, e.g. `BRL`, `USD`, `COP`. |

**`store.vendor`**

| Field | Type | Description |
|---|---|---|
| `uid` | string | Vendor ID (dotted text format, e.g. `100.2.1`). |
| `name` | string | Vendor name. |
| `description` | string | Description. |
| `loyaltyPlan` | boolean | `true` if the vendor has an active loyalty program. |

**`store.account`**

| Field | Type | Description |
|---|---|---|
| `uid` | string | `accounts.account_id` (TEXT slug, not UUID). |
| `name` | string | Account name. |
| `description` | string | Account description. |

**`store.storeFiscalConfig`** (Brazil-specific shown; null in other countries unless fiscal is enabled)

| Field | Type | Description |
|---|---|---|
| `enabled` | boolean | `true` if fiscal emission is enabled. |
| `company` | object \| null | Emitter snapshot: `{ govIdType, govIdNumber, legalName, tradeName }`. |
| `govIdType` | string | Tax ID type. For BR: `CNPJ`. |
| `govIdNumber` | string | Store's tax ID number. |
| `secondaryGovIdType` | string \| null | Secondary doc. For BR: `INSCRICAO_ESTADUAL`. |
| `secondaryGovIdNumber` | string \| null | Secondary doc number. |
| `metadata` | object | `{ storeCode3S, serialNumber, neverstop }` (BR-only). |

</Expandable>

### `payments`

Order totals, taxes, and payment methods.

<Expandable title="payments properties">

**`payments.totals[]`** — Monetary fields use **spec-scale × 10000** (string): `"458000"` = `R$ 45.80`.

| Field | Type | Description |
|---|---|---|
| `taxes` | array | Per-tax breakdown — see below. |
| `rewardId` | string | Reward ID applied to the total. Omitted when not applicable. |
| `total` | string | Total with taxes (× 10000). |
| `subtotal` | string | Subtotal without taxes (× 10000). |
| `taxes_value` | string | Total monetary taxes (× 10000). Snake-case is intentional. |
| `discount_value` | string | Total discount (× 10000). |
| `currency_code` | string | ISO 4217. |
| `subtotal_before_taxes` | string | Subtotal before taxes (× 10000). |
| `discounts` | array | Discount breakdown. |

**`payments.totals[].taxes[]`**

| Field | Type | Description |
|---|---|---|
| `base` | string | Tax base (× 10000). |
| `name` | string | For BR: `ICMS`, `PIS`, `COFINS`, `IBS_UF`, `IBS_MUN`, `CBS`. |
| `rate` | string | Applied rate (decimal string, no scale). |
| `amount` | string | Tax amount (× 10000). |
| `metadata` | object | Always present. Holds `cst`, `cBenef`, `cClassTrib`, `reducao`, `rateNominal`, `rateEffective`. |

**`payments.shippingCost[]`**, **`extraCharges[]`**, **`discounts[]`** — Decimal strings (no spec-scale).

**`payments.paymentMethods[]`**

| Field | Type | Description |
|---|---|---|
| `mid` / `tid` | string | Merchant ID / Terminal ID. Empty when N/A. |
| `card` | object | Card details. Three keys are intentionally snake_case: `card_country`, `last_four_digits`, `external_card_brand_id`. |
| `voucher` | string | Receipt printout (multi-line). |
| `acquirer` | object | `{ code, name }` |
| `processor` | string | `CREDIT_CARD`, `CASH`, `DEBIT_CARD`, `PIX`, etc. |
| `totalBill` | number | Amount charged. |
| `currencyCode` | string | ISO 4217. |
| `exactPayment` | boolean | |
| `transactionId` | string | |
| `metadata` | object | `{}` by default. |
| `referenceNumber` | string \| null | |
| `transactionDate` | object | `{ date: ISO_UTC, timeZoneName: IANA }` |
| `transactionType` | string | |
| `authorizationCode` | string | |
| `paymentMethodCode` | string | |
| `transactionStatus` | string | `APPROVED`, `DECLINED`, `PENDING`. |
| `customerCashAmount` | string | Change received. |

**`payments.metadata.fiscal`** — **BR-only** aggregated fiscal totals. `null` when source did not send fiscal data.

| Field | Type | Description |
|---|---|---|
| `vBC` | string | Tax base (× 10000). |
| `vNF` | string | Total invoice amount. |
| `vCBS`, `vIBS`, `vPIS`, `vICMS`, `vCOFINS`, `vIBSUF`, `vIBSMun` | string | Per-tax totals (× 10000). |
| `vDesc` | string | Total discount. |
| `vProd` | string | Product subtotal. |
| `vTotTrib` | string | Total tributes. |
| `vBCIBSCBS` | string | IBS/CBS calculation base. |

</Expandable>

### `orderLines`

Each item in the order. FIRE-aligned shape with prices in spec-scale × 10000.

<Expandable title="orderLines[] properties">

| Field | Type | Description |
|---|---|---|
| `uid` | string | UUID per line. |
| `hash` | string | Deterministic hash for idempotency. |
| `price` | object | `{ unitPrice: [], totalPrice: [] }` — per-currency price detail × 10000. |
| `itemId` | string | Catalog product ID. |
| `quantity` | string | Quantity as string (FIRE convention). |
| `itemType` | string | `PRODUCT` or `MODIFIER`. |
| `updatedAt` | string | ISO 8601 UTC. |
| `lineTotals` | array | Line contribution to fiscal total. |
| `metadata` | object | See below. |
| `modifierGroups` | array | Nested modifier groups. |
| `itemDescription` | string | Human-readable product name. |

**`orderLines[].metadata`**

| Field | Type | Description |
|---|---|---|

| `redeemed` | boolean | `true` if the item was redeemed with loyalty points. |
| `externalCode` | string | External code (PLU) — e.g. `30130`. |
| `referenceUnitPrice` | object \| null | Reference unit price for repricing. |
| `referenceTotalPrice` | object \| null | Reference total price. |

**`orderLines[].modifierGroups[]`** — Each `selectedModifier` carries only 8 fields (no `uid`/`hash`/`updatedAt`/`lineTotals`).

</Expandable>

| Field | Type | Description |

| `propertyId` | number \| string \| null | Property/unit identifier. |

</Expandable>

## Idempotency

Use `event.id` as your idempotency key. The same `event.id` may arrive more than once (network retries, your endpoint timing out and Fire retrying):

```js
async function handle(payload) {
  const eventId = payload.event.id;

  if (await db.events.has(eventId)) {
    return { ok: true, deduplicated: true };
  }

  await db.events.insert({ id: eventId, type: payload.event.type, raw: payload });
  await processOrder(payload.data);
}
```

## Related events

- [`order.cancelled`](/en/webhook-reference/order-cancelled) — order is later cancelled.
- [`fiscal.authorized.br`](/en/webhook-reference/fiscal-authorized-br) — Brazil-only follow-up when SEFAZ authorizes the NFC-e.
- [`order.status_changed`](/en/webhook-reference/order-status-changed) — granular order state updates.
