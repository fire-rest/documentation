---
title: "order.cancelled"
description: "Sent when an order is cancelled. Carries the V4 Order Snapshot plus a top-level cancellation block with reason, source, and (for Brazil) fiscal context."
---

Fire fires `order.cancelled` when an order transitions to `status="CANCELLED"`. The cancellation can come from the Fire backoffice, the POS, or your API. The payload mirrors the [`order.completed`](/en/webhook-reference/order-completed) snapshot **plus** a top-level `cancellation` block describing who/when/why. For Brazil, when the original fiscal document was already authorized, the block also carries that document's context under `cancellation.metadata.fiscal`.

<Note>
  When fiscal cancellation is requested on a Brazilian order with an already-authorized NFC-e, Fire fires **two** events: this one (`order.cancelled`) immediately, then [`fiscal.cancelled.br`](/en/webhook-reference/fiscal-cancelled-br) once SEFAZ confirms the cancellation.
</Note>

## When it fires

| Trigger | Fires `order.cancelled`? |
|---|---|
| User cancels the order from the Fire backoffice | ✅ Yes |
| Cashier voids the order on the POS | ✅ Yes |
| Your system calls the cancel endpoint | ✅ Yes |
| Order is rejected at injection (validation error) | ❌ No (the `POST` returns `4xx`, no event fires) |

## Envelope

```json
{
  "event": {
    "id":        "evt_9b4f1234567890abcdef1234567890ab",
    "type":      "order.cancelled",
    "createdAt": "2025-01-15T14:45:00.000Z"
  },
  "data": {
    /* V4 Order Snapshot + cancellation block */
  }
}
```

The top-level `fiscal` block (used by `fiscal.authorized.br`) is **dropped** for cancellation events. All fiscal context lives inside `cancellation.metadata.fiscal` instead.

## Data fields

The `data` block is the **V4 Order Snapshot** (same shape documented in [`order.completed`](/en/webhook-reference/order-completed#data-fields)) plus the cancellation block below.

### `cancellation`

<Expandable title="cancellation properties">

| Field | Type | Description |
|---|---|---|
| `cancellationId` | string | Fire's internal ID for this cancellation. |
| `cancelledAt` | string | ISO 8601 UTC — when the cancellation was recorded in Fire. |
| `cancelledBy` | string | Who triggered the cancellation. Examples: `system`, `operator@store`, a user UUID. |
| `cancellationReason` | string | Free-form reason captured at cancellation time. |
| `cancellationSource` | string | Origin: `BACKOFFICE`, `POS`, `API`, `KDS`, `CUSTOMER_APP`. |
| `metadata` | object | Optional. Present only for **Brazilian** orders that had an authorized fiscal document at cancellation time. Absent for CO/EC/CL/AR/VE. |

**`cancellation.metadata.fiscal`** (BR-only) — Snapshot of the original authorized document.

| Field | Type | Description |
|---|---|---|
| `docSubtype` | string | `nfce` or `nfe`. |
| `chaveAcesso` | string | 44-digit SEFAZ access key. |
| `numero` | string | Document number, e.g. `1000013`. |
| `serie` | string \| null | Document series. |
| `protocolo` | string \| null | Authorization protocol from SEFAZ. |
| `dataAutorizacao` | string \| null | When the document was authorized (ISO 8601 UTC). |
| `xmlUrl` | string \| null | URL to download the authorization XML. |
| `pdfUrl` | string \| null | URL to download the DANFE PDF. |
| `providerDocId` | string | PlugNotas integration ID. |

</Expandable>

## Idempotency and ordering

- Use `event.id` for idempotency, same as `order.completed`.
- For BR orders, expect events in this order: `order.completed` → (later) `order.cancelled` → (later still, after SEFAZ confirms) `fiscal.cancelled.br`. They are independent deliveries — your handler should not assume they arrive on the same TCP connection or in the same minute.
- For non-BR countries, the sequence is: `order.completed` → `order.cancelled`. The fiscal cancellation in your local authority is reported back via [`POST /v1/webhooks/fiscal/callback`](/en/configuration/fiscal-callback) — Fire does not emit a fiscal event.
