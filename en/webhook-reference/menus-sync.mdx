---
title: "menus.sync"
description: "Fired when Fire needs to propagate menus for multiple stores at once."
---

`menus.sync` is the batch counterpart to [`menu.updated`](/en/webhook-reference/menu-updated). Fire emits it when menus for multiple stores need to be propagated at once — for example, during initial onboarding or after a global menu change that affects many stores.

Fire splits large syncs automatically and emits multiple `menus.sync` events. Each event carries a single menu in `data.menu`. Use `batchIndex` and `batchTotal` to track progress across the sync. Each event is delivered and retried independently.

## Fields

### `data`

| Field | Type | Description |
|---|---|---|
| `account` | string | Account identifier — required by downstream systems |
| `country` | string | ISO 3166-1 alpha-2 country code (e.g. `EC`, `BR`, `CO`) — required by downstream systems |
| `batchIndex` | integer | Position of this batch (1-based) |
| `batchTotal` | integer | Total number of batches in this sync |
| `menu` | object | Complete menu payload — same structure as `data.menu` in [`menu.updated`](/en/webhook-reference/menu-updated) |

### `data.menu`

| Field | Type | Description |
|---|---|---|
| `list` | object | Menu metadata and channel/store association |
| `categories` | object[] | Category tree |
| `products` | object[] | Product catalog |
| `modifierGroups` | object[] | Modifier groups and options |
| `scheduledActivities` | object[] | Future activation/deactivation windows |

Nested objects use the same field definitions as [`menu.updated`](/en/webhook-reference/menu-updated#datamenu).

## Processing

Process each `menus.sync` event independently. Apply `data.menu` to the downstream system identified by `menu.list.storeId` and `menu.list.channelId`.

The menu is a **complete replacement** — same full-replacement semantics as [`menu.updated`](/en/webhook-reference/menu-updated).

Use `batchIndex` and `batchTotal` to track progress if your system needs to know when a full sync is complete.

<Note>
  Each batch event is retried independently on failure — not the entire sync.
</Note>

## When does Fire emit this event?

- During initial client onboarding
- After a global menu change affecting many stores
- On explicit sync requests triggered from the Fire dashboard

For individual menu changes in normal operation, Fire emits [`menu.updated`](/en/webhook-reference/menu-updated) instead.
