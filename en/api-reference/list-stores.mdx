---
title: "List stores"
api: "GET https://app.fire.rest/api/v1/fire/external/stores"
description: "List the stores of the account and vendor bound to your API key, with pagination and filters."
authMethod: "bearer"
---

Returns the stores of the account + vendor bound to your API key, with their **full configuration** —
including the `fiscal` block needed for electronic-invoicing integrations. Internal back-office
fields (drafts, overrides, audit columns) are excluded.

Use `fields` to narrow the payload to just what you need.

## Authentication

<ParamField header="x-api-key" type="string" required>
  Your Fire API key with the `store:read` scope. The key **must be vendor-scoped** (account +
  vendor binding) — keys without a `vendorId` are rejected with `403`.
</ParamField>

## Query parameters

<ParamField query="accountId" type="string" required>
  Account identifier. **Must match** the account bound to your API key, or the request is rejected with `403`.
</ParamField>

<ParamField query="vendorId" type="string" required>
  Vendor identifier. **Must match** the vendor bound to your API key, or the request is rejected with `403`.
</ParamField>

<ParamField query="fields" type="string">
  Comma-separated list of fields to return (projection). See [Field projection](#field-projection).
  Omit to return every field. An unknown field yields `400`.
</ParamField>

<ParamField query="status" type="string">
  Filter by publication status: `DRAFT`, `PUBLISHED`, `PARTIALLY_PUBLISHED`, `ARCHIVED`.
</ParamField>

<ParamField query="active" type="string">
  Filter by operational state: `ACTIVE`, `INACTIVE`, `SUSPENDED`.
</ParamField>

<ParamField query="syncStatus" type="string">
  Filter by sync state: `SYNCED`, `PENDING`, `FAILED`.
</ParamField>

<ParamField query="countryId" type="string">Filter by country id.</ParamField>
<ParamField query="cityId" type="string">Filter by city id.</ParamField>
<ParamField query="channel" type="string">Filter by a published channel code (e.g. `APP`).</ParamField>
<ParamField query="query" type="string">Free-text search over name, store code and external id.</ParamField>

<ParamField query="page" type="integer" default="1">Page number (1-based).</ParamField>
<ParamField query="size" type="integer" default="20">Page size (1–500).</ParamField>

## Request

<RequestExample>
```http
GET https://app.fire.rest/api/v1/fire/external/stores?accountId=100&vendorId=100.1.10&page=1&size=20
x-api-key: <your_api_key>
```
</RequestExample>

## Fiscal block

`fiscal` carries the store's electronic-invoicing configuration. It is the **same object** you
already receive as `store.storeFiscalConfig` in order events such as
[`order.completed`](/en/events/order-completed) — both are produced by the same projection, so the
two sources never drift.

| Field | Type | Description |
|---|---|---|
| `enabled` | boolean | `true` if invoicing is enabled for the store |
| `company` | object \| null | Issuer snapshot: `{ govIdType, govIdNumber, legalName, tradeName }` |
| `govIdType` | string \| null | Store tax-id type (see table below) |
| `govIdNumber` | string \| null | Store tax-id number |
| `secondaryGovIdType` | string \| null | Secondary tax-id type — Brazil only today |
| `secondaryGovIdNumber` | string \| null | Secondary tax-id number |
| `metadata` | object \| null | **Country-specific** — see below |

### What `metadata` returns per country

Only `metadata` changes between countries. Discriminate using `location.countryCode` — there is no
`country` field inside `fiscal`.

| Country | `govIdType` | `secondaryGovIdType` | `metadata` |
|---|---|---|---|
| 🇧🇷 BR | `CNPJ` | `INSCRICAO_ESTADUAL` | `{ storeCode3S, serialNumber, neverstop: { enabled, url } }` |
| 🇪🇨 EC | `RUC` | — | `null` |
| 🇨🇴 CO | `NIT` | — | `null` |
| 🇨🇱 CL | `RUT` | — | `null` |
| 🇦🇷 AR | `CUIT` | — | `null` |
| 🇻🇪 VE | `RIF` | — | `null` |

Brazil is the only country populating `metadata` today. New countries add keys without breaking the
contract. `fiscal` is `null` for stores with no fiscal configuration.

## Field projection

Pick which fields each store returns, like MongoDB projection or the Elasticsearch `_source` param.

- No `fields` → every field is returned.
- `fields=id,name,fiscal` → only those fields.
- A field outside the catalog → `400` with the list of allowed fields.

**Available fields**: `id`, `storeNumber`, `storeCode`, `accountId`, `vendorId`, `name`,
`externalId`, `status`, `active`, `timezone`, `location`, `services`, `channels`,
`publishedChannels`, `operationSchedule`, `salesSchedule`, `schedulesByChannel`, `taxesInfo`,
`contactInfo`, `deliveryInfo`, `salesGoals`, `fiscal`, `operational`, `syncStatus`, `lastSyncedAt`,
`createdAt`, `updatedAt`.

```http
GET https://app.fire.rest/api/v1/fire/external/stores?accountId=100&vendorId=100.1.10&fields=id,storeCode,fiscal
x-api-key: <your_api_key>
```
