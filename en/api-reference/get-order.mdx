---
title: "Get order"
api: "GET https://api.fire.rest/api/v1/fire/external/orders/{orderId}"
description: "Read a single order by any of its references, with field projection. The order must belong to the account and vendor bound to your API key."
authMethod: "bearer"
---

Returns a single order projected according to `fields`. If the order does not exist — or belongs to
another tenant — the response is `404` (existence is never leaked across tenants).

Without `fields` it returns the full order: lines, totals, payment methods, payment progress, billing
data and the fiscal document with its journey. It is the endpoint to reconcile a single order.

## Authentication

<ParamField header="x-api-key" type="string" required>
  Your Fire API key with the `orders:read` scope. The key **must be vendor-scoped** — keys without a
  `vendorId` are rejected with `403`.
</ParamField>

## Path parameters

<ParamField path="orderId" type="string" required>
  Any of the order's public references:

  | reference | what it is |
  | --- | --- |
  | `orders.id` | Fire's internal UUID |
  | `order_external` | the id you assigned when creating the order |
  | `metadata.order_id` | a copy of the external id inside the order |
  | `order_code` | the order code the cashier sees |

  No translation needed: use the id you already have. `order_code` can repeat within your vendor; if
  it matches more than one order the response is `409`, and in that case use the UUID or the external id.
</ParamField>

<Note>
  This is the same set of references accepted by [Cancel order](/en/api-reference/cancel-order), so the
  id you created the order with also works to read it back.
</Note>

## Query parameters

<ParamField query="fields" type="string">
  Projection — see [Field projection](/en/api-reference/list-orders#field-projection). Omit to
  return every field.
</ParamField>

## Request

<RequestExample>
```http
GET https://api.fire.rest/api/v1/fire/external/orders/7e2b8c10-1a2b-4c3d-8e9f-0a1b2c3d4e5f?fields=id,orderCode,status,orderLines,totals
x-api-key: <your_api_key>
```
</RequestExample>

## Response

The response comes in the standard envelope `{ "success": true, "data": { … } }`. `data` is an order
object, projected according to `fields`. See the full field list in
[Field projection](/en/api-reference/list-orders#field-projection).

To reconcile an order, read in [List orders](/en/api-reference/list-orders):

- [Amount scales](/en/api-reference/list-orders#amount-scales): not every amount comes in the same
  scale.
- [Payment progress](/en/api-reference/list-orders#payment-progress-settlement-and-payments):
  `settlement` (how much has been collected) and `payments` (with what).
- [The `fiscal` block by country](/en/api-reference/list-orders#the-fiscal-block-by-country): the
  fiscal document and its journey.

Each `paymentMethods` entry carries `details.acquirer_configured`: who acquires that payment according to your account's configuration in Fire, or `null` — see
[Configured acquirer](/en/events/order-completed#configured-acquirer).

<Note>
  Each `orderLines` line and each modifier can carry `descriptions` (`{ marketing, ops }`) from the Fire catalog and `item_type` with the menu type, as in the [order events](/en/events/order-completed#data-orderlines). `reported_item_type` is informational: the type the channel sent when it does not match the menu, or `null` if it sent none. Absent when the channel sent the menu type.
</Note>
