---
title: "Request fiscal document"
api: "POST /api/v1/external/fiscal/documents"
description: "Gets the fiscal identifiers the point of sale needs to print the receipt. It is synchronous, and the result enriches the order you inject afterwards."
authMethod: "bearer"
---

Call it **after taking payment and before injecting the order**. Fire resolves internally
which fiscal provider matches the store's country, requests the numbering and returns the
data ready to print.

<Info>
  **Three things worth knowing before you integrate:**

  1. The body is **the same one you already send to [Inject order](/en/api-reference/orders)**,
     with a single extra field: `device.externalId`.
  2. The response **does not mean the document is authorized**. It means there are numbers to
     print. Authorization by the tax authority happens later, asynchronously.
  3. That response **enriches the injection body** (see [Enrich the order](#enrich-the-order)).
     It is copy and paste — no transformation.
</Info>

## When to call it

<Steps>
  <Step title="You take payment">
    The customer pays at the POS or kiosk.
  </Step>
  <Step title="You request the fiscal document">
    Call this endpoint with the order body.
  </Step>
  <Step title="You print">
    Based on `printing.mode`, print the fiscal receipt or a provisional ticket.
  </Step>
  <Step title="You inject the order">
    Add the response to the body under `fiscal` and call
    [Inject order](/en/api-reference/orders).
  </Step>
</Steps>

<Warning>
  **A sale is never blocked by fiscalization.** If the provider does not answer in time, this
  endpoint returns `202` with an explicit status: print a provisional ticket, inject the order
  anyway, and Fire completes the numbering on its own. What you must not do is retry in a loop
  or hold the sale.
</Warning>

## Headers

<ParamField header="Authorization" type="string" required>
  Bearer token obtained from [POST /login](/en/api-reference/login). Format: `Bearer <accessToken>`.
</ParamField>

<ParamField header="x-api-key" type="string" required>
  Your Fire API key.
</ParamField>

<ParamField header="x-client-channel" type="string" required>
  Must be `integration`.
</ParamField>

<ParamField header="account" type="string" required>
  Identifier of the account the request belongs to.
</ParamField>

<ParamField header="Idempotency-Key" type="string" required>
  UUID identifying **this fiscal operation**. If you retry after a network failure, send the
  **same** value: you get the previous result instead of a new document.

  Generate it once per order and keep it with the order until you inject it.
</ParamField>

## Body

Send **the same body as [Inject order](/en/api-reference/orders)**. Fire ignores what it does
not need for fiscalization (`order.products`, `payments`, `shippingMethod`, `marketing`…), so
you do not have to build a different payload: reuse the one you already have.

The fields actually used to issue the document are documented below.

<ParamField body="orderId" type="string" required>
  Unique identifier of the order in your system.

  It is the **fiscal idempotency key**: the same order requested twice returns the same
  document. It must be **the same value** you later send as `orderId` when injecting the
  order — if they differ, two receipts are issued for a single sale.
</ParamField>

<ParamField body="orderCode" type="string">
  Human-readable order code. Informational.
</ParamField>

<ParamField body="createdAt" type="string" required>
  Order creation date and time. The **issue date** of the receipt is derived from it,
  converted to the store's time zone.

  If it carries no time zone (`2026-08-06 17:26:09`) it is read as **UTC**. Prefer ISO 8601
  with offset (`2026-08-06T17:26:09.386Z`).
</ParamField>

<ParamField body="documentType" type="string" default="SALE_INVOICE">
  Type of document to issue. One of: `SALE_INVOICE`, `CREDIT_NOTE`.

  For a credit note do not send fiscal keys: Fire finds the original document of that same
  order by itself.
</ParamField>

<ParamField body="reason" type="string">
  Reason for the credit note. Only applies with `documentType: "CREDIT_NOTE"`.
</ParamField>

<ParamField body="store" type="object" required>
  The issuing store. From `code`, Fire resolves the country, the issuer's tax id and the
  establishment — do not send them yourself.
  <Expandable title="store">
    <ParamField body="code" type="string" required>Store code in Fire (e.g. `K097`).</ParamField>
  </Expandable>
</ParamField>

<ParamField body="device" type="object" required>
  The issuing device. **This is the only block that differs from order injection**:
  `externalId` is added.
  <Expandable title="device">
    <ParamField body="externalId" type="string" required>
      Identifier of the **point of emission** this device issues from (`"1"`, `"2"`…). It is a
      business identifier, not a tax-authority one: Fire translates it to whatever each
      country requires. The POS does not need to know or maintain that mapping.

      Two registers in the same store number independently, so it cannot be inferred or
      shared: each device declares its own. If the device is not associated with any point of
      emission, the response is `400` with the reason.
    </ParamField>
    <ParamField body="uid" type="string" required>Device UID.</ParamField>
    <ParamField body="name" type="string">Display name (e.g. `KIOSK`).</ParamField>
    <ParamField body="metadata" type="object">Additional device metadata.</ParamField>
  </Expandable>
</ParamField>

<ParamField body="client" type="object">
  Buyer details. **Numbering does not use them** — they are accepted because they are part of
  the body you already build for the injection, and the document will need them once it is
  issued.

  Send your usual vocabulary (`FINAL_CONSUMER`, `TAX_ID`, `NATIONAL_ID`, `PASSPORT`,
  `FOREIGN_ID`): Fire maps them to each country's tax authority catalog. Without
  identification, the receipt is issued to a final consumer.
  <Expandable title="client">
    <ParamField body="govIdType" type="string">Buyer's document type.</ParamField>
    <ParamField body="govIdNumber" type="string">Buyer's document number.</ParamField>
    <ParamField body="name" type="string">First name.</ParamField>
    <ParamField body="lastName" type="string">Last name.</ParamField>
    <ParamField body="email" type="string">Email.</ParamField>
    <ParamField body="phone" type="string">Phone.</ParamField>
    <ParamField body="billingInformation" type="object">Billing details, when they differ.</ParamField>
  </Expandable>
</ParamField>

<ParamField body="channel" type="object">
  Sales channel, same as in the injection.
  <Expandable title="channel">
    <ParamField body="code" type="string" required>Channel code (`KIOSK`, `POS`, …).</ParamField>
    <ParamField body="uid" type="string">Channel UID in Fire.</ParamField>
  </Expandable>
</ParamField>

<ParamField body="operator" type="object">
  Operator or cashier, same as in the injection.
</ParamField>

<ParamField body="metadata" type="object">
  Additional fiscal data required by the country. **In Ecuador it is empty**: any key returns
  a `400`.

  In countries that require it, send only the fields the point of sale knows — the rest comes
  from the store configuration.
</ParamField>

## Response

The response has **three layers**, and you should code against the first one:

<CardGroup cols={3}>
  <Card title="Core" icon="box">
    Identical across every country and provider. This is what your integration reads.
  </Card>
  <Card title="Country" icon="flag">
    `countryIdentifiers`. Varies per tax authority. For backoffice and reconciliation.
  </Card>
  <Card title="Provider" icon="plug">
    `providerMetadata`. Opaque, for support. Do not code against it.
  </Card>
</CardGroup>

<ResponseField name="fiscalRequestId" type="string">
  Identifier of the fiscal request in Fire. Keep it: you query the status with it later.
</ResponseField>

<ResponseField name="orderId" type="string">
  Echo of the `orderId` you sent.
</ResponseField>

<ResponseField name="reused" type="boolean">
  `true` if this request already existed and the previous one was returned. Treat it like a
  new one.
</ResponseField>

<ResponseField name="countryCode" type="string">
  Country of the issuing store (`EC`, `VE`, `BR`).
</ResponseField>

<ResponseField name="requestStatus" type="string">
  Result of **the numbering**: are there numbers to print?

  <Expandable title="values">
    <ResponseField name="GENERATED" type="—">There is a document. Print it.</ResponseField>
    <ResponseField name="PENDING" type="—">The provider did not answer in time. Fire completes it later.</ResponseField>
    <ResponseField name="FAILED_RETRYABLE" type="—">Temporary failure. Fire retries on its own.</ResponseField>
    <ResponseField name="FAILED_FINAL" type="—">Definitive rejection. Retrying will not fix it.</ResponseField>
    <ResponseField name="UNAVAILABLE" type="—">The country's fiscal service is unavailable.</ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="documentStatus" type="string">
  Status of the **document before the tax authority**: `PENDING`, `AUTHORIZED`, `REJECTED`,
  `CANCELLED`.

  In this response it is **always `PENDING`**: authorization happens later. Do not read it as
  the sale being authorized, and do not send it when injecting the order.
</ResponseField>

<ResponseField name="retryable" type="boolean">
  Whether the failure allows a retry. Informational: retries are Fire's job, not your
  integration's.
</ResponseField>

<ResponseField name="document" type="object">
  The issued document. `null` when there was no numbering.
  <Expandable title="document">
    <ResponseField name="documentType" type="string">`SALE_INVOICE` or `CREDIT_NOTE`.</ResponseField>
    <ResponseField name="documentNumber" type="string">
      Visible number, already formatted for the country (`097-107-000000001`). **It is for
      printing**: to search or reconcile use `sequential`, `serie` and `countryIdentifiers`.
    </ResponseField>
    <ResponseField name="sequential" type="string">Sequential number of the document.</ResponseField>
    <ResponseField name="serie" type="string">Series. May be `null` — some countries do not use it.</ResponseField>
    <ResponseField name="authorizationMode" type="string">`ONLINE`, `OFFLINE` or `BATCH`. May be `null`.</ResponseField>
    <ResponseField name="issuedAt" type="string">Issue date and time (UTC).</ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="printing" type="object">
  **What to print.** Fire resolves each country's legal rule here so your integration does not
  have to know it.
  <Expandable title="printing">
    <ResponseField name="printable" type="boolean">Whether there is a fiscal receipt to hand over.</ResponseField>
    <ResponseField name="mode" type="string">
      `FISCAL_DOCUMENT` — print the full fiscal receipt.
      `PROVISIONAL_RECEIPT` — print a non-fiscal / "in progress" ticket.
      `NONE` — nothing to print.
    </ResponseField>
    <ResponseField name="reason" type="string">
      Reason, when it applies: `ISSUED_OFFLINE` (issued in contingency, authorized later),
      `AWAITING_FISCAL_NUMBERING`, `FISCAL_REJECTED`.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="graphic" type="object">
  What gets drawn or downloaded.
  <Expandable title="graphic">
    <ResponseField name="code" type="object">
      Code to print: `{ "format": "QR" | "PDF417", "content": "..." }`. If `null`, draw
      nothing — some countries do not use a code.
    </ResponseField>
    <ResponseField name="lookupUrl" type="string">Public URL to look up the receipt.</ResponseField>
    <ResponseField name="pdfUrl" type="string">
      Graphic representation as PDF. It arrives **later**, with the authorization: in this
      response it is `null`.
    </ResponseField>
    <ResponseField name="xmlUrl" type="string">Legal document as XML. Also arrives later.</ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="countryIdentifiers" type="object">
  Identifiers specific to the country's tax authority. They change with `countryCode`:

  Ecuador `{ accessKey }` · Venezuela `{ accessKey: null, controlNumber }` ·
  Brazil `{ accessKey, protocolo, modelo }`.

  <Warning>
    `accessKey` **can be `null`**. Venezuela does not issue an access key: the identifier is
    `controlNumber`. If your integration assumes it is always present, it breaks when that
    country opens.
  </Warning>
</ResponseField>

<ResponseField name="failure" type="object">
  Why there is no document. `null` on success.
  <Expandable title="failure">
    <ResponseField name="code" type="string">Error code.</ResponseField>
    <ResponseField name="scope" type="string">
      `TECHNICAL` — a communication problem; print provisional and move on.
      `FUNCTIONAL` — a document value is wrong; retrying will not fix it.
    </ResponseField>
    <ResponseField name="message" type="string">Readable description.</ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="providerMetadata" type="object">
  Fiscal provider data, for support and traceability. Do not use it to operate.
</ResponseField>

<ResponseField name="timestamps" type="object">
  `requestedAt`, `respondedAt` and `providerLatencyMs`.
</ResponseField>

## Enrich the order

The response goes into the [Inject order](/en/api-reference/orders) body under `fiscal`.
**Copy the whole `data` object, without transforming it** — Fire takes what it needs and
ignores the rest.

```json Injection body, enriched {3-11}
{
  "orderId": "EC-K097-42-1786037102",
  "fiscal": {
    "fiscalRequestId": "fr_01HZ8N4K2P7QY3V6R0S9TG",
    "requestStatus": "GENERATED",
    "countryCode": "EC",
    "document": { "documentNumber": "097-107-000000001", "sequential": "000000001", "serie": "097107" },
    "countryIdentifiers": { "countryCode": "EC", "accessKey": "0408…818" },
    "graphic": { "code": { "format": "QR", "content": "0408…818" } },
    "providerMetadata": { "code": "hio" }
  },
  "store": { "code": "K097" },
  "device": { "uid": "92ef49e315423aec", "externalId": "1" },
  "order": { "products": [] },
  "payments": {}
}
```

<Check>
  **Always inject the order**, with whatever fiscal status you received — including `PENDING`
  or `FAILED_FINAL`. A sale that was paid must reach Fire; the fiscal status is resolved
  afterwards and Fire updates the order by itself.
</Check>

<Note>
  If for some reason you did not call this endpoint, inject the order **without** the `fiscal`
  field. Fire handles fiscalization on its own; the only thing lost is printing the receipt
  immediately.
</Note>

## What to do with each response

<AccordionGroup>
  <Accordion title="requestStatus: GENERATED — the normal case">
    Print the fiscal receipt with `document.documentNumber` and, if `graphic.code` is not
    `null`, draw the code. Add the response to the order and inject it.

    If `printing.reason` is `ISSUED_OFFLINE`, the receipt is valid but was issued in
    contingency: print whatever legend that country requires.
  </Accordion>

  <Accordion title="requestStatus: PENDING or FAILED_RETRYABLE — the provider did not answer">
    `printing.mode` comes as `PROVISIONAL_RECEIPT`. Print a non-fiscal ticket and inject the
    order anyway, with the `fiscal` block exactly as received.

    **Do not retry this call.** Fire completes the numbering asynchronously and updates the
    order. If you need to show the outcome, query it with the `fiscalRequestId`.
  </Accordion>

  <Accordion title="requestStatus: FAILED_FINAL — the tax authority rejected it">
    A document value is not accepted and retrying will not fix it: read `failure.message`.
    Print the provisional ticket, inject the order and escalate to support with the
    `fiscalRequestId`.
  </Accordion>

  <Accordion title="4xx — the problem is in the request">
    `400` invalid body · `401` / `403` credentials · `409` same `Idempotency-Key` with a
    different body · `400` the store or device is not configured to issue (the message says
    which one).

    In these cases **no fiscal request was created**. Fix it and call again.
  </Accordion>
</AccordionGroup>

## Query a request

`GET /api/v1/external/fiscal/documents/{fiscalRequestId}` returns **the same body** with an updated
status: once the authority authorizes, `documentStatus` becomes `AUTHORIZED` and
`graphic.pdfUrl` and `graphic.xmlUrl` are filled in.

You can also search by order: `GET /api/v1/external/fiscal/documents?orderId=EC-K097-42-1786037102`.
